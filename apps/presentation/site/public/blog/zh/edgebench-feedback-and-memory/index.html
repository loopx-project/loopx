让长程 Agent 的下一步有据可依

从可信反馈，到持续进展，再到上下文成本

长时间运行之后，我们关心三个问题：第一次好结果之后还有什么改善，改善有没有保住，整个过程花了多少成本。

我们的 EdgeBench 研究经历了三个阶段：先让评测和续跑可信，再看积累的证据能否改变后续工作，最后削减交付这些证据的成本。早期 Lean 和后来的 Ad Placement 轨迹显示了实际进展。更强的基础模型基线也在前进。这些观察支持继续发展 LoopX，但尚不能分离各机制的贡献及净收益。

当前判断是有限正向：已有后程有效工作和恢复复盘流程改善的实例，尚无一般性的因果增益估计，也没有完整费用比较。

研究问题可信反馈后程进展证据与决策完整成本下一轮验证

1. 更多时间，应该换来什么？

LoopX 让原始目标、验收条件、工作归属和证据跨会话、跨宿主持久化。控制面约束状态转换，为模型的下一步提供反馈，但不能认证这个选择是否高明。一条发现、一次读取回执、一条 replan 记录都只是中间证据；真正需要追踪的链条，要落到实际工作和经过验证的成果。

  1. 目标验收与范围
  2. 证据结果与限制
  3. 决策继续或换方向
  4. 工作执行与验证
  5. 保留保住最佳有效成果

我们区分起点优势、后续增量和最佳成果保留。更高的最终分数，可能主要来自更强的起点；更好的中间候选，也可能没有留在终态工作区里。运行更久、Todo 更多、图更大，都不能替代这三项判断。

比较边界

历史研究包含 Official、单次调用、原生 Goal、LoopX Resume 和 LoopX Explore。Explore 在续跑基础上增加可选的证据采集和规划。盲跑仍可使用公开任务、训练数据和本地验证器，但收不到隐藏评测分数和诊断；后台操作者评测不是 solver 反馈。后来的 native-feedback 研究由 Agent 主动申请评测，按已接受提交执行一小时冷却，不做周期评测。这些是不同研究，不能合并成一个处理效应。

模型、effort、提示、runner 和预算共同演化。早期主要用 Sol/xhigh，后来的 Sol/max、Astra/xhigh 批次各自保留条件。每臂一次运行只能提供描述性证据。缺失、主动停止、无效和有效零分分别记录。Checkpoint 接续保留源时间、评测机会和冷却；donor 历史不算新的独立重复。

2. 先让反馈与续跑可信

最初的 Portfolio 实验先暴露了测量和执行缺陷。一个盲跑 wrapper 在移除评测入口时，也删掉了迭代优化提示；一个账本检查把更早的市场收益归给了收盘时才买入的持仓。它们都混淆了原本的比较。修复后必须另起尝试，旧结果继续保留。

一个小反例就能说明记账问题：初始现金 100,000，在收盘价 200 时买入 100 单位并支付 10 手续费，即时权益应为 99,990，NAV 为 0.9999；新持仓没有赚到此前从 100 涨到 200 的收益。之后，对两个冻结样本独立重建，各自 243 天全部吻合，权益残差小于 4×10⁻⁹，股数没有差异。这证明账本一致，不证明投资策略优秀。版本化修复见 EdgeBench #14。

续跑也有类似问题：某个工作项结束后，外层进程可以不断唤醒，却没有恢复出有用的下一步。判断必须回到原始目标。Todo 完成之后，可以继续实验、等待或结束，但它本身不能代表 Goal 验收。可靠反馈与恢复让之后的研究变得可解释。

3. 第一次好结果之后，还发生了什么？

后来的实验把重点转向十几个小时之后的工作。先比较共同观察窗口，再拆开起点、后续增量和保留的候选。只看终点排名，很容易混淆它们。

Ad Placement 说明后程并非必然平台期：后来的差候选被拒绝，最佳版本保住了。原始分领先约 0.052%，幅度不大；这里的终态工作区核验也只覆盖这一臂。新旧包同时改变 core 和 runner，不能当作某个 LoopX feature 的独立效应。

Astra 的结果推进了我们观察到的基础模型能力边界。Official 将速度修改和搜索修改分开，得到连续的原生改善。这项进展属于基础模型／Official 路径，不能算到 LoopX 头上。更强模型也提高了 harness 的要求：面对不断进步的基线，上下文与复盘成本必须换来相应价值。

Schema：起点领先不等于持续改善

Schema 是这里展开的反例。Sol 新旧版 14 小时窗口，新版 0.804620、旧版 0.723684。但第一次原生结果已经是 0.794620 对 0.713158，且收到反馈的耗时不同。后续增量仅为 0.010000 和 0.010526。较大的终点优势主要来自起点；后续不断改代码，仍未完成原始六项目标。

另一组 Astra/xhigh 的 12 小时比较更不利：Official 达到 0.881813，LoopX 为 0.786257，两边 6h 到 12h 的 best 都没有提升。LoopX 记录了 36 次完成的压缩，Official 为四次；未缓存输入约为其 5.32 倍。压缩可能与有效工作重叠，版本、恢复、共享负载和评分条件也有差异。但轨迹仍指出了实际挑战：更多改动和控制活动，没有转化为更多验收价值。

这些窗口的条件与限制

Sol 新旧研究采用 planned + Explore、Sol/xhigh、关闭 TurnEnvelope、Agent 主动申请 native feedback、一小时冷却。14h 是读过早期结果后，按最早实际结束时间以下的最大整小时选定，并非完成 18h。另一组 Astra 比较各臂自己的前 12h，包含准备。Sol 窗口对齐了 7,522 个独立 response 和 52 个收到的原生结果，Astra 为 5,277 个 response、45 个结果；累计计数没有反复累加，reasoning 已在 output 中。历史基础设施失败及整次运行完整性未知继续保留。处理包不同、自适应重启，以及此前操作者读到过一个 Official 终态汇总，都限制了因果判断。

4. 证据有没有改变下一步工作？

成熟 checkpoint 可以帮助观察一个具体决策边界。接收者继承相同科学状态和 incumbent，再追踪它读了什么证据、选了什么实验、实际做了什么、原生反馈如何。负向本地结果若能在明确条件下排除一条分支，也有价值。继续原方向有依据时，replan 不必强行改道。

近期 #7269 让 Agent 先读目标、事实和反馈，再读写回格式；释放过时的任务选择偏好，并在创建 successor 后保留原 Turn 的结算身份。它对应两个真实往返来源：决策前先读大段写入指令，以及后续任务创建后还要补一轮确认结算归属。

两道修订臂都在第一次自主复盘完成分段读取、写回和原 Turn 结算。基线最终也完成了；额外轮次还包含有用验证和新增来源，不能把所有差额算作冗余。Grid 修订臂选择更深复用，进行了独立等价检查和更广的本地验证，最后比基线低六分。Schema 找到了真实的注册表生命周期缺陷，但新原生结果仍为继承的 0.786257；截止时基线没有本轮新结果。

这是流程的有限正向证据，伴随 Grid 小幅成果优势、Schema 反馈中性，不等于全任务加速。这组每题一对、各对同一原 checkpoint、Sol/max、普通 cadence 为三个有效工作 Turn，差分、TurnEnvelope 和 stride 关闭。恢复准备阶段暂用 cadence 一，直到语义复盘与原生 Turn 完成。它不是多轮稳定态三 Turn 复盘研究。

更早 Graph、Portfolio 的 retained／fresh-context 接续回答的是另一问题；源点龄、重建费用和接续仍算在原累计 36h 内。早期一个名义上“with #7197”的臂没有实际收到分段 reader，其得分不能判断该处理有益或有害。后来的 Astra 到 Sol 接续又同时换了模型和 effort。这些历史有诊断价值，但不能当成独立冷启动或互换的消融。

5. 效率要算完整过程

完整账单包括模型输入输出、工具响应与重试、上下文重建、复盘结算、评测、共享资源和操作者介入。缓存输入在部分计费条件下更便宜，但不是免费；reasoning 已在 output 里。没有实际价格与账户对账，token 向量只能描述用量，不能直接当作费用。

减少重复交付，同时保留义务

分段读取与上下文差分处理相关但不同的问题。分段把决策证据放在写入指令之前；差分只传相对精确基线的变化，并保持当前控制条件显式可见。原生 Hook 方案在同一会话、同一上下文周期内，完整分页读取后采用明确的连续性工程假设：这些内容经过正常工具交付后仍可使用。它不再要求常态开启完整模型输入诊断，也不把读取回执冒称为独立的保留证明。会话变化、已观察到的压缩、读取不完整或已知交付失败会使基线失效；恢复取自同一份不可变捕获。遗漏的 Hook、不可见的下游截断仍可能逃过检测，必须保留为验证边界。

历史离线回放说明了为什么必须算总量：结构化 Host 和原生呈现字节下降 57.72%、60.23%，原生入口加完整恢复上升 6.37%。这些是历史字节观察，不是当前提交的模型 token 结果。早期离线探针还曾报告 CLI 字节增加 2.25%，但因漏掉最终 CLI 压缩并重新格式化入口，已撤回其实际 CLI 交付测量资格。该数字仅作为无效历史记录保留，不用于完整交付或成本结论。不能把视图缩小 60% 写成总成本下降 60%。

当前效率工作把普通入口、分段交付接到共享传输，减少重复读取和重新绑定，消掉可避免的结算往返。差分关闭的默认路径同样重要；开启后也必须正确恢复，并让产品和 benchmark 都易于启用。所有机制合计 15% 的参考目标尚未完成资格验证；它不是每个机制各有一份额度，也不能用来漏记失败和重建成本。

6. 从零开始的上下文验证

当前上下文研究让 Grid、Schema、Ad Placement 从原始任务开始，使用 Sol/max，每题最多 18h。可用的历史 Official 或旧 LoopX 作为描述性参考，保留模型／effort、源码、评分器、机会和时钟差异，不冒称严格配对；旧材料无法回答相应问题时再补 base。各次尝试按实际源码、连续性依据和传输路径分别分析，不合并成同一处理。

先核实实际交付确实改变：首次完整读取、声明连续性依据的后续差分、已知基线失效时的完整回退，以及一次从复盘到工作的完整交互。再比较有效进展、成果保留和完整用量。开关、回执、局部小包都不能替代这些证据。Feature 偏离预期时，停止相关尝试，保留其成本和历史，修复后用新的尝试身份重启。

新原生 Hook 路径的首批 Grid、Ad 交互已完成完整分页、一次差分及后续任务工作。同一次捕获内，差分载荷分别比对应完整包小 19.53%、19.48%；这只是一轮读取的载荷比较，不含分页封装、后续模型输入、Hook、恢复或复盘费用，不能外推为总成本下降。完整复盘到后续原生成果、持续收益和故障恢复仍待验证。

效果目标是很多小时之后仍能取得有效进展并保住成果；效率目标是用更低完整成本和人工介入取得同等验收价值。下一份结果需要同时回答它们；当前运行不重置原定截止时间，替换尝试的失败和消耗也保留。

数值分别保留各历史模型、版本、窗口与有效性边界。公开实现：LoopX。早期详细记录保留在上一版文章。这里不发布原始轨迹、隐藏评测材料、运行时凭证或私有操作上下文。
