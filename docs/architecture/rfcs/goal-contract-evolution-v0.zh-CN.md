## 1. 决定与范围

把验收维护统一到 **Goal 演化**，复用既有 Goal authority。持久化的基本单位是
有版本、来源、适用范围和证据的承诺，而不是不断增长的一段正文或一个数组。
不可变的原始请求、当前有效契约、历史变更和实际结果具有不同生命周期。
保留意图，不等于让每句历史文字永远成为当前义务。

[共享目标对齐与受治理修订](shared-goal-alignment-and-governed-amendment-v0.zh-CN.md)
负责共享承诺的变化；[成果细化](goal-outcome-refinement-v0.zh-CN.md)负责支撑要求
与自查。本文把它们与当前执行目标修订组合，不新增演化服务、能力、调度器、
事件账本或 Python 决策 owner。Provider 是已选 canonical AuthorityStore，
来源是 builtin Core。

同一份绑定来源的变更集可一起修改当前目标与受影响要求，显式声明工作／检查
影响，并产生一次提交结果。各既有领域仍验证自身效果和权限。证据可支持提案，
不能自行降低用户验收。预算、权限、停止条件和根范围的变化仍走对应权限；
已有明确授权直接复用，不增加确认轮次。

本提案不修改安装态或当前上限。第 3–10 节定义提议的契约，第 2 节是源码事实，
第 11 节是交付计划，第 12 节列出待决事项。设计接受、实现和真实路径资格分开。
本文不授权实验、迁移或本提案之外的发布。

## 2. 当前能力与根本缺口

| 已审计归属 | 已有能力 | 与本提案有关的限制 |
| --- | --- | --- |
| [成果规则](../../../loopx/control_plane/goals/outcome_requirements.ts) | 稳定成果／要求 ID、来源、工作关联、当前 Agent 自查 | 只能追加，不能替换已有要求描述。每 Goal 最多 24 项成果；每成果最多 32 项要求、64 项来源、64 项工作关联。全部声明共用 131072 字节 UTF-8 JSON，自查另共用 131072 字节。 |
| [验收事务](../../../loopx/control_plane/goals/acceptance_authority.ts) | CAS、精确操作重放、canonical 读回 | 细化将 `goal_outcomes` 写入完整 Goal 投影，回执也保留验收投影。只缩小 prompt 不会消除存储／回执增长。 |
| [当前目标](../../../loopx/control_plane/goals/goal_objective.ts) | 有序修订、owner 应用、逐 Agent 采用、新执行门禁 | 修改目标正文，明确不修改验收／权限；历史本身有 64 次修订、256 KiB 上限。 |
| [受治理修订](shared-goal-alignment-and-governed-amendment-v0.md#93-bounded-local-implementation-and-operation) | 显式本机 profile 可按预先约定的策略提交工作，保留根承诺 | 有界实现不等于任意要求替代，也不是通用演化引擎。 |
| [原生对话](../../../loopx/chat_loopx_mode.py)、[replan](../../../loopx/control_plane/work_items/replan_semantics.ts) | `refine_outcome`、目标准备／采用和语义规划指引 | 普通纠正主要引导到只增细化；目标提案主要针对明确用户方向使当前目标失真的情况。 |
| [Goal UI](../../../apps/presentation/dashboard/src/features/personal-workspace/goal-outcome-requirements.tsx) | 查看要求／证据／来源，补充要求，保留待确认写入 | 首屏仅显示三项时也加载完整集合；没有要求修订／撤回路径。 |

容量拒绝符合当前契约。把新请求只写入 Vision 没有修复它：Vision 管执行路线，
不管验收。增大上限只是推迟失败；缩写要求可能丢失语义；为绕容量拆 Goal 会
丢掉共享义务。

更深的错配是：**用单调累加表示持续演化的意图**。纠正可以替代旧条件；持续性
条件通过一次仍然有效；实验结果改变可信度，不自动改变承诺；过期来源需要保留
历史，但不必每次进入工作上下文。先定义这些语义，再设计分页。

### 模型为什么可能没有使用已有演化路径

源码证明能力存在，不证明使用频率。
[test_goal_objective_revision.py](../../../tests/control_plane/test_goal_objective_revision.py)
明确断言普通上下文不主动提示 `prepare-objective`。原生工具提供准备能力，
但普通纠正路径指向 outcome refinement，实质目标核对主要放在 replan。
而且目标修订本就无法修复要求声明已满。
这些是可发现性和操作适配的疑点，不能证明某个模型忽略了正确可用操作。
旧宿主缺少工具、不知何时适用、提案／应用阻力、调用后失败，要分别测量。
提高调用次数不是目标。

## 3. 一套演化契约，区分不同事实

```mermaid
flowchart LR
  I[原始请求与获授权纠正] --> E[既有 Goal 演化权威]
  E --> C[当前目标与有效要求]
  E --> H[不可变变更与原始回执]
  C --> W[按任务与 Agent 组织的工作上下文]
  W --> X[既有 Todo 与租约执行]
  X --> V[绑定版本的结果与独立检查]
  V --> E
  V --> R[验收与请求方实际使用]
```

| 事实 | 权威含义 | 演化规则 |
| --- | --- | --- |
| 原始请求／根承诺 | 历史起点与适用的权限边界 | 保留精确来源和生命周期；执行目标修订不能暗改根授权。真正超出边界的变化走受治理 owner 或关联的后继生命周期。 |
| 当前契约 | 当前目标、有效要求版本、范围、必需／可选适用关系 | 只经获授权且绑定来源的变更集改变。成果仍从属于 Goal，不新增预算或执行循环。 |
| 计划 | 工作、依赖、负责人、路线 | Todo／Vision owner 可在契约内重规划；换计划不一定要改 Goal。 |
| 证据 | Agent 自查、独立检查、产物版本和来源 | 原 owner 更新观察；失败或过期不能直接改写要求。 |
| 演化历史 | 改了什么、原因、来源、权限和影响 | 保留不可变版本及原操作回执；历史文字不自动成为当前指令。 |

要求具有精确 Goal 生命周期内的稳定身份、版本、完整正文、声明范围、来源引用
和适用的工作／检查关联。获授权的修订显式连接前后版本；获授权的撤回保留旧版
及原因。拆分／合并保留全部前驱身份和显式覆盖，不能用文本相似度证明等价。
这是对既有 Goal 词汇的提议扩展，本 PR 没有交付新 schema 或枚举；实现必须注册
版本契约并迁移每个生产者和消费者。

满足情况与适用性分开：一次通过不终止持续性义务，撤回也不能把历史失败改成成功。
归档改变存储位置，不改变权限或适用性。所有当前成果要求满足也不代表根 Goal
完成。独立检查、Agent 声明、请求方采用分别保留。

旧来源属于成果级。迁移必须保留这个粒度，无法确定逐要求来源时标为未知，不能
猜测哪条历史消息引入了哪项要求。完全相同的不可变正文可共用存储，但不同来源
身份不能因文字相似合并。自然语言要求提取仍由 Agent 判断，原文可用于核对遗漏。

## 4. 在有意义的决策点演化

复用直接消息、实质反馈、replan、结项路径，不增加每 Turn 表单、定时器、强制
提案或关键词检测器。Agent 根据真实宿主来源及当前事实判断：

| 观察 | 既有 owner 的响应 |
| --- | --- |
| 新的范围内承诺 | 添加到对应成果；同一声明 ID／版本完全相同则复用，不制造新修订。 |
| 用户改条件，目的不变 | 准备显式替换／撤回并保留历史，不追加相互矛盾的有效条件。 |
| 用户一起改变当前目的与验收 | 准备一个变更集，不分开提交新标题与旧条件。 |
| 新证据／检查失败 | 更新证据、重规划；有有效权限依据才能提议改契约，不能通过降低标准让失败变通过。 |
| 没有实质契约变化 | 继续或改计划，不写演化记录、不重复确认。 |
| 范围／权限／预算变化 | 交给对应受治理权威；缺权限仅阻塞依赖它的效果。 |

变更集包含原来源身份、actor、operation identity、受影响记录的预期版本、精确
新增／替换／撤回、原因、受影响工作／检查和保留条件。预览呈现可读的前后差异
及每项效果所需权限。既有 owner-apply 路径执行权限检查，准备不能授予权限。
Agent 仍可像现在一样记录自己成果中已获授权的新增要求；协调者不能因协调身份
改写同伴承诺，也不能把省略 actor 的 CLI 写法当成授权证明。

TS owner 校验完整变更集，包括当前 Goal 生命周期、共享约束／索引版本；原子
发布目标／要求变更、失效引用、journal event 和 receipt。外部执行、同伴计划
修改和 oracle 运行是使用既有恢复机制的后续效果，不冒充同一事务。
部分合法的变更集整体拒绝，不能只提交新目标；另行明确选择的独立变化仍可推进。

效果不确定时保留原操作。意图改变走既有冲突／重基路径，不能换 ID 掩盖未知
提交。同一身份的 no-op 判定是结构性的，不能由模型自动合并语义相近的用户要求。

## 5. 存储与工作上下文服从语义

### 持久记录与有界操作

扩展既有 TypeScript AuthorityStore 的版本记录读写及索引快照契约。当前契约根、
分页索引与不可变要求／目标版本、来源、证据和历史回执分离。根节点不能保存
无限增长的记录／分段指针列表。有界回执引用不可变已提交记录，并能解析回原始
结果；旧回执字节及重放身份绝不重写。

SQLite 是首个本机实现目标；PostgreSQL 在 tenant／生命周期隔离下采用同一逻辑
事务。File 在持久分段发布协议取得资格前，保留为兼容和一致性基线。
不支持新格式的 provider 显式拒写，不能用若干独立 JSON 写冒充原子性，也不能
自动切换 provider。复用[共享权威持久化工作](shared-goal-authority-state-provider-v0.md#preferred-local-direction-and-compatibility-boundary)，
不建立验收专用数据库。把旧完整投影塞进 SQL 一行也不算完成迁移。

分别约束单请求、单记录、响应页、决策上下文、保留存储和磁盘恢复余量。
切换前计算迁移空间，包含备份、回执和临时写。跨页变更先暂存有界块，全部就绪并
验证后一次发布 manifest，任何前缀都不能生效。v0 仍执行旧 128 KiB 上限。
新上限必须有工作负载测量和显式契约决策，不能为了让当前失败通过而改常量。

### 决策完整，不要求每次把历史全部放进 prompt

复用上下文 owner 与[统一工作契约](controller-executor-unified-contract-v0.zh-CN.md)。
快照根标明精确 Goal 生命周期、契约版本、来源版本、声明覆盖、强制共享约束和
可解析详情。任务读取覆盖关联要求、依赖、受影响共享约束和反证。摘要用于导航，
精确记录保留权威。每页／cursor 绑定快照、查询、actor 和权限；过期、详情缺失、
digest 不匹配均显式失败，不能返回部分成功。

[outcomeContextNavigation](../../../loopx/control_plane/goals/outcome_requirements.ts)
已使用注册关系，而且明确只是建议，不是阅读门。不能暗中升级为独立性证明。
未知／未关联关系需要相关扩读，并呈现覆盖不全；因权限不可见也不能说没有义务。
强制读取仍由原契约 owner 定义。有界首个响应必须说明遗漏并给出可用批读入口。
最终整契约验收在同一快照上使用完整索引覆盖，包含首屏之外的要求；搜索结果或
向量 top-k 召回不能证明完整性。

缓存和 delta 绑定精确基线与来源摘要。基线失效／缺失时回读完整的**相关快照**，
必要时明确分页读取全量，不能静默截断。复用已交付的当前详情，无变化轮次不
增加阅读 ACK。替代当前完整成果上下文前，必须验证生产者→模型→行动路径。
输出变小本身不证明义务保留、完整成本降低或决策改善。

## 6. 多 Agent 的变更、并发与采用

演化提交根据显式要求／工作／检查关系计算影响范围；覆盖缺失是未知，不是独立。
共享约束可能确实影响所有 peer，局部条件不必让无关 lane 全部失效。责任转移是
显式获授权变更，使用既有 handoff 和接收方确认，不能成为分页／压缩副作用。

记录版本、Goal 提交 cursor、provider revision 是不同身份。无关存储写最终应
允许重试，不必重新编写语义提案。版本化命令绑定不可变的领域读写集合，包括
共享约束版本、索引／不存在谓词；store 原子检查。这样才能防止两个看似独立
变更共同破坏共享条件的 write skew。同记录冲突需要重基，journal 顺序不能
替代读集校验。M1 可保留全局 CAS 并披露竞争成本，M2 必须验证范围化并发。
不得重新解释 v0 operation digest，也不得改变 provider-revision 参数重试旧操作。

既有 replan／adoption 路径为每位 Agent 保留受影响版本检查点。到下一个相关执行
边界时，由该 Agent 协调自己的计划，并将决定绑定到精确契约／工作依据，尽量
合并进普通规划／写回。已采用且未改变的依据不重复写回执；peer 不能代替同伴
采用，无关 lane 不等待全员屏障。通知或已读回执不是语义采用。丢通知通过既有
scheduler／outbox 从 canonical 状态恢复。

在途工作保留原 Turn／lease／settlement 身份。变更集按现有 R4 策略为每项受影响
工作记录租约处置：可继续、下次受保护操作前须更新工作依据，或须停止。缺少处置时，
由现有策略暂缓受影响变更。必要的转换由现有租约或宿主 owner 执行。契约提交
本身不扣额，原 Turn 仍可恢复尚欠效果。已有 stop 和权限规则仍按各 owner
要求立即生效。旧版本产物带原
依据保留可读，在验收 owner 验证当前覆盖前，不能满足新版本。依赖消费者须
明确采用已验证版本，并把结果返回原请求。结算旧 Turn 或接受旧产物不能掩盖
新增要求。

## 7. 让演化可发现、可恢复

在既有 `goal-acceptance`／受治理变更界面中提供统一的 **修改 Goal 契约** 路径；
保留当前命令作为版本兼容适配。在实际纠正／replan 决策点交付有界前后差异和
适用的可调用操作。宿主提供来源及未决操作身份，不推断预期答案。Agent 可以
判断只需改证据或计划。不把冗长演化讲义永久塞入每轮 heartbeat，也不为增加
工具使用率强迫修订。

复用宿主请求 envelope／inbox，在派发前保留原纠正。待处理请求**不是已生效
验收**。区分明确拒绝、效果未确认、契约已提交、工作实际采用。
容量拒写时说明验收没变，保留精确草稿／来源和恢复入口；Vision 可以记录受阻
路线，不能把要求说成已保存。丢响应先查原回执；迁移／重基后按对应操作规则
重试或准备新意图。没有持久副本时先从获授权原历史恢复，再考虑让用户重述。
依赖新条件的操作不能悄悄沿用已矛盾的旧契约；独立获授权工作仍可继续。
不新增 Goal 全局停止，也不建立另一套权威要求队列。

在 **Goal Overview → 支撑成果** 与既有设置中呈现当前要求和可读拟议变更；
历史、来源、受影响工作／Agent、容量细节按需展开。失败时保留未发送正文和
原请求。区分“已保存”“工作待核对”和独立验证，不乐观显示验收通过。
桌面／窄屏覆盖过期依据、保存失败、来源不可访问、冲突和重试。
CLI 与 Lark 原生会话复用同一提案／提交／读回 owner；Lark 传输、送达和原会话
返回需要独立证据。不需要新增配置编辑器；mock 页面不能代替真实后端的打包验收。

## 8. 迁移、隐私与回滚

替换 `goal_outcomes` 或目标历史前，盘点全部字段及消费者。保留 `goal_id`、精确
`goal_ref`、state／outcome revision、ID、原目标／owner、完整要求、有序工作
关联、来源 ref／summary、review basis／items；保留目标原文、完整有序修订及
digest、registered Agents、adoptions。检查关联、提案、回执及历史结果形状也
保留。不支持的字段应在预检失败，不能消失，更不能用模型摘要替换原字节。

显式可恢复迁移：捕获同一 source revision，暂存记录／索引，校验有序清单、
digest 和前后语义读回，短暂 fencing 写入并复核来源，在原生命周期／store
lineage 下原子选择新格式。并发来源变化使受影响准备重新开始。没有双写权威、
伪造新 Goal 或回执改写。升级本身不迁移运行态、不启用新 guard。

只有满足旧契约时才给旧 reader 完整兼容读回，否则明确要求升级，不能把截断
视图标成完整。新格式写入超出旧表示能力后，回滚必须保留兼容读写器，或通过
明确合格的无损反向迁移。用旧备份覆盖新承诺不是回滚；压缩和恢复始终保留
精确来源版本解析及原操作查找。

读取、索引、数量、变更事件、缓存、产物解析都遵循原 principal／tenant／Goal
生命周期和受众权限。共享摘要不能通过标识或数量泄露私有要求。本机 File／SQLite
范围不证明跨人 ACL 或云端授权，资格仍由[共享权威](shared-goal-authority-state-provider-v0.zh-CN.md)负责。

## 10. 运行行为与排除的捷径

容量读回分别呈现有效声明、保留历史、当前自查、回执／索引增长、分页上限及
磁盘恢复余量。说明具体失败预算、请求明确拒绝还是效果未确认，给出既有重试／
迁移入口，不建议删除承诺。压缩必须保留可解析精确版本与重放索引，恢复有界；
备份在一致快照下覆盖所有引用记录。

只加上限、有损总结验收、归档仍有效要求、另开 Goal 绕容量、用 Vision 当备用
权威都违背目标契约。只加一句“多调用目标演化”仍然留下不支持的迁移和容量
问题。不要求新增向量库、CRDT 或微服务；冲突解决遵循权限和语义，不自动合并
自然语言正文。
