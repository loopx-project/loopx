## 1. 决策摘要

交付一项显式开启的个人职责：持续跟进指定飞书会话中的承诺，准备授权范围内的
材料，在用户桌面原对话返回带来源的每日简报。用户可以纠正、忽略、暂停和查看
每项事项，无须学习 Agent/Turn 术语。

人的承诺复用规范 User Todo，代办准备复用 Agent Todo。提议携带来源关系，
不新增任务账本。现有类型化 Todo、权限、调度、外部效果与结果返回 owner 保持
权威。来源文本和模型输出不能授予权限。

本 RFC 不批准自动外发、扩大账号访问、新调度器、云端部署，也不宣称个人 Agent
产品已经完成。

## 2. 问题与动机

用户答应周五交草稿，随后收到延期至周一的变更，之后分享了草稿。助手应维持
同一事项、更新依据、准备允许代办的材料，并区分交付与验收。现有 Inbox、Todo、
报告和 Chat 组件尚未证明这条持续流程。逐条消息摘要容易重复建任务、把他人的
承诺归给用户，或者错误宣布完成。

必须保持的约束：

- 每项承诺提议有授权来源、责任身份、证据和明确的不确定性；引用和提问不等于承诺。
- 相同来源重放至多产生一次对应的规范变更。
- 提取、ACK、草稿或消息已发送，均不能单独证明承诺完成。
- 用户纠正在后续模型运行及旧消息重放后仍然有效。
- 来源新鲜度、工作状态与执行可用性分别表达。
- 读取群聊不会授予代表成员发言或分享其数据的权限。

## 3. 范围与非目标

首个配置支持单用户、单个本地运行时、已有或明确创建的私有 Goal、选定授权群聊、
本地草稿准备和仅本人可见的桌面简报。展示机器人实际可见范围。必须将用户映射到
已核验的平台身份；昵称不能作为身份。群访问不代表私信或全账号访问。

暂缓邮箱、钉钉、日历写入、外部任务双向同步、云端全天运行、多 Agent 团队、
连接器市场及跨来源自动身份匹配。不要求新的个人记忆平台或 UI 重做。

## 5. 提议架构

### 归属与权威

组合现有 `lark-event-inbox`、`manager-context`、`periodic-report`、规范 Todo
操作和 App 对话。Provider 为随包提供、可选启用的 `loopx-lark`。不新增内置
capability 或独立可安装 connector。理解由 Agent 完成；与平台无关的校验和
变更映射放在现有 TypeScript 工作项边界。飞书认证、标识和历史留在 provider。
实现语言确定为 TypeScript，编译为 JavaScript 并运行在 Node.js。飞书 provider
适配、事件规范化、语义提议校验、规范操作接入、报告组合和恢复均遵循此约束。
桌面 UI 使用 TypeScript/TSX，测试复用现有 JS/TS 工具。该流程不新增 Python
模块、Python 子进程桥接或第二个 Python 决策源；JavaScript 限于既有工具约定。

第 4 节的 Python 源码链接仅描述已审计基线，不代表目标实现。复用既有类型化
owner 和受支持 API。如果必要操作仅有 Python 实现，在宣称该阶段完成前，将
最小内聚 owner 及活跃调用方迁移到 TypeScript，提供特征测试、真实路径等价
验证和回滚证据。禁止通过直接写状态绕过规范权威。M1 必须识别并解决这些依赖；
最终流程须在无 Python 进程条件下运行。仓库全量迁移不在范围内。仅在首个真实
调用方需要时增加 helper。

### 提议与任务映射

复用现有类型化操作/提议存储和生命周期，在其中定义带版本的跟进载荷，不建立
独立数据库或竞争状态枚举。载荷包含来源绑定、opaque 事件/修订引用、核验后的
责任身份、候选标题、提议操作、更新时的目标 Todo 身份及预期修订、证据引用，
以及可选截止时间、时区和解释依据。未知日期保持缺失；明确清空和字段未提供
含义不同。非法日期和身份不匹配拒绝变更；责任或时间模糊时保留提议。

语义结果包括无需跟进、澄清、创建、修改、提议完成和忽略；实现时使用 typed
variant，并保持规范 Todo 转移规则。完成需要用户明确判断，或符合此前授权的
可验证完成条件。“已发出”可成为已交付证据；承诺要求对方验收时仍需对方证据。

通过已有引用和回执维持“来源 → 提议 → Todo → 准备产物 → 证据”关系。
User Todo 保存个人承诺；关联 Agent Todo 保存有界准备任务，其完成不会完成
人的承诺。合并/拆分保留旧引用；身份含糊时要求限域审阅。

### 采集、理解与恢复

1. 校验当前授权、绑定和本人身份，通过现有 Inbox 增量采集有界页面。
2. 只用授权上下文及相关未完成事项理解消息。模型提出关联，确定性代码校验
   范围、修订和权限。文本相似度不能独自决定合并或完成。
3. 首版创建、修改和完成先保存为提议，支持批量审阅。后续持续授权可以允许
   明确的一类本地变更；已授权读取和草稿准备无须逐步确认。
4. 通过规范操作应用，幂等身份取自绑定、来源事件/修订和操作，绑定载荷摘要。
   同一身份不同载荷发生冲突；编辑产生新修订。不同消息中的同一承诺需要明确
   关联已有 Todo，传输去重不能替代语义关联。
5. 持久保存效果或无需跟进回执后 ACK/推进游标。持久提议代表输入已处理，
   不代表承诺完成。崩溃后先对账原提议和操作回执；丢响应不能生成第二次操作。
6. 经现有 worker 准入准备材料，将带版本产物返回原桌面对话。简报读取限域
   当前状态，包含来源新鲜度和未解决事项。

并发修改使用预期 Todo 修订。新的用户编辑优先于旧提议；冲突后重读并重新提出。
来源编辑/删除按影响使未执行提议失效；已完成事实保留来源关系并标注证据不可用。

## 6. 替代方案与取舍

| 方案 | 决策及取舍 |
| --- | --- |
| 一次性摘要 | 用作比较基线，缺少持久跟进和纠正 |
| 新建个人任务库 | 拒绝重复生命周期及完成事实分叉 |
| 每条消息转 Todo | 拒绝噪声和责任误判，保留有界提议 |
| 先接齐全部渠道 | 暂缓，先验证一个来源，再复用流程 |
| 等待全量 TS 迁移 | 无须该依赖，只迁移受影响的内聚规则 |

## 7. 安全、隐私和兼容性

默认关闭。关闭时不改变现有 Chat、Todo、采集、调度和报告行为，不调用模型，
不增加通知。启用预览明确来源、历史窗口、本人身份、本地动作权限、预算、频率、
保留期和交付对象。凭证留在现有 provider 边界；私有载荷不得进入公共状态、
日志、fixture、报告、PR 或仓库。

本人私有简报使用独立权限校验配置，不输入现有公共安全报告预设或共享飞书投影。
撤权立即阻止新的读取和依赖效果，排队重放在实际派发时再次检查。保留/删除与
断开连接分开定义。外部文本均为不可信数据，包括自称来自用户的指令。
外发、分派他人或修改外部任务需要匹配的外部效果授权及读回，均在 v0 范围之外。

新增 schema 保留旧字段。旧 reader 安全忽略可选元数据，或在写入前拒绝未知
操作版本。无法保留载荷的 reader 必须先升级再启用；禁止双 writer 和静默丢字段。

## 8. 迁移与回滚

不自动导入历史消息或已有 Todo。启用从明确游标/时间窗口开始，历史补抓预览
有界范围。预检 provider 权限、本人身份、私有存储、执行器及版本兼容性。
首版不要求全局存储迁移。

关闭后停止后续采集、理解及周期触发。通过已有限域 owner 排空或取消在途任务，
保留防重复回执。已创建 Todo 保留并标注来源断开。用户要求删除时删除私有内容
和记忆索引，仅保留授权的最小无正文去重/审计信息。不兼容降级前关闭功能，
需要数据迁移才能恢复时提供仅本人可用的导出。

## 9. 验证与验收

| 主张 | 待实现/执行的证据 | 必须结果 | 边界 |
| --- | --- | --- | --- |
| 正确理解责任 | 冻结标注集：本人/他人承诺、引用、否定、歧义、时区、编辑、删除 | 分别报告准确率和召回率；歧义不静默生效 | 模型评估，不证明生命周期 |
| 持续跟进 | 独立期望序列：承诺、改期、重复、用户纠正、草稿、完成 | 一个 Todo、正确修订；准备不能完成承诺 | 真实隔离存储上的类型化集成 |
| 效果恢复 | apply/ACK 前后崩溃、响应丢失、重放、并发编辑 | 无重复变更、丢失待处理项或跳过游标 | 隔离运行时故障注入 |
| 保持边界 | 撤权、其他用户、来源注入、关闭功能 | 无越权读写和关闭态副作用 | 所有受影响共享入口 |
| 完整桌面流程 | 发布包、真实授权飞书来源、真实执行器 | 连接、采集、审阅、准备、纠正、重开、查看同一返回产物、断开 | 浏览器 fixture 无法独立通过 |
| 纯 JS/TS 执行 | 在 Python 不可用的环境运行打包流程，覆盖采集、变更、准备和返回 | 无 Python 进程或桥接依赖，规范状态保持等价 | 整条选定流程，单测不足以通过 |
| 诚实运行 | 休眠/断网、凭证过期、预算耗尽 | 可见过期/阻塞状态、有界恢复、无全天在线假象 | 仅本地主机配置 |

模型资格使用至少 100 条合成或经授权消息，其中至少 30 项真实待办承诺，标签
独立于模型输出制作。提议准确率 = 正确提议数 / 全部提议数；召回率 = 正确发现
的承诺数 / 标注的全部承诺数。首版目标准确率至少 95%、召回率至少 90%，
错误责任人自动变更和越权效果均为零。这些是提议验收阈值，尚无性能实测。
保留失败和模糊样本。

随后运行用户授权的七天试用。检查全部提议/采纳事项，并独立抽查来源寻找漏项。
报告分母、来源窗口、重复率、截止时间准确率、核验后的准备结果、模型成本以及
每日审阅纠正分钟数，与可比工作量的人工基线比较。小样本保持探索性结论。
推广需要正确性门槛通过且审阅纠正总耗时下降；公开材料仅包含脱敏汇总。

## 10. 运行契约

复用来源健康、积压、新鲜度、预算准入与限域停止。已采集、已提议、已应用、
准备中、已返回、已核验分别来自各 owner，不引入万能 active 布尔值。

限制历史窗口、分页大小、每日模型预算、重试次数和保留提议数量。超限保留游标
并展示积压，不静默丢弃。事件触发结合现有有界补抓。现有调度器负责一项显式
每日简报计划，包含时区和免打扰设置；具体工作写入规范状态，不修改通用心跳
提示词。休眠时本机暂停；唤醒后对账，每个已结算报告窗口最多一份补发简报。
不宣称云端可用性。

桌面展示覆盖范围、最近同步成功时间、未解决事项、来源链接、产物版本、暂停/
断开和可执行修复。常规进展保持安静，紧急提醒遵循明确策略。CLI 读回同一状态；
飞书采集不授予飞书简报发送权限。不建立第二套设置 owner 或强制审批层。

## 11. 规范交付计划

| 阶段 | 前置 | 完整出口 | 回滚 |
| --- | --- | --- | --- |
| M1：读取与审阅 | 明确来源/本人身份；类型化提议到规范变更接口 | 安装版连接 → 来源 → 提议 → 审阅 Todo → 纠正 → 桌面简报，含重放/撤权测试 | 关闭配置，保留 Todo/回执 |
| M2：准备与返回 | M1；可用执行器与原路返回 | 关联准备产物、真实来源变更、重启、原对话核验结果 | 停止准备范围，保留已审阅产物 |
| M3：周期试用 | M2 正确性；明确频率/预算/保留期 | 七天证据、每日简报、断网恢复和注意力成本实测 | 可分别关闭计划和配置 |

M1 包含前端、飞书适配器和 CLI 读回；只交付后端属于部分完成。M2 复用在途
App 连续性工作，不重复实现结果 watcher。归属总体路线图 S1/S5/S6/S8/S9，
不另立平行里程碑，不关闭原有验收。实现前解析规范 Todo 和关联 PR，复用已有
后继任务；本提案不宣称已领取运行中的任务。

相关有界重构：先刻画采集到效果结算、提议到 Todo 映射，再提取已证明的通用
规则到类型化 owner；飞书传输保持独立，不建设推测性 provider 框架。
