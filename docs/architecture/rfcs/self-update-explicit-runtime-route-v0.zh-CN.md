# 回滚全程保留所选运行目录

状态：实现提案。

[English](self-update-explicit-runtime-route-v0.md)

## 问题与责任层

显式指定 registry 与 runtime root 的 `update --rollback`，在规划和启动目标运行时
时丢失了这两个参数。两个默认目录都已有状态时，目标运行时的只读权威兼容检查会
拒绝隐式路由，父进程却将它报告为格式不兼容；即使该检查通过，后续诊断也可能
读取另一个目录。

修复位于既有更新器。回滚与前向更新复用原有 registry/runtime 解析器选择路由，
将同一路由传给规划诊断及每个子进程，并共用参数构建函数。直接调用且未提供路由
的调用者仍保留原有隐式行为，不增加状态、provider、迁移、权限、调度器或执行者。

## 失败与验收边界

兼容检查仍在修改启动器之前，以只读 `--require-current` 执行。退出码和有界输出
保留在既有 execution 读回中，默认 CLI 同时展示失败检查的有界输出，不猜测原因。
核心诊断失败仍恢复原启动器；
扩展失败仍如实报告已激活运行时与不可用 provider，不把失败改成成功。

验收从实际回滚 CLI 贯穿规划与三个子检查，覆盖各阶段拒绝和含空格路径，并保留
archive、pip、pipx 前向更新的既有路由回归。安装验收分别说明隔离回滚、本人实际
启动器变化与生产存储恢复的范围。本修复不解释另一安装过程为何选择了较旧源码。
