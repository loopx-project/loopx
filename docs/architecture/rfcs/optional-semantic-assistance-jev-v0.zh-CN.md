## 2. 问题与证据边界

操作者可能看到合法观测、通过的测试和连续进展声明，但工作实际服务于另一个结果。反过来，特征测试、负面实验、研究和合理等待即使未产出完整功能，也可能有价值。有效评估必须区分这些情况，不能奖励有说服力的自述，也不能误伤必要前置。

### 2.1 重复触发器能够证明什么

在具名源码基线上，[typed_progress_repeat_trigger](../../../loopx/control_plane/work_items/progress_observation.py) 需要足够的连续有效观测，去重可归属的 Turn，比较相同指纹，并且仅对 `unchanged` 或 `blocked` 触发。指纹包含所提供的语义身份与证据字段，`hypothesis_id` 是其中之一。

| 示意情形 | 对这条触发器的影响 | 仍然未知的部分 |
| --- | --- | --- |
| 连续等价的 `unchanged`/`blocked` 观测 | 有效序列达到阈值后可以触发 | 这种重复在业务上是否合理 |
| 工作自报 `advanced`，实际未推进已批准结果 | 即使指纹不变，也不满足这条规则 | 完整流程是否能发现；任何模型是否有足够证据判断 |
| 等价工作修改参与指纹的 ID | 打断相应窗口内的指纹相等条件 | 实际是否为同一工作，或是否属于获准变更 |
| 有效推进或必要前置工作 | 可能不触发重复规则 | 未触发不等于进展已经认证 |

这些是从源码推导的边界案例，不是新增的模型实测。该函数负责精确重复检测，不负责语义完成验收。它的边界支持一个研究问题，不能证明整个 LoopX/Agent/reviewer 流程都看不见。搜索少量源码关键词也无法证明这种全局缺失。

### 2.2 为什么仍把 Jev 列为候选

Jev 的有限类型化问题与概率分布接口，可能适合一个小范围评估任务。这些接口特点支持比较，不支持直接采用：现有模型也能进行结构化、只读评估。本 RFC 没有建立准确率、成本优势、严格超集或生产 token 预算的结论。合成案例可以检查问题设计；把手写描述命名为 `observed_artifacts`，并不会使它成为宿主读取的证据。

### 不变量

- **I1：保留已有权威。** 可选建议不能授予工作权限、解除 hold、替代必要评审或否决确定性保护。
- **I2：关闭不新增副作用。** 不新增凭证读取、client、网络、文件或 worker hook；普通成功和拒绝行为保持不变。
- **I3：比较实际基线。** 包含现有 Agent、reviewer、工具和规则；不虚构本地 fallback，也不剥夺基线正常调查能力。
- **I4：未知如实表达。** 未评估、失败、弃权、不确定和过期不同，均不等于进展正常或批准。
- **I5：区分证据、推断和动作。** 类型合法的模型输出是判断记录，不是交付证明、来源真实性或授权。
- **I6：读取和发送分别授权。** 凭证、安装和私有进程运行不等于获准上传私有数据。
- **I7：保留原 owner。** 一个有限问题由一个领域负责，不建立第二套 planner、评估政策、registry 或安装器。
- **I8：成本有界、允许退出。** 不静默重试或切换提供方；无收益可以停止，缺少 live 证据不能算通过资格验证。

## 3. 应用机会与暂定价值排序

D1–D8 是稳定讨论标识，不是优先级或运行时类型。第 3.1 节根据源码支持的应用机会建议调查顺序，不代表已测得 Jev 优势，也不构成实施承诺。选定研究仍需要具体案例、owner、对照、获准数据与预算。在原六个场景上新增两个不同 caller：选择下一个合法 Todo，以及选择 Explore 候选组合。

| 场景 | 目标用户 | 当前判断者和基线 | 主要价值假设 | 就绪条件与不采用条件 |
| --- | --- | --- | --- | --- |
| **D1：进展与目标偏离** | 长周期工作操作者 | 执行 Agent、操作者、已启用 reviewer、progress/frontier/writeback 与 acceptance 路径 | 更早发现需要复核目标关系的工作 | 需要批准目标、可归属产物、有界历史和独立标签；若只是重复已有评审或误伤前置工作，则不采用 |
| **D2：新概念与 owner 复用** | 开发者 | 开发 Agent、owner 检索、语义评审和已交付 inventory | 缩短寻找合适既有 owner 的时间 | 需要候选及契约含义，不假定 #4743 本地探针已交付；拒绝凭字面值相同推定语义等价 |
| **D3：交付声明与证据对照** | PR reviewer | 能实际调查和验证的 exact-head reviewer | 更早发现具名声明与证据不符 | 需要一个未充分覆盖的子任务；不增加没有增量的第二轮整体 PR 评分 |
| **D4：材料/证据重排** | 操作者或证据消费者 | 实际检索候选、原排序、Agent 选择和必读规则 | 减少找到有效证据所需的阅读 | 需要相关性预期和覆盖记录；不能隐藏必读来源或丢失候选 |
| **D5：Skill/capability 建议** | 任务操作者 | 宿主发现、现有 catalog、Agent/用户选择 | 减少遗漏或无关的能力选择 | 需要真实任务/catalog 案例；拒绝重复发现能力或暗示安装权限 |
| **D6：Replan 候选比较** | planner/manager | 原 planner、合法备选、可归属历史和约束 | 更好识别重复探索 | 需要有意义的备选和历史结果；不能形成第二个 planner 或压制合理探索 |
| **D7：同优先级 Todo 排序** | 选择下一步工作的 Agent 或 steward | 原 Agent 选择、类型化 eligibility/claim 规则和确定性优先级/顺序键 | 在下一个有界工作窗口内产出更多获验收的目标价值 | 需要可比较的合法 Todo 和目标/依赖证据；拒绝优先级倒置、饥饿或仅重复 Agent 判断 |
| **D8：Explore harness 排序** | 分配固定探索预算的研究操作者 | 原静态分支评分、已启用 router 反馈、组合/admission 约束及 Agent 判断 | 在相同预算下获得更多有助于决策的证据 | 需要固定候选集、历史和独立结果评价；拒绝重复研究、新颖性偏好或靠更换评价器取得的表面收益 |

每项获选实验只选一个主要假设：新增检出、提前发现、降低判断成本、减少阅读，或提高固定预算内的有效结果价值。其他指标作为约束，不同时承诺全部收益。除非证明真实依赖，否则 D3 不要求等待 D1/D2，D5 也不要求等待 D4。

D1 继续作为第 2 节展开的偏离检测案例。下列机会分析建议优先讨论 D7/D8 的研究选择，因为它们有有界备选和反复出现的分配决策；没有任何方向因此获准开展实验或实施。

### 3.1 哪些位置最值得比较

这里定性比较的是**增加评估环节的预期净价值**，不是模型排行榜。综合考虑决策频率与影响、相对完整基线可能改善多少、证据就绪度、误判损失、评估/延迟/维护成本和可逆性。潜在收益很大但难以归因的场景，可能排在收益较小、较易评价的干预之后。这里没有实测效应量或虚构的数字权重；同一层内的顺序仍为暂定。

| 调查顺序 | 应用机会 | 排在这里的理由 / 决定性不确定因素 | 主要验证结果 |
| --- | --- | --- | --- |
| **首批 · 1** | **D7：同优先级 Todo 排序** | 高频选择直接影响目标推进，已有候选身份与优先级；仍须评价反事实价值和完整上下文 Agent 的覆盖 | 固定预算/窗口内，相对正常 Agent 选择的获验收目标贡献 |
| **首批 · 2** | **D8：Explore 分支、实验和 worker bundle** | 已有 harness 比较入口与结果历史；既有启发式/router 较强，增量收益更难证明 | 固定研究总预算内，独立评价为有用的发现、反证或决策 |
| **下一批 · 3** | **D4：材料和记忆证据排序** | 高频有界检索可能降低阅读成本，来源和必读覆盖可观察；相关性本身不证明结果效用 | 获得充分决策证据所需的阅读量，且不丢必读/相反来源 |
| **下一批 · 4** | **D3：评审焦点与补充验证选择** | 漏掉关键声明的代价可能很大；在现有评审义务内排序调查对象，不替代 exact-head 评审 | 评审预算内独立确认的重要不一致，并约束漏检 |
| **下一批 · 5** | **D1：进展/偏离评估** | 潜在浪费避免价值高，但批准意图、产物历史和前置上下文的准备昂贵；误报消耗注意力 | 相对完整流程更早发现可行动问题，且误报有界 |
| **后续 · 6** | **D6：继续、切换或 replan 备选** | 可能影响重大，但反馈慢、干预成本高；与 D7 不同，它可能修改拟做的工作而非排列已有工作 | 计入切换/恢复成本后，独立评价更好的计划选择 |
| **后续 · 7** | **D2：概念和 owner 复用** | 开发者收益具体，但须先确认 inventory/检索改进不足以解决 | 降低 owner 查找/返工成本，同时避免错误语义等价 |
| **后续 · 8** | **D5：Skill/capability 建议** | catalog 有界，但与现有发现和 Agent 选择明显重叠 | 以更低的总选择成本减少有实质影响的能力遗漏 |

D3 包括按缺陷可能性 × 后果 × 可检出性减去调查成本，排列可选探针；强制验证和社区/积压年龄评审层级仍由原 owner 决定。D4 包括证据窗口构建和记忆召回，不授予遗忘或删除材料的权限。D8 包括实验/组合选择和分支/bundle 排序，不按 harness 自评分选择 profile；测试 ranker 时固定 harness/profile，比较 profile 属于另一项处理。

其他可能用途包括执行器/模型分配、replay checkpoint 放置和人工注意力分流。先证明存在语义判断缺口，再考虑独立 Jev caller：[执行器可用性/成本](../../reference/protocols/local-agent-launch-plan-v1.md)与 replay 节省已有专属 owner，注意力分流必须保留必要升级。不能用模型猜测替代已测得的资源或 replay 算术。D1/D3 可以提供复核证据，无需增加第二个注意力调度器。

### 3.2 候选的“预期价值”具体指什么

区分**应用机会优先级**（第 3.1 节）和**获选应用内部的候选效用**。对合法候选 `a`，可采用以下研究分解：

```text
预期净价值(a | 当前证据、决策时间窗口)
  = 预期新增的获验收结果贡献
  + 不重复计入的依赖解锁价值
  + 与决策相关的信息价值
  - 执行、验证和协调成本
  - 预期失败、返工和切换损失
```

这是讨论模型，不是新增评分字段或生产公式。收益归属于已批准目标和时间窗口，不由模型定义；下游贡献须去重，不能同时按解锁和最终交付计算两遍。负面实验若排除了重要不确定性，也有价值。confidence、任务完成概率、证据数量和语义相似度，都不同于价值。只有事件定义明确且有校准证据，才能用概率乘影响；Jev 分布并不会自动成为已校准的工程成功概率。

先对贡献、解锁、信息增益、成本、风险和不确定性给出有证据归属的序数判断/区间，不能把序数档位当作同单位数值相加。采用支配关系或 caller 所有的比较标准，暴露取舍并保留并列/未知。后续数值聚合需要共同效用尺度、独立校准和敏感性分析。按稀缺资源计算单位价值只在资源约束明确时有意义；简单的价值/耗时可能无限推迟大型必要工作。保留原 owner 的公平性/截止时间政策、依赖闭包和有价值的探索；缺证据不等于零价值。

例如，在合法 P1 Todo 中，能解锁多项已接受依赖的小修复可能先于容易完成的润色；有界实验若能低成本排除昂贵路线，又可能先于两者。Explore 中，有区分力的反证可能比再次成功重复更有用。这些只是依赖真实目标和成本证据的示意偏好，不是固定任务类别加分。

### 3.3 D7：在合法 Todo 候选组内排序

1. 原类型化 owner 提供当前合法候选集。保留显式优先级、binding/claim/lease、依赖、hold、quota 和强制 lane/公平性规则；只比较过滤后同优先级、同政策地位的候选。高价值估计不能让 blocked 或归其他 owner 的 Todo 变得可执行。
2. 有界卡片绑定 Todo 身份/版本、已批准目标/验收基准、结果贡献、依赖/解锁证据、剩余投入、近期尝试和不确定性。与拥有正常上下文的 Agent 比较，不能只选择弱化的 FIFO 基线。
3. 初期只返回 shadow 建议：候选引用顺序、理由/证据、并列、缺失上下文和原排序。不改写 canonical priority、持久化/展示顺序、归属或状态。展示顺序与执行选择是不同契约。
4. 全量候选仍须可找回。截断窗口时记录覆盖范围与选取规则，轮换/抽样窗口外候选以发现盲区和饥饿，不能静默 top-k 排除。答案不完整、无效或过期时使用未改变的基线，并显示原因。
5. 后续若采用，在原选择边界重新核验当前状态下的 eligibility；纯 reducer、status 读取和写事务中不执行推理。分别记录建议与实际选择/结果。相关证据变化或显式请求时重评，不随每次轮询调用。

### 3.4 D8：固定预算下排列边际研究价值

现有 Explore 并非空白 ranker：静态分数已有 priority/actionability/claim/frontier overlap，可选 router 使用历史、不确定性/覆盖项、新颖性与基础设施反馈；routing bias 与 admission/价值核算分离。语义估计必须与完整已启用基线比较，不能用 Jev confidence 替换这些量。

用假设、支持/反对证据、历史尝试、预期有区分力的观测、依赖/write-scope/资源约束，以及完整探针/验证成本，比较合法实验或分支候选。估计相对已选候选的**边际**信息或结果价值；分支相关性和共享 setup 使逐项独立排序不足以决定组合。保留依赖闭包、多样性/探索额度、资源限制和空置 lane 的选项。区分科学反证与基础设施失败；新颖性和预测成功率都不能单独成为目标。

分开分支排序、bundle 构建、admission 和结果测量。ranker 实验只改变排序，bundle/admission 改动另列为处理。现有 composition-selection RFC 已提供合法有界集合/模型选择设计，不新增竞争协议。harness 建议保持只读，不能启动 worker、claim Todo、支出、提升 finding 或关闭研究义务。

### 3.5 保留优先级建议所需的证据

D7/D8 使用第 6 节 A/B/C 比较；当前确定性排序作为诊断消融，完整 Agent/router 流程作为真实基线。固定候选快照、优先级组、profile、目标基准、历史截止点、独立效用标准、预算和保留任务族。总成本计入证据准备、ranker 调用、延迟、执行/验证、失败探针和人工修正；单次调用更便宜但整个流程更慢，不能算节省。

离线 replay 可以验证覆盖、约束保留、排名稳定性和与独立偏好判断的一致性，无法证明未执行备选的结果。真实效用结论需要获准的匹配隔离运行或前瞻对照研究，保持相同评价器与预算。避免结果泄漏、重复任务污染和选择偏差；未观察的备选保持未知。在看到提供方结果前固定数值化采用/停止门槛，报告不确定性，不能事后挑选获胜指标。

覆盖同优先级并列、高价值但 blocked 的项、低成本低影响项、收益延后的前置、不确定但上限高的工作、负面实验、相关分支、冷启动、基础设施失败、过期/部分排序、误导自述和反复饥饿。测量有效结果/价值；只有备选实际被评价时才计算决策后悔值，top-k 一致率和排名相关性只作为诊断。若补齐上下文后收益消失、现有模型以更低总成本达到同等结果，或决策质量/公平性下降，则重排或停止提案。本次文档修订不认证任何提供方。

## 5. 拟议的有界比较

### 5.1 实验前的一份决策说明

复用被选 issue/PR 的决策字段，不新建 registry。记录操作者与当前困难、现有判断者、一个有限问题、调用时点、证据窗口、主要假设、独立评价者、获准数据/目的地、预算及停止条件。无法明确时保留为待决。固定证据研究不以新增产品 CLI、profile 迁移或持久化 attempt store 为前提。

一个可能的 D1 研究是在具名检查点，由操作者主动复核一段已完成工作。这个时点是否足够早、能否帮助用户，都需要测量；它不是逐 Turn 常驻监督器。仅使用当时已经可得的证据，不能引入最终结果的事后信息。owner 仍需选择或拒绝此设定。

### 5.2 证据与问题设计

绑定批准的 Goal/acceptance 版本、可归属工作身份、宿主读取的产物或 diff、验证读回，以及比较所需的历史证据。记录缺失、冲突和省略材料。原文读取证明来源，不证明语义结论正确。缺少目标权威时停止评估，不能从文件名或自述猜意图。

D1 分别研究目标关系与证据增量。保留必要前置、合理阻塞等待和证据不足，不能硬塞成漂移。它们不必组成一个互斥枚举：等待描述工作状态，对齐描述与目标的关系。缺少此前证据时，增量判断必须为未知。无关的新工作可以有增量，同时偏离目标。

主要比较采用基于产物的输入。作者声明分离保存，在相同产物上增加无自述/中性/自夸/自贬的消融比较。观察分类和概率变化，不能断言标记为不可信就消除了影响，也不能断言删除全部解释总是最好。解释前置必要性的上下文应有可归属支持；即使删除作者摘要，源码内容仍是不可信输入。

### 5.3 提供方事实与延后机制

[TypeSafe API](https://docs.typesafe.ai/api) 接受 state、按 key 组织的类型化问题及请求模型，返回同 key 答案和实际模型。[Confidence](https://docs.typesafe.ai/confidence) 来自 Choice/Score 概率分布；Noul 没有独立 confidence 字段。原始概率不能修复有偏证据，两种数值都不等于实测工程正确率或权限。保留提供方特有语义，不为其他模型伪造等价 confidence。

实验须固定请求模型、记录实际模型和问题版本，并披露不匹配。官方接口/模型文档不等于 live 资格、数据留存协议或中英文任务的实测价值。已公开的[模型限制](https://docs.typesafe.ai/model-jaggedness/jev-1.13) 支持针对间接关系、无关上下文和对抗内容设计测试。

包位置、最终 CLI/API、profile 版本、持久化、请求生命周期与计费机制，等获选 caller 证明需要后再定。现有严格 profile v0 不能直接接受虚构字段；后续配置决定必须保留限制及旧 reader 行为。本 RFC 不选择替代 schema。

## 6. 替代方案与采用逻辑

| 组别 | 做法 | 回答的问题 |
| --- | --- | --- |
| **A：现有完整流程** | 实际 Agent、已启用 reviewer、工具和确定性检查 | 当前质量、时机与完整投入如何？ |
| **B：有限评估＋现有获准模型** | 固定证据范围、有限问题、只读职责 | 改善证据/评估组织本身是否有价值？ |
| **C：相同评估＋Jev** | 与 B 相同的证据范围、语义问题和独立标准 | 提供方是否带来额外收益？ |

固定快照比较控制 B/C 的证据和问题含义，不要求 API 字节相同。完整流程比较保留 A 正常调查、运行检查的能力。记录提示、工具、证据准备、人工注意力和调用次数差异；A/B/C 本身不是因果归因的保证。

执行 Agent 可能受益于更完整的历史、工具和任务上下文；独立评估可能提供另一个视角，也可能丢失上下文或重复同样的错误。角色或模型名称都不能证明这些优势。这里“独立”指单独的评估职责，不代表错误在统计上独立，也不代表更加智能。

| 问题形态 | 候选分工 | 改变流程前需要的证据 |
| --- | --- | --- |
| 需要调查、隐含依赖或还原意图 | 保留现有 Agent/reviewer 及其工具的调查职责 | 有限评估器是否遗漏关键上下文，或误判有用的前置工作？ |
| 能表述为针对可归属产物和明确标准的有限问题 | 将现有模型评估（B）与 Jev（C）作为可选第二意见比较 | 同一标准下错误/覆盖或总成本更好，且不损害完整流程（A） |
| 证据缺失或矛盾 | 由原 owner 获取证据，或保留未知 | 增加模型投票不能补齐事实；记录哪些证据能够消除不确定性 |
| 涉及权限、验收、计划执行或结算 | 保留已有获授权的决定者 | 模型分数或意见一致不产生权限 |

B/C 使用同一快照，并报告相对 A 省略的上下文；另外测量 A 保有正常上下文和调查能力时的表现，不为适配有限 API 而削弱 Agent。比较判断质量、误报/漏报、弃权与覆盖、上下文需求、耗时和完整成本，不能只凭 confidence 判定优劣。若补齐上下文或整理证据后优势消失，应归因于这些改动，而不是 Jev。

初期测量补充观察，不改变控制决定。用 Jev 替代一个有界模型子任务，以及分流/重排，是后续不同方案。分流必须抽查未提示案例以估计漏报，不能跳过必需评审。若保留全部旧评审又加入 Jev，除非证明额外收益，否则只是增加成本。

- B 优于 A，而 C 相对 B 没有值得承担成本的收益：保留流程改进与现有模型。
- C 优于 B，但整体方案在预先定义的目标/约束上仍差于 A：不能仅凭局部优势采用。
- C 在误判、隐私、延迟、成本和维护限制内有增量：再提具名产品试点；价值本身不授予动作权限。
- 证据不足、数据不能获准或原流程已经满足需要：延期或停止。不改动也是实际选项。

## 7. 安全、隐私与降级

以下约束适用于后续获准实验或接入，不是已交付行为声明。保留现有默认关闭和零出站采集边界。私有进程使用 BYOK 仍会向远端服务发送所选数据；读取权限不是上传权限。最小化输入，限定目的地/受众/留存，脱敏密钥，不将原始轨迹和私有证据放进公开材料。哈希不等于匿名化。

| 情形 | 必须保留的边界 |
| --- | --- |
| 关闭、缺 key、出站未获准或预算耗尽 | 不新增发送；原流程及其 hold 保留，显式请求的评估显示未评估 |
| 目标、身份错误/缺失，或必要证据不足 | 不虚构事实；按实际情况标记基准不可用或证据不足 |
| 超时、限流、无效/缺失答案或服务失败 | 失败可见且有界，不自动重试、静默换提供方或给正常判断 |
| 不确定或弃权 | 区分完成但未采用的建议与传输失败，不解释为无漂移 |
| 目标/证据版本改变或响应迟到 | 不能作为当前判断；留存政策允许时保留历史来源 |
| 模型乐观，但已有拒绝 | 身份、权限、验收、评审和结算义务继续生效 |

模型没有工具或权限去追随引用、安装技能、执行命令。排序失败必须保留必读覆盖和 D4 候选身份；D5 建议不授权启用，D6 比较不授权提交计划。可逆干预也可能成本很高，需要单独批准的动作契约。

### 9.2 范围批准后的实验质量
