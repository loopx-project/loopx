## 1. 决策摘要

1. **一个 Goal，一张组合页面。** 常驻页头（面包屑、标题、团队行、停止/恢复、设置）
   和关键指标条位于每个 Goal 视图之上：概览、任务、对话、文件。概览成为组合简报：
   方向 → 等你决定 → 当前工作 → 成果，其后保留既有交付区；宽屏右侧配「全部工作」侧栏。
2. **每个数字只有一种含义。** 每项指标绑定一个既有类型化 owner，并声明窗口、范围、
   覆盖度和未知时的表现（第 5.3 节）。在 owner 产出之前不显示任何“累计”数字。
   完成、已验收与已采用保持区分。
3. **一个 reducer 产出所有计数。** 在既有展示边界中新增纯 TypeScript reducer
   `goal_workspace_digest_v0`，基于已投影事实组合指标、按负责人分组、侧栏顺序和
   “自上次查看”变化。同一快照下，指标条、侧栏筛选、当前工作分组和任务看板一致。
4. **就地决定。** 停止/恢复、Gate 决定、新建任务，以及在其 owner 允许 App 路径后的
   验收目标声明，都复用既有类型化动作：预览、一次确认、回读已记录结果。
5. **有表现力，不做表演。** 只有观察到活跃 Turn 或 worker 时才显示实时样式；动效只在
   观察到变化时出现一次；深色主题是同一套 token 的反色；命令面板只启动已投影的动作。

**不变：** Todo、Gate、quota、生命周期、验收与用量的权限；任务看板、W1 地图、对话、
文件和 Stage 4 交付区保持各自合同，成为本页面的镜头或去处。**默认边界：** 概览组合
属于默认 UI 变化；M1 遵循仓库首屏证据规则，将具体首屏放入 PR description，
获准方向内的普通细化不再增加一轮确认。**本文不批准：** 新 Todo 字段
（包括显示编号）、累计用量聚合、在浏览器中编写可执行验收检查、飞书或 CLI 对等呈现，
以及任何团队实时 L1/L2 或 G1 声明。

## 2. 问题与动机

owner 隔了几个小时回到一个 Goal（[GQ09](../../product/use-cases/steward/golden-queries.md)：
“接着昨天的做，有要我决定的再说。”）。他们想一眼得到五个答案：现在是否真的有工作在跑、
什么在等我、进展到哪、花了多少、交回了什么。现状是事实都在，但分散：选中 Goal 常常
先进入对话；“等你决定”和 24 小时用量在概览，分栏在任务页，停止在侧边栏行上，产出在
文件页，工作地图在交付区里。各区域窗口与措辞不同，也没有地方说明“自你上次查看以来
变了什么”。

常见的目标详情页用指标条、简报、当前任务和全部任务侧栏回答这些问题。若照搬，会产生
误导：墙钟“运行时长”暗示闲置时段也在工作；`#47` 暗示原生 Todo 刻意没有的稳定身份；
“54 已完成”会被读成已验收；由存储状态推出的转圈图标暗示了无人观察到的活动。LoopX
需要这种页面的易读性，同时遵守自身的诚实规则。

现有 owner 无法局部解决：用量 RFC 拥有成本字段，团队实时工作区拥有 W 分线与团队场景，
智能展示拥有条目披露与交付区，任务页拥有分栏。没有人把页面当作一个整体负责，于是计数、
窗口和选中状态在区域之间漂移。

### 不变量

- 组合只读。写入只经由既有类型化动作及其预览、确认、指纹与回读。
- 同一类型化分类驱动所有计数、筛选、进度条分段、分组与侧栏分区；计数不从文本推断。
  同一快照下各区域一致。
- 活跃来自观察。存储状态、注册、claim 或最近一次状态写入都不是活动；过期观察显示其时长。
- 未知不是零。覆盖不完整要可见。每个指标说明窗口与范围。
- 完成、已验收、已采用是不同事实；Todo 耗尽不等于 Goal 完成。
- 按负责人分组；无法解析负责人的工作放入明确分组，绝不丢弃。
- 显示位置绝不是标识符。
- 打开、刷新、切换镜头、打开命令面板或回放，都不会启动工作、消耗 quota 或调用校验器。
- 某个来源失败只让其所在区域不可用并说明原因；页面其余部分照常呈现。

## 3. 范围与非目标

### 范围内

- 打包前端中单个 Goal 的页面结构与响应式布局。
- 各项指标及“自上次查看”变化的规范语义。
- 当前工作镜头：按负责人分组、排序与行语法。
- 全部工作侧栏：分区、筛选、排序与覆盖度披露。
- 停止/恢复、Gate 决定、新建任务与目标声明的位置和回读，全部经由既有 owner。
- 当前工作、看板、地图、侧栏与详情抽屉共享一个选中模型。
- 快捷键、命令面板、状态图形、动效语法与深色反色主题。
- 在打包前端配合真实后端验证上述内容。

### 非目标

- 新的 Todo、Gate、验收或用量字段与存储；第 12 节把此类需求交给对应 owner。
- 调度、唤醒、quota 或节奏变化。
- 替换任务看板、W1 地图、对话或文件。
- 团队实时空间工作室及其 L1–L3 旅程，仍属于[团队实时工作区](live-team-workspace-v0.zh-CN.md)，
  可从本页面进入。
- 飞书 Goal Channel、管家首页、公开网站或 README 首屏。
- benchmark study 看板。

## 5. 架构方案

### 5.1 归属与落位

扩展 `apps/presentation/dashboard` 中既有个人工作区展示，以及
`loopx/control_plane/presentation/` 中已承载类型化动作审阅计划的 TypeScript 展示边界。
**落位理由：** 不新增 capability、extension 或 provider；页面只呈现既有内置 owner。智能
展示拥有条目披露与交付区，团队实时工作区拥有团队场景，两者都不拥有跨区域页面语义，
因此本文只拥有组合。

| 区域 | 数据 owner（不变） | 动作 owner（不变） |
| --- | --- | --- |
| 页头 | Goal registry 与生命周期激活状态 | `goal_lifecycle` 类型化动作 |
| 指标 | Todo 投影、attention 队列、`usage_summary`、执行观察 | 无；每格聚焦到对应区域 |
| 方向 | 已记录 Goal 文档目标；独立的验收合同与进展观测（第 12 节 D6） | 验收 owner 配置检查，不改写已记录 Goal 目标（M3，第 12 节 D3） |
| 等你决定 | attention 与 Gate owner；动作审阅计划 | 既有 Gate 决定动作 |
| 当前工作、侧栏 | Todo 投影、执行观察、运行时间线、`goal_task_map_v0` 关系 | Todo 新建 dry-run/apply；既有抽屉动作 |
| 成果 | 文件与 Goal-results owner；验收标记来自验收 owner | 既有打开/阅读动作 |
| 对话 | Chat 与会话 owner | 既有输入框 |

**禁止的替代：** 与类型化 owner 不一致的前端专属状态类；从文本解析计数；从审阅人名称或
产物哈希推断验收；从 `updated_at`、claim 或注册推断活动；在客户端把窗口相加得到累计值。

### 5.2 页面结构

![Goal 工作区组合研究（浅色）](assets/goal-workspace-surface-v0/goal-workspace-light.jpg)

*以 LoopX token 和公开 GQ01 示例渲染的合成组合研究。它不是运行证据，不是打包界面，也不是
已批准的首屏。*

| # | 区域 | 何时显示 | 值得占用注意力的理由 |
| --- | --- | --- | --- |
| 1 | **页头**：面包屑（工作区 / 目标 / Goal）、标题、团队行（Agent 名称或数量、仓库）、停止/恢复、设置 | 始终，在每个 Goal 视图；滚动时收紧 | 身份与唯一有后果的控制始终一眼可及 |
| 2 | **指标条**：最多六格，每格是聚焦对应区域的按钮 | 始终 | 一行回答在动吗/等我吗/到哪了/花多少 |
| 3 | **变化行**：“自你 09:12 查看以来：完成 2 项 · 新决定 1 项” | 仅有实质变化时；成本由其 owner 核验区间后才可加入 | 产品承诺的“回来看结果”时刻 |
| 4 | **方向**：已记录的 Goal 目标，独立且可选的验收标准与核验状态 | 始终；有合同时显示标准 | Goal 为了什么；已配置检查能证明什么 |
| 5 | **等你决定**：带建议、后果与动作的决定卡 | 仅非空时 | 决定才是 owner 真正的工作 |
| 6 | **当前工作**：镜头切换（按负责人 / 看板 / 地图）与新建任务 | 有未完成工作时 | 谁在做什么、谁被阻塞 |
| 7 | **成果**：已交回的产出，验收状态单独显示 | 至少一项成果时 | 交回了什么、是否可信 |
| 8 | **全部工作侧栏**：全部工作 / 动态两个页签、筛选、分区 | ≥1200px；更窄时为抽屉 | 不离开简报即可看完整清单 |
| 9 | 既有**交付与证据**区 | 与现状相同 | Stage 4 合同不变，位于成果之下 |

对话仍是直接去处。决定卡或行上的“讨论”会经既有输入框带着该对象打开 Goal 对话，
不建立第二个对话存储。

三张示意图仅显示工作与决定变化，省略自上次查看的新增成本；$18.40 仍只表示有覆盖度标记的 7 天总额。工作 5/10 排除单列的用户决定；两者不是同一计数范围。

### 5.3 指标语义

每项指标是一条类型化记录：`value`、`window`、`scope`、`basis`、
`coverage: complete | partial | unknown`、`availability: ok | loading | unavailable(reason)`。
下表为规范。

| 指标 | 来源 | 显示 | 未知 / 不完整 | 绝不 |
| --- | --- | --- | --- | --- |
| **状态** | 生命周期激活加既有活动展示器（基于 `goalExecution` 的 `presentGoalActivity`）；reducer 只补充“停止后收尾”这一事实 | 沿用展示器的状态与优先级：等你决定优先，同时观察到的执行在副行保持可见（“另有执行进行中”）；只有观察到活跃 Turn 或 worker 时“执行中”才带实时样式；否则为安静 / 已安排 / 已停止。副行说明依据，如观察宿主与时间 | 观察不可用：显示状态但无实时样式，并标“活动未知” | 根据状态、claim 或注册显示实时样式 |
| **工作** | 本 Goal 的 Todo 投影：未归档的 Agent 推进 Todo；完成数来自同一快照 | “完成 / 总数”，以及按类型化显示类分段的进度条（第 5.6 节） | 完成数不可用：只显示未完成数并标注 | 把用户决定或心愿计入工作；把完成显示为已验收 |
| **等你决定** | 本 Goal 的阻塞性 attention（用户 Gate、运行级操作员 Gate） | 数量与最久等待时长；大于零时用危险色加图标，零值弱化 | 读取失败：显示“不可用”，不是 0 | 非阻塞心愿 |
| **Agent 用时** | `usage_summary` 在最宽可用窗口内的时长（7 天，否则 24 小时） | “3h 12m · 7 天” | 缺失：“—”并标“未测量”；owner 标明采样缺口时：“不完整” | 墙钟 Goal 年龄；累计数字 |
| **成本** | 与 Agent 用时同窗口的 `usage_summary` `cost_usd` | “$18.40 · 7 天” | 缺失：“—”，绝不显示“$0.00”；实测为零显示“$0.00”；“不完整”只来自 owner 覆盖度信号 | 预算；未经 owner 标记的价格估算 |
| **最近活动** | 最近一次观察到的执行事实：被观察执行的最近活动、宿主线程事件、Turn 或运行事件 | 相对时间与执行者 | 无观察：“—”并标“暂无观测到的活动” | `updated_at`、Agent 分道的 `last_activity_at`（由 Todo 写入派生，生产方明确它只是提示而非活性）、claim、注册或配置写入 |

Agent 用时与成本始终共用一个窗口。owner 不提供覆盖度信号时，单元格说明窗口与来源，
不声称完整（第 12 节 D4）。当 Goal owner 投影了创建时间时，页头行可显示“10 月 9 日开始”
这样的 Goal 年龄，但绝不作为运行时长。

### 5.4 当前工作：负责人分组与行语法

**成员。** 当前工作显示正在运行（已观察）、已认领、等待依赖、阻塞或下一个可运行的
未完成工作。已完成与已延期工作在侧栏；决定位于“等你决定”，被决定卡住的工作在其分组中
加标记。

**分组。** 每个负责成员（claim 或 Agent 分道）一组，组头汇总该成员的观察状态；无法解析
负责人的工作放入明确的“未分配”组。组顺序：需要关注的组（阻塞、失败）在前，其次是观察到
在工作的，再次是等待中的，最后是空闲的。组内顺序：运行中、被决定卡住、下一个、等待、
阻塞。并列时依 `goal_task_map_v0` 依赖顺序，再依 `todo_id`。

**行。** `图形 · 标题 · 一行原因 · 类型化标记 · 时间`。

- 图形按形状区分并带文字标签，颜色是辅助信号。
- 原因行只写一个事实：当前运行步骤、“依赖：…”、可公开的阻塞原因或“延期至…”。
- 时间对运行中工作是自观察到 Turn 开始以来的耗时；对决定与阻塞工作，若 owner 记录了
  等待时长则显示该时长；否则显示“—”。

**镜头。** 看板即既有 `GoalTasksView`；地图即 W1 `GoalWorkMapView`。在任何位置（行、
看板卡片、地图节点、侧栏、命令面板）选中一个 Todo，都会打开既有详情抽屉，在其他区域
高亮同一 Todo，并把 `todo` 写入 URL，使刷新和后退能恢复。

**新建任务。** 行内输入框调用既有 Todo dry-run，显示预览，一次确认后 apply，并在所属
分组中回读新建行。apply 失败时保留草稿并显示 owner 的错误。

### 5.5 全部工作侧栏

- **按类型顺序分区：** 等你决定 → 未完成（运行中在前）→ 阻塞与延期 → 已完成（最新在前、
  虚拟滚动、由既有已完成历史 owner 分页）。
- **筛选标签**的计数来自与指标条相同的分类；搜索匹配标题。
- **动态页签：** 只列实质事件（完成、阻塞、决定已记录、成果交回、验收变化），来自运行
  历史与时间线；常规进展折叠。
- **不编号。** v0 不显示 `#n`：原生 Todo 刻意没有合成序号，位置计数会被读成身份。可复制
  的引用保留在抽屉的诊断披露中（第 12 节 D1）。
- **页脚**说明范围（“计数覆盖本 Goal”）、刷新时间，以及任何截断（节点上限、有界历史），
  按不完整覆盖处理。

### 5.6 共享 reducer：`goal_workspace_digest_v0`

位于 `loopx/control_plane/presentation/` 的纯函数，输入已解析的 Goal 快照事实：Todo、完成数、
attention 条目、用量、执行观察、生命周期激活、验收摘要、调用方提供的 `observed_at`，以及
可选的上一份摘要。输出指标（第 5.3 节）、类型化计数、有序的当前工作分组、有序的侧栏分区
和变化。不做 I/O，不读时钟。

**词汇。** 复用 Todo 状态（`open | done | blocked | deferred`）、attention 类型与既有展示
状态；新增一个 reducer 本地的封闭显示类集合：`running_observed`、`open`、
`waiting_dependency`、`blocked`、`deferred`、`done`，以及六个指标 id。`needs_you` 在 M2
投影出“决定—工作”关系后加入；M1 不推断某个决定阻挡了哪些工作。两组词汇在第二个
消费者（CLI 或飞书）采用该摘要之前保持本地；届时登记到语义词汇 registry，而不是复制。

### 5.7 自你上次查看

- 浏览器按（状态来源，Goal）在本地存储中保存上次查看的摘要：类型化计数、决定 id、有界
  的已完成 Todo id 集合与观察时间。不保存标题、内容或成本账本，不写服务端。
- 打开时，reducer 比较当前摘要与该标记：新完成、新决定、新阻塞与成果交回。当前用量
  投影不能证明自该标记以来的花费，因此变化行省略成本。
- 相同的滚动窗口标签不代表相同的覆盖区间。例如，旧 $100 移出 7 天窗口、新 $5 进入时，
  总额从 $100 变为 $5；差值 -$95 既不是新增的 $5 花费，也不是零花费。不得用滚动总额
  相减，或把该差值截为零，来报告自上次查看的花费。既有按范围和窗口展示的成本指标不变。
- 只有用量 owner 提供两次观察之间精确区间的花费，或来源、范围、币种、计数代际稳定且
  覆盖度与保留期可证明该区间有效的单调累计计数时，成本才可进入变化行（D7）。数据缺失、
  范围或覆盖度变化、owner 无法核验区间时，省略成本，保留其他已知变化。浏览器不另建用量
  authority；成本不可用绝不等于零。
- 只有实质变化才显示该行。owner 点击“标为已读”，或在该行显示后离开该 Goal 时，标记前移。
- 该行不是通知通道，也不触碰 attention 队列。

长程研究的拟议[进展阅读旅程](../../product/use-cases/auto-research/long-horizon-progress-design.zh-CN.md)
复用本页与共享选中，将原生结果/时间窗、一个研究片段/分支及带版本行内证据连起来。
已经打开的 Goal 无需设置；一次选择应显示变化、检查与后续采用，或准确缺口。
可选比较保留窗口/焦点，标明不匹配或不可用证据。摘要或 Todo 数变化不证明信息增益
或结果改善。沿用上文 since-last-look 与 usage 语义，不另建成本账本、进度百分比、
实时信号或可写图。这是设计扩展，不是已交付的 M1/M2 行为；仍须完成打包态来源/访问/
恢复与理解资格。

### 5.8 方向与可衡量目标

- 始终独立于验收显示 Goal 已记录的目标。状态将既有 Goal 文档的 `objective` 元数据经
  类型化工作区 digest 投影，复用公开安全过滤与 1,000 字符上限，不增加来源读取。
  内容缺失或不可读时明确未提供，不能用标题、Todo、进展句、Agent Vision 或验收合同
  补齐。当前进展另行折叠；启用的验收合同继续显示其自身覆盖范围内的目标与标准。
- 每条标准显示 owner 给出的状态：已核验（含时间）、未通过、尚未核验或等待工作。摘要写作
  “3 项中 1 项已核验”。观测的不完整性保持可见：没有缺口不等于已验收。
- **无合同：** 已观察到未配置时安静显示“验收标准未配置（可选）”；旧来源或读取不完整时
  说明标准尚未提供。配置复用既有 Goal 设置；这不否定 Goal 目标、不启用合同或新增门禁。
- **M3：** 声明经由验收 owner：目标、标准描述、覆盖范围（`selected_work` 或
  `all_advancement`）与绑定。流程为预览、一次确认、provider CAS 与回读，冲突时显示更新的
  修订。可执行检查仍留在 owner 本地文件中（第 12 节 D3）。

### 5.9 生命周期控制

- 停止/恢复位于每个 Goal 视图的页头，使用既有 `goal.stop` / `goal.resume` 动作与当前
  状态指纹。停止在原位确认；恢复打开 owner 既有的审阅预览，不再额外确认。两者执行后
  页面都停留在该 Goal。
- 确认框用平实语言写出 owner 的效果：“停止本 Goal 新的自动 Turn，并移出活跃关注。正在
  执行的工具调用会执行完。任务、历史、证据与配置都会保留。只有恢复能重新启动。”
- 执行后页面回读激活状态。仍观察到活跃 Turn 时，状态显示“正在停止 · Turn 收尾中”，
  之后显示“已停止”。过期指纹被拒绝并提示刷新，重复点击不会重复生效。远端来源沿用既有的
  精确 Host alias 规则。
- 该控制不同于团队实时工作区的“暂停动画”，也不同于团队面板中的协调员暂停（后者不停止
  worker）。

### 5.10 快捷键、命令面板、视觉语言与动效

**快捷键。** `j`/`k` 在当前列表内移动，`Enter` 打开抽屉，`Esc` 关闭并恢复焦点，先按 `g`
再按 `o`/`t`/`c`/`f` 切换视图，`1`/`2`/`3` 切换镜头，`/` 搜索侧栏，`?` 列出快捷键。每个
区域都可按 Tab 顺序到达，焦点可见。

**命令面板（⌘K / Ctrl-K）。** 可跳转到 Goal、Todo 与成果；也只能调用当前快照已投影的动作，
例如停止/恢复、打开设置、新建任务或决定 Gate，每项都打开其既有预览。命令面板是启动器而非
执行器，不接受发给 Agent 的自由文本指令；那是对话的职责。

**图形。** 完成是实心对勾；运行中是带圆心的弧线，仅在观察到时出现；未完成是圆环；等待是
虚线圆环；等你决定是实心感叹号；阻塞是带斜线的圆环；延期是时钟。形状在灰度下仍可区分。

**颜色。** 底色按设计系统保持单色。蓝色只用于观察到的活动，危险色用于等你决定，警示色
用于阻塞，绿色用于已核验的验收。

**动效。** 动效只在观察到变化时出现一次：快照显示状态转换时，行图形在 200ms 内变化；
新决定在 250ms 内进入；变化行淡入。实时标记是静态光晕；可选的慢速脉动只用于观察到的
活跃 Turn，并在隐藏标签页和减少动态效果偏好下停止。无变化的刷新不产生动效，回放标注为
历史。

**深色。** 作为工作区主题选项，是同一套 token 的反色，不是另一种视觉身份。

![同一组合的深色反色](assets/goal-workspace-surface-v0/goal-workspace-dark.jpg)

**响应式。**

- 1200px 及以上：侧边栏、一个内容框和侧栏。
- 768px 至 1199px：侧栏变为从页头切换的抽屉。
- 640px 及以下：单列，顺序为带图标停止的页头、3×2 指标、变化行、等你决定、当前工作；

### 5.11 研究 Goal：全历史 Explore 与按需深度分析

**产品细化提案；尚未实现，也未取得科学资格。** 研究视图默认回答完整已记录研究历史中
发生了什么，包括持续十几个小时的研究。选中的 episode 是全历史的细节，不是页面默认
只展示的单位。复用既有 Goal 工作区与 Explore 读取模型，不新增图 authority、科学评分、
调度器或 evaluator 实现。

**第一层——默认 Explore 历史图。** 打开研究 Goal 不需配置，也不增加模型调用。一张图
覆盖已记录时间跨度，按问题与竞争路线组织跨 Turn 的多轮尝试、显式分叉、继承、回退、
正负证据、后续决策和已观察的实际采用；同时保留原生结果曲线、测量时间和评分条件。
任务依赖、研究关系与结果归因保持各自语义；时间相邻不构成因果或采用关系。

初始适配完整已覆盖区间。语义分组与渐进展开可降低密度，但须保留失败、放弃、未完成
路线、后半程、旧锚点、等待和观测空档。明确请求区间、实际观测区间、尚未加载的分页与
保留期限制，不能把最近一页或摘要标为完整历史。缺少尝试时间或路线绑定就保持未知；
当前 reader 修复或回放不能改写历史原记录。选一路线/尝试一次，即在原位看到有权读取的
决定性证据、产物/输入版本、检查和下一决策。刷新、返回与回到全图应保留范围内的焦点，
或解释为什么它已失效。

只有 Explore 记录时，应标明范围是“已记录 Explore 历史”。`recorded_at` 是记录时间，
可包含延后分析和历史回填，不证明原生尝试发生时间或完整路线/采用覆盖。父子主题保持
分组语义，即使旧投影将其编码为 `supports` 和 `materialized_from=node_parent_id`，
也不构成科研支持证据。显式来源关系保留原依据，不能自动晋升为独立验证。

**第二层——按需调用 Agent 分析。** 这是 benchmark 研究 owner 的深入轨迹评测在产品
中的消费者，不在前端另造 judge。复用其分析方法与带版本的结果 sidecar，再对同一历史
生成解释图和结论。整条 run 与预先固定的共同比较窗口负责覆盖、原生结果和边际成本；
研究 owner 定义 episode 切分（含跨 Turn episode），并经同一快照的显式来源引用、
submission id 和产物摘要映射到原记录。展示分组不能自行成为评估单位。口径、校准与
科学结论仍由[长程研究计划](long-horizon-harness-benchmark-research-program-v0.zh-CN.md#63-长程控制质量)
和[研究评估 owner](research-exploration-control-plane-v0.zh-CN.md#15-评估与-claim-边界)负责。

**当前 producer，不是已完成的分析服务。** 现有
[`benchmark_behavior_finding_v0` / `benchmark_behavior_report_v0`](../../reference/benchmark-behavior-findings.md)
只提供有界的 `exploratory_behavior` 观察与解释，不是科学评分；toolkit 的
[`public_trajectory_summary_v0`](../../../loopx/capabilities/benchmark_toolkit/README.md)
是原生 Goal 生命周期的紧凑投影，首个适配器为 DeepSWE，不是完整研究图或质量评定。
既有实验 board 拥有原生 run、可比性与完整性，计数不能证明研究进展。可选的
[轨迹评测 producer](../../reference/trajectory-assessment.md)现负责版本化输入与结果
sidecar、来源绑定的固定包注册、执行、取消和历史回读。工作台经既有本机 Chat 传输
消费同一 owner，不另造统一科研评测服务，也不宣称已独立校准模型口径。

当前产品切片发现可信 host 为所选 owner Goal 注册的包，在一次显式分析请求之前用标题
说明实际 case 与 episode 窗口；匹配结果直接打开，不再次调用模型。owner Goal、被分析的
solver/run 和固定 episode 可能不是同一份历史，必须区分。未注册 case 明确不可用，尚未
实现整场 run 自动分段。普通用户不用准备 JSON 路径或选择可执行程序；注册属于 host/CLI
准备步骤，不是 renderer 操作，也不授予新的来源访问权。

结果分三层阅读：主要问题与原目标收益缺口；episode 的收益检验和证据采用解释；再按需
展开各项判断、引用原文、方法、覆盖与单独分析用量。有价值的前置诊断可能仍未检验原生
目标效用，不做全绿质量概览或综合分数。总体未知、未校准模型解释与历史适用性均明确保留。
关闭、重开和刷新保留 Goal 范围内所选包，不启动工作；已存的 running 回执不冒充当前模型活动。

数值读览提案复用同一个包选择，不打开或执行分析。toolkit 可选的完整 session 用量投影
提供捕获窗口、完整轮数、跨度与轮内时间、未缓存/缓存输入及输出。首层明确窗口与未包含
的研究成本；输入已含缓存，输出已含推理。捕获变化或缺失时保留历史值并明确提示，独立于
分析结果的适用性；没有该 producer 的包显示未测，不记零。原本关闭的分析面板在切换 case
时保持关闭；所选来源加载期间仍保留范围选择。

已有版本化分析计数属于独立的可选阅读层：逐项显示是/适用数、否和未知，不合成总分，
适用数为零不显示百分比。这些数值仅描述所选样本，不代表全运行比例或独立校准。原生
起点/保留最佳/最后有效值、达标时间与成本、增益面积和后期边际产出，在同一 owner 提供
可比且绑定来源的事实前保持未接入；不能由前端或模型正文补算。打包整合验收须区分这条
部分数值旅程、原生结果资格与实际安装采用。

产品与研究须先对齐已有生产/消费事实，再决定运行时 schema；下表是整合要求，既不是
新增协议，也不表示当前 producer 已提供全部内容：

| 共同基准 | 产品消费要求 |
| --- | --- |
| 来源快照 | 同一 Goal/来源、版本、完整请求窗口、观测覆盖、episode 到事件/产物的绑定与获准受众；保留未知和未分配工作 |
| 评测基准 | 输入摘要与覆盖、方法/代码版本、实际使用时才记录模型/配置、评测时间、资格、实际费用/覆盖度与可比控制条件；拟议或未校准判断明确标注 |
| 分析结果 | 一个可引用、带版本的 sidecar 与产物摘要，保留观察、解释、检查、采用、支持/反证、不确定性、弃答与分歧；生成图的结论回指它 |
| 有效性 | 输入/产物或方法变化后，旧结果仍按历史基准可读，当前适用性标为尚未建立；新结果不能静默覆盖旧结果 |

已有意图和范围内授权时，一次可选请求应足够：复用有效的匹配评测，或由既有获准的
Agent/执行 owner 准备并完成分析。不要求用户填写来源 id、选择 provider 或手工建图。
额外决定须对应真实缺失信息、权限或成本边界。打开、刷新、选择历史绝不启动分析；权限/
预算不可用、执行中、取消、失败和重试沿既有 action owner 呈现，失败仍可读第一层。
重复点击或导航不能重复执行。只有既有执行路径确实可用才提供执行入口，否则说明未接入。
分析不能借用冻结 solver 的预算、冷却或反馈机会。本文不创建该动作，也不授予模型或 run 预算。

查看生成解释时仍可回看事实图。观察、Agent 解释、独立检查与实际采用各自溯源。原生分数
持平、尝试多、一次 review、图边或漂亮解释都不能证明收益。分析不改原生评分，也不把
解释写回为已观察的 Explore 事实。工作台只接收受众获准的投影；受保护 evaluator 材料须
同时满足 solver 已终止与评分已完成，继续遵守原访问边界，且绝不进入 solver 上下文或
运行时反馈。本视图不授权干预冻结 benchmark。

## 6. 备选方案与设计取舍

| 备选 | 决定 | 理由 |
| --- | --- | --- |
| 照搬参考页面（平铺列表、`#n`、累计运行时长） | 否决 | 违反身份、活跃与未知不是零的不变量 |
| 在工作区页签之外另建 Goal 页面路由 | 否决 | 重复导航；概览已是直达 Goal 的去处 |
| 由 Python 提供页面投影 | 否决 | TypeScript 展示边界是既定 owner；禁止 Python 决策镜像 |
| 所有概览均以 W1 任务地图为主视觉 | 推迟 | 普通工作保留负责人镜头；研究 Goal 使用第 5.11 节全历史 Explore 组合，不将任务依赖变成研究证据；首屏 PR 证据仍适用 |
| 指标只放在概览 | 否决 | 在对话或任务页工作的 owner 会失去停止与等你决定的上下文 |

## 7. 安全、隐私与兼容
