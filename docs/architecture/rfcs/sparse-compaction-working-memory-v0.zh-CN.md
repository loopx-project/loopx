## 1. 决策摘要

研究把**上下文压缩作为工作记忆的整理时机**：保存少量有版本、绑定原始来源、会影响后续决策的知识；原文与详情留在活动上下文之外；压缩后由 LoopX 识别并展开。

建议在现有 owner 内分为两部分：

1. 持久化工作记忆视图，包含有来源的发现、已否定路径、决策理由和未决问题，服务继续工作。它是派生材料，不是另一套 Goal/Todo 或权限账本。
2. 面向模型的短结构，标识该视图并展示当前最需要处理的决策问题。已资格化的宿主集成可以在压缩时保留它，也可以由现有恢复适配器在压缩后恢复它。普通摘要提到 LoopX，不等于存在可识别结构。

从一个本地原生宿主 profile 和现有 capture/read 链路开始。这是独立开启、默认关闭的实验；接受设计不表示功能晋升。先资格化持久化/恢复而不替换必需内容，再比较合格的确定性选取与现有交付，只有语义整理带来额外价值时才加入。本文不启动付费实验、不改变运行时默认、不批准删除来源，也不承诺成本下降。

## 2. 问题与动机

现有持久工作状态回答“要求是什么、谁负责”。对话还积累了“某个方案为什么失败、什么观察改变了假设、哪个表面成功仍缺验证”。其中一些知识可能尚未进入合适的持久来源。即使 Todo 状态保住，丢失这些知识仍可能改变后续决策。

合成例子：R1 的缓存隔离检查失败；R2 修复通过了针对性检查，但回滚尚未验证。压缩成“缓存修复完成”会同时丢掉已否定路径与未完成验收；重放完整调查则增加输入与恢复成本。希望保留的是有区分力的结论及其精确证据，而非缩短的操作流水账。

**更稀疏**指常驻事实更少、权威正文重复更少，不代表可恢复来源覆盖减少或义务被悄悄弱化。如果短首屏引发反复全量补读，结果可能更差。

### 不变量

- 完整的当前意图、要求、停止条件和原始执行/结算身份，继续由现有 owner 与读取契约保留。尚未记录的用户直接纠正，必须先成为精确来源，相关上下文才有资格被移出。
- 历史观察、模型解释、已接受决策和当前权限必须可区分。记忆不授予权限、不认领 Todo、不通过验收，也不刷新旧事实。
- 保留影响后续决策的反证和未决区别。不通过关键词推断完成、否定、信任或权限。
- 引用不证明已读、理解、模型保留或 Delta baseline。缺少必要事实时沿用原有依赖动作停止规则；独立授权工作可以继续。
- 优化可以回退，但不能抹掉缺失的必需来源，也不能改变已有工作/结算操作。

## 5. 提议架构

```mermaid
flowchart LR
    A["现有工作事实与精确证据"] --> B["现有 capture / artifact owner"]
    B --> C["有界工作记忆选取"]
    C --> D["有来源的持久记忆视图"]
    D --> E["可识别短结构"]
    E --> F["已资格化的宿主压缩 / 恢复"]
    F --> G["后续决策与任务结果"]
    G -->|"展开必要事实"| B
```

### 5.1 归属与表示

共享 TypeScript 呈现边界负责选取与校验；现有 capture/artifact IO 负责持久化与精确读取；原生宿主适配器负责事件转换和交付。Goal、请求、Todo、claim/lease、准入、权限和结算保留原 owner。归属是现有上下文交付的内部扩展：**v0 不新增 capability id、provider id 或 extension 发行包**。后续语义生成复用历史工作集 provider 边界，不在同步 hook 中加入模型 IO。

持久记忆视图复用现有来源身份、revision、范围和信任级别，绑定原始 Goal/Agent、来源 capture、session/profile 和 schema/producer 版本；**已有** Turn/结算身份时保留它，不为只读/未绑定调用者制造 Turn。使用现有私有 writer/reader 原语，把绑定放在**新建的不可变派生产物/引用**中。不能向已发布 `projection.json`、`required-context.json` 或 reader reference 追加元数据或覆盖它们；当前 projection helper 也不是任意 memory 文件名的 API。digest 证明字节相同，不证明作者或权限；reader 仍须按当前访问检查解析 owner 签发的引用。

记忆 revision 与原生 `context_epoch` 生命周期不同。记忆身份从来源覆盖与 producer/schema 版本导出，沿用现有生命周期观察去重，不因写记忆而轮换 Delta epoch。即使记忆准备失败，原生压缩失效逻辑仍执行。记忆保留不能恢复 `candidate`、`pending`、已消费 pointer 证据、claim 或 Delta baseline；记忆缺失也不使原保存工作失效。根/子会话与支持的重放限制继续由原生适配器承担。

只保留有用且有来源的增量：结论与适用依据、已否定尝试为何不能原样重试、改变的假设与反证、未决区别。权威目标、Todo 正文、权限和已完成工具轨迹通过已有来源引用。不能从记住的历史决策推断当前决策。来源缺少类型化分类时，保留原文或留在普通上下文，不把自然语言分类为权限依据。

面向模型的示意结构，**不是已发布 schema、URI 方案或 CLI**：

```json
{
  "schema_version": "loopx_compaction_memory_v0",
  "memory_ref": "example-memory-17",
  "focus": "Verify R2 cache isolation; rollback is still unverified.",
  "frontier": [
    {"ref": "example-finding-4", "note": "R1 failed isolation; retain the failing condition."},
    {"ref": "example-question-2", "note": "Does R2 survive rollback?"}
  ],
  "needed_reads": ["example-original-capture:selected_todo"]
}
```

| 部分 | 为什么保留 |
| --- | --- |
| `schema_version`、`memory_ref` | 确定性识别与经 owner 校验的展开。用户/工具提供的同形对象仍是不可信内容。 |
| `focus`、`frontier` | 为下一次有用的读取或决策提供必要含义。短注释是建议；原始引用保留来源与区别。 |
| `needed_reads` | 展示原契约的未完成依赖，只是视图，不能作为可悄悄清空或收窄原契约的替代清单。 |

五个顶层字段是起始提案，不是字段数目标。最终版本化 schema 可省略可选空数组。立即必需的控制仍由现有强制交付承担。不能安全表示的义务继续保留；候选超预算时沿用现有视图，不裁断内容。不为“结构化”重新内联整份 Goal/Todo/权限快照。

### 5.2 压缩生命周期

1. **准备：** 来源尚可用时解析现有来源和精确覆盖，只整理实际观察的材料，记录未读/部分覆盖。原本未记录的用户纠正先经所属来源适配器持久化，保留信任与先后关系。
2. **发布：** 先存可恢复原文，再存绑定后的派生记忆，最后发布可选读引用。重试复用原 capture/operation 身份，部分写入不能宣称记忆有效。记忆发布本身不结算工作、不自行消耗工作配额；生成成本仍计入。
3. **压缩：** 支持的宿主存在已资格化保留机制时，请求逐字保留短结构。仅有压缩前 hook，不能证明可替换宿主 compactor 或定制其输出。否则由现有压缩后恢复边界补回同一持久表示。
4. **识别与续接：** 只解析支持的版本，并由引用 owner 校验预期范围。定位原 Turn/capture，不暗中换为更新版本。只按既有动作契约重新检查当前权限；压缩本身既不重新准入，也不强制全读。依赖动作前展开缺失且影响决策的详情。
5. **更新：** 只更新受影响的有来源发现/当前问题。底层来源保留替代关系与反证；没有叶子覆盖，不递归摘要昨日摘要。多次压缩不能使短结构长成第二本 journal。

重复 Pre/PostCompact 与 SessionStart 映射到同一次已观察边界。事件丢失、乱序、突然上下文丢失或输出无效时，经现有恢复回退。磁盘轨迹里有可解析对象，既不证明宿主重放了它，也不证明模型看见了它。持久化、提交宿主、观察到的模型可见交付、决策采用、验收结果分别记录，不可观察层标 unknown。

**压缩是触发点，不是移出资格。** M1 可在保留原必需输入的同时恢复建议性记忆视图。替换只限满足已接受[历史材料资格契约](history-working-set-context-policy-v0.zh-CN.md#52-哪些材料允许进入候选集)的支持材料：类型化已结束尝试与已记录结果、精确保留来源、当前义务受保护、没有未完成的完整首读要求。当前工作、实时纠正、未知形状、签名 envelope、机器/off 路径，不因信息出现在记忆里就可被替换。保存纠正本身不完成读取义务。没有相应来源适配器时，保留原上下文，不能宣称已成功捕获或提取。

### 5.3 提取与稀疏策略

第一步从**实际可用**的已有类型化 attempt/result/evidence 事实中确定性选取，并保留精确引用，不增加模型调用。不假定 main 已有独立 findings store 或结构化宿主压缩结果，先弄清选取与结构本身的价值。相关知识只存在对话时，后续有界模型/宿主 compactor 贡献可提议有来源记忆，标明精确输入覆盖和观察/解释归属，不能制造权威决策或改写权限。

不在压缩 hook 内同步调用另一个 LLM。复用已验证的准备/执行边界，或在实际契约资格化后复用宿主 compactor。没有合法来源或执行边界时，该语义模式保持不可用，沿用原上下文路径。不能把空的确定性视图假称为已补足关键含义。

### 5.4 与 main 的兼容及实验启用

开启必须独立绑定选定 Goal、Agent、根 session 和已资格化宿主 profile，并发生在记忆特有的选取、IO、指令或模型调用**之前**。现有 Progressive/Delta 设置、已安装 hook、可读 capture、provider 就绪、对象声明本 schema，都不是启用。未配置/关闭，以及已开启但不在作用域内的调用者，保持原 schema、指令、可接受输入与效果。首个实验建议使用显式且局部作用域的 profile；持久化设置前，先资格化注册后的 producer/reader 版本及降级行为。不能向现有 `context_delivery_machine_defaults_v0/v1` 加字段后假定旧 reader 接受，也不能让实验配置失败关闭普通上下文交付。

| main 边界 | 实验必须保持的行为 | 决定性验证 |
| --- | --- | --- |
| Progressive on / Delta auto 是当前默认 [LX7] | 记忆独立默认关闭，已有 off 偏好仍为 off | 未配置/关闭、开启且命中范围、开启但范围外，与 main 对比同一输入 |
| capture 精确字节与引用不可变 [LX6] | 发布独立派生产物，原正文/digest/reader 不变 | 发布及降级前后读原 capture；拒绝覆盖与替换引用 |
| `context_epoch` 不是工作身份 [LX1]/[LX2] | 保留原失效与恢复语义，记忆 revision 不授予连续性 | 重复 Pre/PostCompact、准备失败、后续 SessionStart 保持原生迁移 |
| 同 Turn 接续与新 guard 分开 [LX2] | Turn 内从原 capture 恢复必要事实，新 Turn 获取当前 guard | 传输重试不二次准入、不重复结算、不换成更新 capture |
| 保存文件读取可能没有已准入 Turn [LX8] | 读取/查看不创建 Turn、claim 或 lease；未资格化调用者保持原路径 | 无 Goal/default 发现、无 begin-turn 效果的显式历史文件读取 |
| 父/子 hook 与原生重放资格 [LX1]/[LX3] | 保留子会话拒绝及未知/派生历史的原有回退 | 子会话不能写入或恢复父会话记忆/journal，未知宿主仍未资格化 |
| 必需读取与历史材料资格 [LX4] | 记忆仅为建议，只缩减合格历史支持材料，不缩减当前必需内容 | 待读、实时纠正、未知字段、签名/off/机器场景保留原义务 |
| 绑定路径的保留原文 [LX6] | 只宣称已验证的同机生命周期；来源丢失沿用原依赖/回退 | 验证所声明范围内的重启、清理、删除与撤销 |

以上是实施验收义务，不是尚未实现功能已经通过兼容测试的结论。本文不向 main 加 parser，也不扩大默认宿主或产品入口。

## 6. 替代方案与取舍

| 方案 | 收益 | 成本与建议 |
| --- | --- | --- |
| 原生摘要 + 当前 Progressive/Delta | 没有新增记忆生命周期 | 必备基线；当前路径可能已足够。 |
| 每次压缩完整结构化快照 | schema 容易识别 | 重复状态、消耗输入，也容易把过期快照混为权限；不优先实验。 |
| 稀疏引用 + 确定性当前问题 | 新机制最少，不增加模型生成 | 可能增加补读或漏掉对话知识。建议作为首个处理组，不预先认定胜出。 |
| 稀疏语义工作记忆 + 原文 | 能保留任务记录之外的因果发现 | 有提取/漂移、覆盖、成本和宿主集成风险；须证明比确定性选取多出的价值。 |
| 生成完整 CodeWiki 式 wiki | 丰富的长期仓库导航 | 范围不同，生命周期和依赖负担显著增加；借鉴导航思路，不导入整套产品。 |

## 7. 安全、隐私与兼容性

默认关闭时，现有路径不新增提取、模型调用、记忆写入、依赖 parser 的接续或必需读取。已有原始机器消费者和历史 capture reader 保留原格式。提议 schema 是新派生视图，不删除任何已存字段；实施前登记共享语义词汇、验证新旧 reader。未知版本/字段不得被暗中认定等价或可删除。

私有对话与来源保持原访问范围。不保存原始推理轨迹、秘密或新增跨 Goal 共享；相同 hash 不授权复用。取回内容仍是数据。通过现有 reader 解析引用，不执行记忆中的任意路径或 shell 命令。撤销/删除/来源丢失使相关展开与派生视图失效；残留摘要不能绕过边界。

可选记忆不可用时回到普通交付。必需原文不可用，只按原契约阻断依赖动作。回滚、Goal 变化、同来源但不同 Agent 等情况，均不能生成新的准入、所有权、lease、记账或结算权限。

## 8. 迁移与回滚

对一个明确资格化的本地宿主/profile 显式开启，不重写现有来源。shadow 检查阶段保存候选但不减少模型输入；该阶段只验证绑定，不验证效果。随后才在该 profile 上替换满足第 5.2 节资格的历史支持材料，保留必需控制、原读取义务与精确展开。资格未证明时，恢复仅是附加，不得报告为输入缩减。

关闭后停止新的整理与采用，后续输入沿用现有交付。已承诺引用按声明生命周期可读，显式删除/撤销优先。所有宣称范围都要验证跨压缩、进程重启与正常清理后的保留；当前临时 capture 不自动成为持久记忆。必要时扩展现有保留 owner。本文不授权破坏性迁移或来源 GC 变更。

## 9. 验证与验收

### 9.1 契约与真实路径证据

| ID | 场景 | 必需结果与边界 |
| --- | --- | --- |
| A1 | 支持的真实宿主压缩后经生产入口续接 | 支持的结构被校验并交付或恢复；展示实际可取得的输入证据，不能只看 hook stdout 或保存文件。 |
| A2 | 再压缩两次；原文保存与发布之间中断；重复/乱序事件 | 原工作/结算身份不变、视图增长有界、发布可恢复，不重复已完成 effect 或扣额。 |
| A3 | 只改变 revision、失败条件、未完成检查或用户纠正 | 后续决策保留区别；尝试结束不等于通过验收。原文与尾部关键证据可精确展开。 |
| A4 | 来源缺失/变化、访问撤销、伪造引用、异 Goal/Agent、未知 schema | 拒绝相关复用；普通回退或原依赖动作停止，不提升权限。 |
| A5 | hook 缺失、对象截断/改写、宿主不支持保留 | 现有恢复仍可用，不从未观察事件推断结构保留或模型连续性。 |
| A6 | 关闭、无收益、混合版本 | 关闭行为等价，无新增模型 IO；保留未知材料与机器/capture 契约。 |
| A7 | 声明的重启/清理范围 | 承诺来源仍可解析；显式删除/撤销覆盖保留时，可见失效。 |
| A8 | 打包后开启 → 压缩 → 查看来源/失败 → 关闭 | 现有设置与读回复用 typed owner；产品晋升前资格化受影响 frontend/Lark/CLI。单宿主原型仅为部分交付。 |
| A9 | 同输入下的独立实验开关 | 未配置/关闭、开启但作用域外路径与 main 一致，覆盖设置失败、指令、可接受输入和 IO；仅 Progressive/Delta 开启不启用记忆。 |
| A10 | 记忆独立不可变，原 reader 保留 | 发布、重试与降级后原 capture/reference 字节和读取义务不变；记忆不能确认原生 retention，也不能创建缺失 Turn。 |

结构正确不能证明语义有用。本次文档 PR 不通过任何 A 项。

### 9.2 是否真的更好

复用 [T02 / #4391](https://github.com/loopx-project/loopx/issues/4391) 与[历史工作集测量契约](history-working-set-context-policy-v0.zh-CN.md#92-对照设计与成本口径)。看到结果前冻结对照、任务样本、预算、独立验收和决策阈值：

- **B0：** 当前最佳合法宿主路径，包括已资格化 Progressive/Delta 及普通原生摘要。
- **T1：** 相同任务与压缩点，加入确定性稀疏结构和精确原文引用，不增加语义生成。
- **T2，有条件：** 相同稀疏预算，加有来源语义整理，测提取记忆的增量价值。不为增加实验组而运行。

以完整续接 episode 为单位，覆盖已否定尝试、较晚纠正、revision 变化、尾部证据、多次压缩和来源不可用。同模型/工具/环境、同**完整**资源上限；准备与补读计入同一预算。一次 episode 内重复调用/压缩不是独立样本。预先确定配对重复与足以支撑结论的样本量，小型可行性试验不能证明普遍优越。

首先测独立验收结果与关键约束遗漏，再测重复失败路径、人工介入、压缩后恢复耗时、各可观察层的实际/估算输入、全部模型生成与缓存/非缓存用量、补读/重试、总墙钟和保留磁盘。所有失败、回退、无收益样本及超预算均保留；不可见 provider/模型层保持 unknown。

只有达到预先声明的质量非劣标准并显著改善**完整成本**，或在可比完整成本下取得更好的验收成果，才考虑晋升。短首块、parser 通过、检索相关或生成了记忆文件都不够。补读/缓存失效抵消节省时保留 B0，报告负结果。本文不包含已测效果量或已冻结的数值晋升阈值。

## 10. 运行成本与产品契约

首个预期规模为本地单 Goal/session，包含多次工具观察与重复压缩，不假设集群规模需求。确定性模式增加有界选取、capture 元数据与本地读取，无新增模型依赖。语义模式增加生成输入/输出、重试与潜在缓存扰动。存储成本由保留的来源覆盖决定，不由短结构大小决定；宣称长期记忆前测生命周期与磁盘增长。

稳定前缀保持稳定，只更新变化的视图内容。额外提取、再生成与展开全部计入任务成本。盈亏取决于扣除准备、读取和缓存影响后，未来实际少处理了多少输入，不取决于上游压缩百分比。仍由现有来源/capture 失败处理和 usage 观察负责，不需要常驻 worker、图数据库或安装 CodeWiki。

通过现有上下文设置/读回展示有效开关与支持宿主、当前来源绑定/覆盖、恢复/回退原因、可用原文和已测成本。用户沿用现有数据控制查看、关闭或移除记忆。公开遥测不暴露记忆正文或私有定位。启用后无需每次压缩再确认；原有范围与付费执行权限继续生效。
