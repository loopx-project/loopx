# LoopX 2.2.0

## Release Decision

**Who should upgrade:** Canonical 2.x users of research history, managed conversations, scheduled reports or native/Windows hosts should upgrade for the changed reading and recovery paths. Operators with unsupported legacy authority must prepare migration first; a production owner may remain on its current version until that is complete.

**What this release solves:** Research evidence was difficult to trace across saved versions; complete reports and recovered requests could lose their original delivery context; races and stale fixtures obscured the actual work and its qualification. This release improves those concrete paths while retaining independent acceptance and effect readback.

**Breaking changes:** Yes for pre-canonical integrations: ordinary unmigrated authority-read fallbacks and retired protocol/legacy bridge formats are removed. Follow the existing explicit backup/migration/recovery contract before use. Existing canonical File/SQLite Goals retain their selected authority; an upgrade does not migrate data or add another writer. Unconfigured new Goals still create SQLite with hard leases. Differential context and Explore device mode remain off by default. Controller/executor-session RFCs are proposals, not shipped two-Agent orchestration.

**How to verify:** Expect loopx 2.2.0 and the correct installation owner/runtime. Open an existing Goal and verify one original result/source or the complete original report; registration, a saved setting and a completed Todo are not delivery proof.

**Contributors:** Release maintenance by @huangruiteng and @loopx-agent; concrete community contributions appear above and below, derived from the previous formal tag v2.1.1 and merged PR metadata.

```bash
loopx --version
```

## State Kernel & Control Plane

Canonical state, complete Todo reads and shared decision ownership stay with their typed owners. Read-only status follows the canonical source runtime; runtime aliases do not create a different authority. Goal creation can resume its original operation without erasing later writes. [#6874](https://github.com/loopx-project/loopx/pull/6874), [#7325](https://github.com/loopx-project/loopx/pull/7325), [#7462](https://github.com/loopx-project/loopx/pull/7462), [#7411](https://github.com/loopx-project/loopx/pull/7411), [#7298](https://github.com/loopx-project/loopx/pull/7298), [#7381](https://github.com/loopx-project/loopx/pull/7381), [#7496](https://github.com/loopx-project/loopx/pull/7496).

An ordinary CLI self-claim now prepares execution atomically when the explicit actor matches the assignee and no explicit lease proof is supplied. Follow the returned progress/completion commands: progress can renew that still-active original execution, while expiry, replacement, foreign ownership and unavailable proof refuse without acquiring a new grant. Explicit lease calls, other assignments, soft-claim policy, read-only guards and App manual completion retain their existing authority. [#7510](https://github.com/loopx-project/loopx/pull/7510).

Replan, outcome review, terminal refusal and original settlement retain their own identities. Required Host work does not grant ordinary delivery; no-write failures preserve their original source and journal. [#7484](https://github.com/loopx-project/loopx/pull/7484), [#7486](https://github.com/loopx-project/loopx/pull/7486), [#7452](https://github.com/loopx-project/loopx/pull/7452), [#7470](https://github.com/loopx-project/loopx/pull/7470).

## Capabilities & Workflows

The Research workspace now leads with results, saved reports and readable questions, then original history, measurements and citations. Search and comparison reuse saved display language while exports preserve original records. New analysis preparations persist the current faithful localized guidance; existing frozen methods, failures and usage remain unchanged. This ships an analysis producer and packaged reader; evaluator calibration and scientific treatment effects remain separate. Retained completed tasks and steward requests can be searched; displayed team report sources can be downloaded. Project peer requests preserve the original conversation and complete brief, without granting coordinator authority. ## Optional Capability Activation & Use

The commands below assume the stated source checkout or an installed 2.2.0 CLI. Set identifiers/directories to the existing authorized object; viewing a setting does not enable it.

### Research reports and original evidence

**Activation:** Open an existing Goal’s Research view. Ask its authorized Agent to register a fixed source pack, then explicitly generate the selected report. New default preparations use synthesis revision 2 and the current faithful localized display guidance; optional synthesis revisions 3/4 need a successor pack. Opening history, search, comparisons and citations is read-only.

**Validation:** Read the original source and revision beside the saved finding; inspect missing coverage, negative evidence, usage and the selected pack’s status. Saved translations can be searched and compared; exports retain original matching records.

**Disable / rollback:** Cancel by the original analysis directory. For subsequent work select the earlier pack/configuration or a legacy encoding/synthesis setting; retain original successes, failures and usage. An uncertain running operation needs original-result readback before retry.

**Authority boundary:** Sources must be authorized and hash-verified. Explicit generation can call the configured model and incur fees; a citation validates binding, not entailment, scientific validity or permission to run a proposed experiment. Existing frozen requests are not silently upgraded.

**Docs:** [Versioned contract](https://github.com/loopx-project/loopx/blob/v2.2.0/docs/reference/trajectory-assessment.md)

```bash
loopx dashboard
loopx benchmark trajectory-packs --goal-id "$GOAL_ID" --format json
loopx benchmark trajectory-assessment-status --directory "$ANALYSIS_DIR" --format json
# Explicit cancellation of that original operation:
loopx benchmark trajectory-assessment-cancel --directory "$ANALYSIS_DIR" --format json
```
### Local Codex source documents

**Activation:** Open a local managed Codex conversation, attach a UTF-8 `.md` or `.txt` source file, then submit the authorized request. Up to four attachments share the 64,000-byte serialized message budget; encoded document data counts toward it. This ships local input, queued recovery and original-source preview/download. [#7740](https://github.com/loopx-project/loopx/pull/7740).

**Validation:** In the original conversation, expand the attachment and download its source; compare the complete UTF-8 bytes. Check the original request/queue result after a busy-session wait or restart. Source delivery does not establish model comprehension or automatic adoption.

**Disable / rollback:** Remove an attachment from the draft before sending, or send plain text. Accepted source remains part of the original saved request; stop current work through its existing owner rather than replacing its journal. To roll back the application, follow the original installation owner after saving a backup.

**Authority boundary:** Only local managed Codex conversations accept text documents. Attached hosts, other executors and linked/Lark conversations reject before admission. Invalid UTF-8, NUL, type/name mismatch or excess size rejects the whole request without truncation. Attached source grants no new instruction, arbitrary-path access or external-send permission.

**Docs:** [Versioned source-document contract](https://github.com/loopx-project/loopx/blob/v2.2.0/docs/architecture/rfcs/app-conversation-and-async-inbox-v0.md#local-text-document-attachments)

```bash
loopx --version
loopx dashboard
```

### Original-request native delegation

**Activation:** In an operator-owned `loopx_local_delegation_v0` file outside member workspaces, omit `todo_id` for ordinary requests and declare `request_validation` with its command/argv, null alternative, label and timeout. Grant only the intended requester and source. Native execution requires a runtime-compatible project registry; lifecycle-only `source_session_v1` rejects before Host launch. Preview then set the Goal configuration pointer. Chat also needs its current Inbox grant and original saved request.

**Validation:** Inspect the exact binding, check original request and independent acceptance in Team execution, then read the original operation's verified result and original-session return. Registration, preview or a completed native process alone is insufficient.

**Disable / rollback:** Revoke the exact binding/source grant in the protected file. Clear the Goal pointer when removing discovery. Preserve in-flight original journals and uncertain effects; do not reinterpret or rerun them as a new request or Todo.

**Authority boundary:** A request, delivered message or reusable session grants no execution, repository-write or external-send authority. Stop, real user gates, quotas, current source policy, independent validation, single-flight and once-only settlement still apply. File/SQLite and packaged synthetic-transport checks do not qualify every model or external transport.

**Docs:** [Versioned ordinary Inbox and delegation contract](https://github.com/loopx-project/loopx/blob/v2.2.0/docs/reference/local-delegation.md#ordinary-inbox-activation-boundary)

```bash
loopx configure-goal --goal-id "$GOAL_ID" --subagent-execution-config "$DELEGATION_CONFIG"
loopx configure-goal --goal-id "$GOAL_ID" --subagent-execution-config "$DELEGATION_CONFIG" --execute
loopx delegation list --goal-id "$GOAL_ID" --agent-id "$AGENT_ID" --execution-config "$DELEGATION_CONFIG"
loopx delegation inspect --goal-id "$GOAL_ID" --agent-id "$AGENT_ID" --execution-config "$DELEGATION_CONFIG" --binding-id "$BINDING_ID"
loopx configure-goal --goal-id "$GOAL_ID" --clear-subagent-execution-config --execute
```

### Codex differential context

**Activation:** Default off. In Settings → This machine → Capabilities → Differential context → Codex, switch on through the existing exact-revision transaction. Supported native Codex App heartbeat, SSH Goal and explicit benchmark heartbeat consumers also require their exact native hook/configuration setup for the next supported session. A saved preference alone does not initialize a loaded thread. For a smaller tool-output budget, add --max-page-output-bytes 7900 to the generated guard or context-project command; follow its bounded continuation and recovery commands, and keep aggregate batch output within the host limit.

### 升级决策

**谁需要升级：**使用研究历程、受管会话、周期报告与原生／Windows 宿主的 canonical 2.x 用户。仍依赖旧 Markdown authority 的集成须先准备迁移，生产 owner 可在完成前保留当前版本。

**解决了什么：**原始证据难以跨版本追踪，完整报告与恢复请求可能丢失原投递上下文，竞态和过期 fixture 又掩盖真实工作状态。本版修复这些路径，验收与业务效果仍须独立读回。

**是否有破坏性变更：**有。移除未迁移普通 authority 读 fallback 与退休协议／legacy bridge。先按既有备份、显式迁移与恢复契约处理。已有 canonical File／SQLite Goal 保留原 authority，不自动迁移或新增 writer；未配置的新 Goal 仍默认 SQLite／hard lease。差分上下文和本机 Explore mode 默认关闭；controller／executor-session RFC 仍是提案。

**如何验证：**CLI 应显示 loopx 2.2.0，doctor 核对安装 owner／runtime；进入已有 Goal 对照一项原结果、原来源或完整原报告。保存配置、注册与 Todo 完成都不等于交付。

**贡献者：**发布维护为 @huangruiteng、@loopx-agent；社区归因来自 v2.1.1 到候选源码及实际 merged PR，详见下方。

### 可选能力启用与使用

#### Research reports and original evidence

**启用：** 进入已有 Goal 的「研究」，让已授权 Agent 准备固定来源 pack，再显式生成所选报告。新默认准备使用 synthesis 第2版与当前忠实本地化指导；第3／4版需显式接续 pack。打开历史、搜索、比较或引用只读。

**验证：** 对照保存的发现、原始来源与记录版本，核对负结果、缺失覆盖、用量和 pack 状态。搜索与比较复用已保存译文，导出保留匹配的原记录。

**停用 / 回退：** 按原 analysis 目录取消。后续可选回旧 pack／配置，或显式旧 encoding／synthesis；保留原成功、失败与用量。结果不明时先读回原操作再决定重试。

**权限边界：** 来源须有授权并通过完整 hash 校验。显式生成可调用模型和计费；引用绑定不证明内容蕴含、科学有效性，也不授权实验。旧冻结请求不会自动升级。

**文档：** [Versioned contract](https://github.com/loopx-project/loopx/blob/v2.2.0/docs/reference/trajectory-assessment.md)

```bash
loopx dashboard
loopx benchmark trajectory-packs --goal-id "$GOAL_ID" --format json
loopx benchmark trajectory-assessment-status --directory "$ANALYSIS_DIR" --format json
# Explicit cancellation of that original operation:
loopx benchmark trajectory-assessment-cancel --directory "$ANALYSIS_DIR" --format json
```

#### Local Codex source documents

**启用：** 打开本地托管 Codex 会话，附加 UTF-8 `.md`／`.txt` 原始文件，再发送已授权请求。最多四个附件共享序列化消息 64,000 字节预算，编码后的文档数据计入额度。本版交付本地输入、队列恢复与原文预览／下载。 [#7740](https://github.com/loopx-project/loopx/pull/7740)。

**验证：** 在原会话展开附件并下载原文，比较完整 UTF-8 字节；忙碌排队或重启后检查原请求／队列结果。原文送达不等于模型理解或自动采用。

**停用 / 回退：** 发送前从草稿移除附件，或只发送文字。已接收原文保留在原始请求中；需要停止时沿既有 owner 操作，不能替换 journal。回退应用须先保存备份，再沿原安装 owner 完成。

**权限边界：** 仅本地托管 Codex 会话接收文本文件；attached 宿主、其他 executor 及关联／飞书会话会在准入前拒绝。非法 UTF-8、NUL、类型／文件名不符及超限均拒绝整个请求，不截断正文。附件来源不增加指令、任意路径访问或外部发送授权。

**文档：** [本版原始文件合同](https://github.com/loopx-project/loopx/blob/v2.2.0/docs/architecture/rfcs/app-conversation-and-async-inbox-v0.zh-CN.md#本地文本文件附件)

#### Original-request native delegation

**启用：** 在成员目录之外的 operator 授权文件中声明 `loopx_local_delegation_v0` binding。普通原请求省略 `todo_id`，但必须声明含 command／argv、另一命令字段的 null、label 与 timeout 的 `request_validation`；只授予指定 requester 与来源。原生执行仍要求 runtime-compatible project registry；生命周期 profile `source_session_v1` 会在 Host 启动前拒绝执行。先预览，再设置 Goal 授权文件指针；Chat 还须当前 Inbox grant 与原始保存请求。

**验证：** 检查准确 binding，在团队执行情况读回原请求与独立验收依据，再检查原 operation 的真实结果及原会话返回。注册、预览或 native 进程完成均不能替代交付。

**停用 / 回退：** 在原受保护文件撤销准确 binding／来源 grant；移除发现入口时再清除 Goal 指针。保留在途原 journal 和未知效果，不能改解为新请求或 Todo 重跑。

**权限边界：** 请求身份、消息送达或会话复用不授予执行、仓库写入或外部发送权。Stop、真正用户门、额度、当前来源授权、独立校验、single-flight 和一次结算继续生效。File／SQLite 与打包合成 transport 检查不等于每个模型或外部 transport 合格。

**文档：** [本版普通 Inbox／委派合同](https://github.com/loopx-project/loopx/blob/v2.2.0/docs/reference/local-delegation.md#ordinary-inbox-activation-boundary)

**启用：** 默认关闭。在「设置 → 本机 → 能力 → 差分上下文 → Codex」开启，沿原精确 revision 事务保存。受支持的 Codex App heartbeat、SSH Goal 与显式 benchmark heartbeat，还须为下一次受支持会话完成准确 hooks／配置。保存偏好不初始化已载入线程。宿主输出预算较小时，可在已有 guard 或 context-project 命令追加 --max-page-output-bytes 7900；沿有界续页与原恢复命令读取，批量输出仍须满足宿主总预算。

**权限边界：** 原生连续性当前仅支持 POSIX。原生完整／后续读取使用既有 64000-byte profile；混合 stdout 中完整 JSON 记录仍须通过 trusted capture 验证。不确定或丢失连续性时恢复同一完整原件；展示不重新准入、不新增工作权。MCP／Claude 机器解析仍读 raw output；不声明费用或效果改善。

#### Session-bound reliability diagnostics

**启用：** 实验性被动 L1 观察仍默认关闭，仅对显式授权的原 Session 使用规范中独立 dsh-loopx-plugin/observer 入口。当前手动读取须提供准确 provider／observer／session、typed run_identity、当前 as-of 和最大观测年龄。

**验证：** 从同一次 ledger 观察读取 status 与 integrity receipt；过期、错绑定、损坏或不完整保留 unavailable。空或旧 ledger 不证明当前运行健康。

**停用 / 回退：** 停用独立 observer 入口可停止新观察，保留 ledger／receipt。省略 expected-binding 只是 legacy readback，不能改称当前绑定资格通过。

**权限边界：** Observer 不能发送、调度、gate、retry、stop、resume 或改 worker state；仅保留无内容诊断，不收原会话／工具正文。Adapter fidelity、实测开销与 P0 exit 仍独立待验。

