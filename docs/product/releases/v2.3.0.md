# LoopX 2.3.0

## Release Decision

**Who should upgrade:** Operators using managed Goals, the Research Workspace, or a supported native host can use the clearer acceptance, source evidence, and request recovery. Windows desktop preview users should install the new stable desktop bundle manually. An existing deployment with a custom ACP endpoint named `antigravity` should rename that endpoint before upgrading. Users who do not need these workflows can stay on 2.2.0.

**What this release solves:** Goal acceptance can use retained checks and evidence. The Workspace makes captured Turn evidence, report editions, and the original conversation easier to follow. An opted-in research Turn can evaluate the next target against matched measurements.

**Breaking changes:** Yes. The built-in Antigravity executor reserves the id `antigravity`. Rename an existing custom ACP endpoint using that id. Existing canonical File and SQLite Goals retain their storage owner. Inherited Stride can apply its evidence-conditioned guidance. Use the Goal or machine setting to opt out explicitly. [#7832](https://github.com/loopx-project/loopx/pull/7832), [#7928](https://github.com/loopx-project/loopx/pull/7928)

**How to verify:** Expect `loopx 2.3.0` and the expected installation owner in Doctor. Open a known Goal and inspect its acceptance record, then open the original source of one Research result.

**Contributors:** Maintained by [@huangruiteng](https://github.com/huangruiteng). See the community contributions below.

```bash
loopx --version
loopx doctor
loopx --format json goal-acceptance inspect --goal-id "$goal_id"
```

## At a Glance

Check what a Goal actually delivered, pick the next research step using comparable evidence, and find the source behind a result in the Workspace.

### Upgrade

Use the installation owner shown by the update check. Existing archive installations keep their archive update path.

```bash
loopx update check
loopx update apply
loopx --version
loopx doctor
```

### Highlights

- **Check a Goal against its commitments.** Open its acceptance record to see declared checks and evidence before making an overall decision. Local Todos can still finish as each delivers its own result. [#8161](https://github.com/loopx-project/loopx/pull/8161), [#8178](https://github.com/loopx-project/loopx/pull/8178)
- **Choose the next research probe from actual results.** Enable Yardstick on a Goal with Explore evidence, then compare distinct candidates tested on the same target and measurement profile. [#8202](https://github.com/loopx-project/loopx/pull/8202), [#8207](https://github.com/loopx-project/loopx/pull/8207), [#8261](https://github.com/loopx-project/loopx/pull/8261)
- **Review the original evidence and results.** Inspect the captured Turn range, compare two captured usages, download the readable evidence report, or open a report edition from Home. [#7882](https://github.com/loopx-project/loopx/pull/7882), [#7973](https://github.com/loopx-project/loopx/pull/7973), [#8017](https://github.com/loopx-project/loopx/pull/8017), [#8116](https://github.com/loopx-project/loopx/pull/8116), [#8146](https://github.com/loopx-project/loopx/pull/8146)
- **Correct a pending request before it runs.** Edit or cancel a queued message from the conversation, steer an active Turn when the session supports it, and read back the answer in its original conversation. [#8059](https://github.com/loopx-project/loopx/pull/8059), [#8096](https://github.com/loopx-project/loopx/pull/8096), [#8121](https://github.com/loopx-project/loopx/pull/8121), [#8269](https://github.com/loopx-project/loopx/pull/8269)

### Replan Fixes

- Captured Turn recovery reads the complete original source, including small object projections. Native first reads include the current task operation and its declared continuation. The Task inspector opens the full original evidence and notes. [#8211](https://github.com/loopx-project/loopx/pull/8211), [#8356](https://github.com/loopx-project/loopx/pull/8356), [#8361](https://github.com/loopx-project/loopx/pull/8361)
- Conversation intake asks for clarification when existing Goals are equally relevant. When an accepted report body is available, the response returns that content; a status marker alone still requires retrieval from its existing owner. [#8356](https://github.com/loopx-project/loopx/pull/8356)
- A pre-bound heartbeat now keeps the actual Turn identity from its producer through admission and settlement. An expired execution claim surfaces its recovery action. [#8232](https://github.com/loopx-project/loopx/pull/8232), [#7912](https://github.com/loopx-project/loopx/pull/7912)
- Current decision cues appear before supporting material. A staged read stays on its original capture across recovery, and composed settlement failures retain the concrete diagnostic. [#7984](https://github.com/loopx-project/loopx/pull/7984), [#7985](https://github.com/loopx-project/loopx/pull/7985), [#8267](https://github.com/loopx-project/loopx/pull/8267)
- Finish the original Turn after its completed Todo moves to the archive. [#8264](https://github.com/loopx-project/loopx/pull/8264)
- A native Host retry keeps the live guard's original capture and managed claim identity. If a saved capture lacks a verified binding, keep its existing claim receipt and obtain a fresh guard for the same Turn if preparation is still needed. [#8279](https://github.com/loopx-project/loopx/pull/8279)
- SSH Goals use the compact activation prompt with inherited context delivery. Windows Doctor reads drive-qualified wheel records using the native path parser.

## State Kernel & Control Plane

- Goal owners can configure and verify checks against retained commitments with an explicit configuration and a revision-bound readback. Existing local Todo acceptance continues under its own declaration. [#8161](https://github.com/loopx-project/loopx/pull/8161), [#8178](https://github.com/loopx-project/loopx/pull/8178)
- Heartbeat and settlement retain the original Turn and its diagnostic through prequota, admission and bound reads. Retry from the committed capture, and recover an expired execution claim through its declared owner. [#7912](https://github.com/loopx-project/loopx/pull/7912), [#8232](https://github.com/loopx-project/loopx/pull/8232), [#8240](https://github.com/loopx-project/loopx/pull/8240), [#8267](https://github.com/loopx-project/loopx/pull/8267)
- Inherited Stride guidance uses evidence and work shape. Opt-in Yardstick adds a scoped comparison from distinct findings that share an acceptance reference and measurement profile. Proxy ordering is advisory, and a comparison only appears when the qualifying pair exists. [#7928](https://github.com/loopx-project/loopx/pull/7928), [#8202](https://github.com/loopx-project/loopx/pull/8202), [#8207](https://github.com/loopx-project/loopx/pull/8207), [#8261](https://github.com/loopx-project/loopx/pull/8261), [#8268](https://github.com/loopx-project/loopx/pull/8268)

## Capabilities & Workflows

- Research shows the captured Turn range and available usage evidence, provides a readable report, and preserves a bookmarked result while part of the source is unavailable. Home can open an existing report edition. [#7882](https://github.com/loopx-project/loopx/pull/7882), [#7973](https://github.com/loopx-project/loopx/pull/7973), [#8017](https://github.com/loopx-project/loopx/pull/8017), [#8116](https://github.com/loopx-project/loopx/pull/8116), [#8146](https://github.com/loopx-project/loopx/pull/8146), [#8226](https://github.com/loopx-project/loopx/pull/8226)
- Conversations can steer a supported active Turn and edit or cancel pending messages. Recovered native replies keep the request and answer together. Use the original conversation to review the result. [#8059](https://github.com/loopx-project/loopx/pull/8059), [#8096](https://github.com/loopx-project/loopx/pull/8096), [#8121](https://github.com/loopx-project/loopx/pull/8121), [#8144](https://github.com/loopx-project/loopx/pull/8144), [#8269](https://github.com/loopx-project/loopx/pull/8269)

## Optional Capability Activation & Use

### Goal commitment checks

**Activation:** Inspect the Goal, then configure its owner-approved check document using the observed provider revision. Execute verification when the current Goal owner authorizes the declared checks.

**Validation:** Inspect again and compare each check and evidence reference with the Goal's declared acceptance.

**Disable / rollback:** Use clear-checks with the current provider revision to remove executable checks from this Goal.

**Authority boundary:** Verification uses the declared checker authority. Goal checks preserve the existing local Todo lifecycle.

**Docs:** [Versioned documentation](https://github.com/loopx-project/loopx/blob/v2.3.0/docs/reference/goal-acceptance-observations.md#owner-pinned-oracle-and-exact-versions)

```bash
loopx --format json goal-acceptance inspect --goal-id "$goal_id"
loopx goal-acceptance configure --goal-id "$goal_id" --document owner-contract.json --expected-provider-revision "$revision" --execute
loopx goal-acceptance verify --goal-id "$goal_id" --execute
loopx --format json goal-acceptance inspect --goal-id "$goal_id"
loopx goal-acceptance clear-checks --goal-id "$goal_id" --expected-provider-revision "$current_revision" --execute
```

### Yardstick decisions

**Activation:** On a Goal with Explore evidence, enable the independent Yardstick setting. The ordinary Turn cue is off until enabled for the effective profile.

**Validation:** Read the effective Goal configuration, then open a Research finding with the recorded target and measurement. Look for a comparison only after two qualifying results.

**Disable / rollback:** Disable the Goal option. Earlier findings remain readable.

**Authority boundary:** Advice uses the recorded matching scope. Current acceptance and execution authority govern the next action.

**Docs:** [Versioned documentation](https://github.com/loopx-project/loopx/blob/v2.3.0/docs/architecture/rfcs/target-yardstick-stride-decisions-v0.md#m1-implementation-checkpoint)

```bash
loopx configure-goal --goal-id "$goal_id" --execution-yardstick-enabled --execute
loopx --format json configure-goal --goal-id "$goal_id"
loopx configure-goal --goal-id "$goal_id" --no-execution-yardstick-enabled --execute
```

### Evidence-conditioned Stride

**Activation:** The inherited strategy can use evidence_conditioned_v1. Set the strategy explicitly to pin it for a Goal.

**Validation:** Read the effective execution profile. For a staged replan, open `decision_value_review` in the review stage and compare its advice with the Goal evidence before choosing work. [#8375](https://github.com/loopx-project/loopx/pull/8375)

**Disable / rollback:** Set the Goal strategy to off, or use the existing clear option to restore inheritance.

**Authority boundary:** The strategy recommends a next choice under the existing approval, cost and Stop conditions.

**Docs:** [Versioned documentation](https://github.com/loopx-project/loopx/blob/v2.3.0/docs/architecture/rfcs/hierarchical-agent-stride-control-v0.md)

```bash
loopx configure-goal --goal-id "$goal_id" --execution-stride-strategy evidence_conditioned_v1 --execute
loopx --format json configure-goal --goal-id "$goal_id"
loopx configure-goal --goal-id "$goal_id" --execution-stride-strategy off --execute
```

### Progressive context recovery

**Activation:** Use the existing Context Delivery setting or request context delivery on a supported host for the next ordinary guard.

**Validation:** Open the saved capture using the path and digest from that guard. Select only the current fields the next action requires. If preflight offers Todo selection, run the emitted command and verify that it opens a separate capture for the same Turn. [#8275](https://github.com/loopx-project/loopx/pull/8275)

**Disable / rollback:** Disable the setting or pass --context-delivery off on the next ordinary guard. Complete in-flight recovery from its original capture.

**Authority boundary:** A read recovers the admitted Turn's facts. The original guard and settlement retain their authority. Complete Turn capability advice and result checks bind to the admitted source, including when a retry reads a recorded result. [#8373](https://github.com/loopx-project/loopx/pull/8373)

**Docs:** [Versioned documentation](https://github.com/loopx-project/loopx/blob/v2.3.0/docs/reference/required-work-context.md)

```bash
loopx --format json quota context-read --capture-file "$capture" --capture-sha256 "$capture_sha" --select /effective_action
```

### Antigravity conversations

**Activation:** Sign in to Antigravity, then open Settings → Steward → Models and executor. Select antigravity, an account-offered Gemini 4 Argon tier and the supported effort. Preview and apply.

**Validation:** Reload the settings to verify the effective executor, then send an ordinary test question in the same conversation and check the returned reply.

**Disable / rollback:** Select Codex again in the same editor. If you installed the agy slash facade for a separate CLI session, remove it with the matching uninstall command.

**Authority boundary:** Native permission decisions remain with the host. Restricted Chat selects the restricted tool policy.

**Docs:** [Versioned documentation](https://github.com/loopx-project/loopx/blob/v2.3.0/docs/reference/protocols/host-mode-plan-v0.md)

```bash
loopx doctor
loopx slash-commands --install --surface agy
loopx slash-commands --uninstall --surface agy
```

### Codex account API priority

**Activation:** Install the optional account package into the LoopX Python environment and restart its serving owner. In Settings → Model Provider configuration, select Steward API use → Prefer API with an existing authorized API key.

**Validation:** Reload the selector and check its saved value. Read the working-Agent policy separately.

**Disable / rollback:** Select Disabled for the Steward's API role. The existing worker fallback setting controls working Agents separately.

**Authority boundary:** Select an API policy only with a key authorized for that use. The next Turn uses the new route and an in-flight request retains its original route.

### 升级决策

**谁需要升级：**使用受管 Goal、研究工作台或原生宿主的用户。Windows 桌面预览版用户应手动安装新版稳定版桌面包。配置了同名自定义 ACP endpoint 的用户先将 `antigravity` 改名。 不需要这些工作流的用户可以继续使用 2.2.0。

**解决了什么：**在 Goal 核对承诺与证据。在研究结果中查看原 Turn、报告和下一步的可比测量。在原会话恢复和追踪请求。

**是否有破坏性变更：**有。内置 Antigravity 占用 `antigravity` 标识，同名自定义 ACP endpoint 需改名。原有 canonical File 或 SQLite 由原存储 owner 继续管理。可在 Goal 或本机设置中关闭继承的证据条件式 Stride。 [#7832](https://github.com/loopx-project/loopx/pull/7832), [#7928](https://github.com/loopx-project/loopx/pull/7928)

### 可选能力启用与使用

#### Goal commitment checks

**启用：** Goal 承诺检查。先读回 Goal，再按当前 provider revision 保存 owner 批准的检查文档。经该 Goal 授权后执行声明的检查。

**验证：** 再次 inspect，逐条对照 Goal 的验收声明与证据。

**停用 / 回退：** 用当前 provider revision 运行 clear-checks 移除该 Goal 的可执行检查。

**权限边界：** 检查使用各自声明的权限。局部 Todo 继续按自身规则结案。

**文档：** [本版文档](https://github.com/loopx-project/loopx/blob/v2.3.0/docs/reference/goal-acceptance-observations.md#owner-pinned-oracle-and-exact-versions)

```bash
loopx --format json goal-acceptance inspect --goal-id "$goal_id"
loopx goal-acceptance configure --goal-id "$goal_id" --document owner-contract.json --expected-provider-revision "$revision" --execute
loopx goal-acceptance verify --goal-id "$goal_id" --execute
loopx --format json goal-acceptance inspect --goal-id "$goal_id"
loopx goal-acceptance clear-checks --goal-id "$goal_id" --expected-provider-revision "$current_revision" --execute
```

#### Yardstick decisions

**启用：** Yardstick 工作选择。为已有 Explore 证据的 Goal 打开独立 Yardstick 设置。普通 Turn 指引在有效配置启用后才出现。

**验证：** 读回 Goal 的有效配置，再看研究记录中的目标和测量。有两条合格结果时核对对照。

**停用 / 回退：** 关闭该 Goal 的 Yardstick。已有研究记录仍可读。

**权限边界：** 建议受相同测量范围约束，原验收与执行授权仍决定下一步。

**文档：** [本版文档](https://github.com/loopx-project/loopx/blob/v2.3.0/docs/architecture/rfcs/target-yardstick-stride-decisions-v0.md#m1-implementation-checkpoint)

```bash
loopx configure-goal --goal-id "$goal_id" --execution-yardstick-enabled --execute
loopx --format json configure-goal --goal-id "$goal_id"
loopx configure-goal --goal-id "$goal_id" --no-execution-yardstick-enabled --execute
```

#### Evidence-conditioned Stride

**启用：** 证据条件式 Stride。继承策略可采用 evidence_conditioned_v1。可为 Goal 显式固定策略。

**验证：** 读回有效执行配置。分阶段重规划时，先在 review 阶段读取 `decision_value_review`，对照 Goal 证据后再选择工作。 [#8375](https://github.com/loopx-project/loopx/pull/8375)

**停用 / 回退：** 将 Goal 策略设为 off，或用既有 clear 参数恢复继承。

**权限边界：** 策略提供下一步建议，仍遵守审批、成本和停止条件。

**文档：** [本版文档](https://github.com/loopx-project/loopx/blob/v2.3.0/docs/architecture/rfcs/hierarchical-agent-stride-control-v0.md)

```bash
loopx configure-goal --goal-id "$goal_id" --execution-stride-strategy evidence_conditioned_v1 --execute
loopx --format json configure-goal --goal-id "$goal_id"
loopx configure-goal --goal-id "$goal_id" --execution-stride-strategy off --execute
```

#### Progressive context recovery

**启用：** 渐进式上下文恢复。通过已有上下文交付设置，或在支持的宿主对下一次普通 guard 指定 context delivery。

**验证：** 用 guard 给出的路径和摘要读取保存的捕获。只补读下一步依赖的当前字段。若预检要求选择 Todo，执行返回的命令，核对它为同一 Turn 打开独立捕获。 [#8275](https://github.com/loopx-project/loopx/pull/8275)

**停用 / 回退：** 关闭设置或在下次普通 guard 传 --context-delivery off。正在恢复的 Turn 沿原捕获完成。

**权限边界：** 读取仅恢复已准入 Turn 的事实，准入与结算仍由原流程负责。Complete Turn 的能力指引及结果校验绑定准入时的来源，重试读取历史结果时也沿用该来源。 [#8373](https://github.com/loopx-project/loopx/pull/8373)

**文档：** [本版文档](https://github.com/loopx-project/loopx/blob/v2.3.0/docs/reference/required-work-context.md)

```bash
loopx --format json quota context-read --capture-file "$capture" --capture-sha256 "$capture_sha" --select /effective_action
```

**验证：** 刷新设置检查有效执行器，在同一对话中问一个普通问题并回看原答案。

**停用 / 回退：** 在原设置切回 Codex。如果单独为 agy CLI 装了 slash facade，用对应命令卸载。

**权限边界：** 宿主负责原生权限决策。受限 Chat 使用受限工具策略。

**权限边界：** 使用经授权的 key。新选择从下一个 Turn 生效，进行中的请求保持原路由。

**验证：** 读回原运行、保留版本、token 来源和未知字段。

**停用 / 回退：** 将 Explore 模式设为 off 停止新的捕获，保留原有证据。

**权限边界：** 报告与对照读取该 Goal 有权访问的来源。实测用量与估算分别保留出处。

#### Anti-Entropy retirement checks

**启用：** Anti-Entropy 退役检查。为该任务明确声明 retirement_basis 或 anti-entropy-governance 要求，给出目标路径或符号及修改后工作区。

**验证：** 对绑定工作区与原始 diff 先 inspect，再用 verify 获取退役验证证据。

**停用 / 回退：** 在后续任务移除显式启用声明，无关任务不调用该检查。

**权限边界：** 检查只读，交付由 change-quality 判定，缺少工作区源码时不能出具认证。

**文档：** [本版文档](https://github.com/loopx-project/loopx/blob/v2.3.0/loopx/capabilities/anti_entropy/README.md)

```bash
loopx anti-entropy inspect --goal-id "$goal_id" --diff-file diff.patch --basis-json basis.json --workspace "$workspace" --format json
loopx anti-entropy verify --goal-id "$goal_id" --diff-file diff.patch --basis-json basis.json --workspace "$workspace" --format json
```

#### Benchmark campaign reports

**启用：** 基准试验报告。提供明确的试验选择，按需设置 duration_policy.makeup_tolerance_ms 允许小额终态缺口，显式加 --score-curves 生成 HTML。

**验证：** 在产物中核对时长分类、实际缺口与分数观测序列。
