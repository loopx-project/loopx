# LoopX v2.4.1 upgrade guide

## Release Decision

[Illustrated personal Feishu guide](https://my.feishu.cn/docx/La9gd9WQjoj9kaxoyePcHYx2nka)

**Who should upgrade:** Operators who resume existing Goals, share a workspace with other Agents, or use the private Steward and signed macOS App. Install the upgrade through the same owner that installed your CLI or App.

**What this release solves:** The default Turn reply carries the original work and recovery identifiers together. Equivalent outcome requirements can share content across views, and distinct sources stay individually reachable. Agents get earlier, actionable feedback when two tasks need the same workspace. [#9176](https://github.com/loopx-project/loopx/pull/9176), [#9328](https://github.com/loopx-project/loopx/pull/9328), [#9256](https://github.com/loopx-project/loopx/pull/9256), [#9293](https://github.com/loopx-project/loopx/pull/9293)

**Breaking changes:** Yes, for integrations that pass retired quota selectors. Adopt the Complete Turn reply and its versioned protocol. Existing Goal data requires no migration. The archived v2.4.0 installation retains its historical format. [#9176](https://github.com/loopx-project/loopx/pull/9176), [#9306](https://github.com/loopx-project/loopx/pull/9306)

**How to verify:** Check the version and installation owner, reopen an existing Goal and read the same unfinished Todo and conversation.

**Contributors:** The release is maintained by @huangruiteng. Community changes in this range came from @BigDataDZ, @cocolord, @Duang777, @gcl-coder, @hhyykk, @Jiaqiiii523, @maxliux5, @xiaobaifly7 and @xiaods.

```bash
loopx --version
loopx doctor --installation-only
loopx status
```

## Release scope

- **Recover a blocked Goal.** When an ongoing goal is still open and blocked work has no qualified resume signal, the Agent can try a bounded replan and select an independent successor. [#9361](https://github.com/loopx-project/loopx/pull/9361)
- **Continue an existing Goal.** The supported Complete Turn path carries the original requirements, authorization and settlement identity together. Matching requirements can share a body across views. A historical full read retains the fallback fields, and exact values continue to have separate sources. [#9176](https://github.com/loopx-project/loopx/pull/9176), [#9323](https://github.com/loopx-project/loopx/pull/9323), [#9328](https://github.com/loopx-project/loopx/pull/9328)
- **Work alongside other Agents.** Routine claims avoid unnecessary path-level contention and a definitive declined claim has one actionable result. Work in the same directory can still require a different worktree. [#9256](https://github.com/loopx-project/loopx/pull/9256), [#9293](https://github.com/loopx-project/loopx/pull/9293)
- **Open the original conversation and result.** A new Goal confirmation links to the verified conversation. Local Goal replies support downloadable text files. Private Steward replies can return through their original Lark topic. [#9315](https://github.com/loopx-project/loopx/pull/9315), [#9316](https://github.com/loopx-project/loopx/pull/9316), [#9321](https://github.com/loopx-project/loopx/pull/9321), [#9318](https://github.com/loopx-project/loopx/pull/9318)
- **Read measured Research candidates in place.** The Research question card shows its supporting measurement and evidence. [#9307](https://github.com/loopx-project/loopx/pull/9307)

## Verify an existing installation

Use the upgrade route for your installation owner. For PyPI, update the same environment. For an archive install, check the exact version first.

```bash
loopx update check --ref v2.4.1
loopx update apply --ref v2.4.1
loopx --version
loopx doctor --installation-only
```

For the signed macOS App, use its update panel or run `loopx upgrade` to update the installed App and reopen it. Check the version in Settings. To restore the previous App, use the update backup action in Settings. After reopening the App, open an existing Goal. Verify the original conversation and an unfinished Todo. For an archive rollback, use `loopx update --rollback previous` if the pre-update release is still present. For a PyPI rollback, reinstall `loopx==2.4.0` in its original environment. Run `loopx doctor --installation-only` and read back the same work.

The runtime compatibility bridge teaches installed readers to accept both approved contract profiles. An old preview-only updater can require the bridge before consuming a Complete Turn archive. See the [release and update contract](https://github.com/loopx-project/loopx/blob/v2.4.1/docs/product/release-readiness.md) and the [Complete Turn protocol](https://github.com/loopx-project/loopx/blob/v2.4.1/docs/reference/protocols/turn-envelope-v0.md). [#9306](https://github.com/loopx-project/loopx/pull/9306)

## Optional Capability Activation & Use

### DSH

**Activation:** DSH is optional and installed separately from Core. Use an authorized profile on a supported DSH host. After the beta.8 GitHub release lists the tarball, install that exact asset; until then keep the installed version. An npm or Hub result is not proof that it serves beta.8.

```bash
dsh plugin --profile web add https://github.com/loopx-project/loopx/releases/download/dsh-loopx-plugin-v0.1.1-beta.8/dsh-loopx-plugin-0.1.1-beta.8.tgz
dsh plugin --profile web
```

**Validation:** Confirm the profile lists `dsh-loopx-plugin@0.1.1-beta.8`. In a bound Goal session, invoke the `loopx` skill and check that GoalBar reflects the successful tool result. Pause the lane, reload the Driver, and verify no new step starts. [#9297](https://github.com/loopx-project/loopx/pull/9297), [#9298](https://github.com/loopx-project/loopx/pull/9298)

**Disable / rollback:** Remove it from the same profile with `dsh plugin --profile web remove dsh-loopx-plugin`. If you need the prior plugin, reinstall the [pinned beta.7 archive](https://github.com/loopx-project/loopx/releases/download/dsh-loopx-plugin-v0.1.1-beta.7/dsh-loopx-plugin-0.1.1-beta.7.tgz) in that profile. Beta.7 does not include the beta.8 Driver pause fix.

**Authority boundary:** The plugin uses the selected profile and the bound Goal's existing authority. Do not share private Goal captures or conversation receipts in public reports.

**Docs:** [Versioned DSH installation and recovery guide](https://github.com/loopx-project/loopx/blob/dsh-loopx-plugin-v0.1.1-beta.8/packages/dsh-loopx-plugin/README.md).

### 升级决策

[个人飞书图文升级指南](https://my.feishu.cn/docx/La9gd9WQjoj9kaxoyePcHYx2nka)

**谁需要升级：** 正在续作已有 Goal、让多个 Agent 协作，或使用私聊管家和 macOS 签名 App 的用户。按原安装方式升级。

**解决了什么：** 续作携带原有工作和恢复标识。相同成果要求在多个视图中共享内容，各自来源仍可读回。同一工作区发生争用时，Agent 能收到明确的恢复指引。[#9176](https://github.com/loopx-project/loopx/pull/9176)、[#9328](https://github.com/loopx-project/loopx/pull/9328)、[#9256](https://github.com/loopx-project/loopx/pull/9256)、[#9293](https://github.com/loopx-project/loopx/pull/9293)

**是否有破坏性变更：** 有。已有 Goal 无需迁移。调用旧 quota 选择器的集成应改用 Complete Turn 及其版本化协议。旧归档继续保留原输出格式。[#9176](https://github.com/loopx-project/loopx/pull/9176)、[#9306](https://github.com/loopx-project/loopx/pull/9306)

**如何验证：** 确认版本和安装归属，重开已有 Goal，读回同一个未完成 Todo 和原会话。

**贡献者：** 由 @huangruiteng 维护。社区贡献者包括 @BigDataDZ、@cocolord、@Duang777、@gcl-coder、@hhyykk、@Jiaqiiii523、@maxliux5、@xiaobaifly7 和 @xiaods。

### 使用说明

- **恢复受阻的 Goal。** 当需要继续推进的 Goal 仍有验收缺口，受阻的待办也没有可核验的恢复条件，Agent 可做一次有界重规划并选取能独立推进的下一项工作。[#9361](https://github.com/loopx-project/loopx/pull/9361)
- **续作与回退。** 根据当前安装方式升级到 2.4.1。执行 `loopx --version` 和 `loopx doctor --installation-only`，重开 App 读原会话和未完成的 Todo。归档安装可用 `loopx update --rollback previous` 回退，PyPI 用户在原环境重装 2.4.0。
- **减少执行摩擦。** 相同成果要求可在多个视图共享，精确值和各自采纳状态仍可读回。不同待办用各自的工作区推进，明确拒绝的领取结果附恢复指引。[#9256](https://github.com/loopx-project/loopx/pull/9256), [#9293](https://github.com/loopx-project/loopx/pull/9293), [#9328](https://github.com/loopx-project/loopx/pull/9328)
- **在原上下文取得结果。** 新 Goal 确认后可打开原会话。Goal 回复附可下载文本，私聊管家答复回到原飞书话题。研究问题卡展示能查证的测量结果。[#9316](https://github.com/loopx-project/loopx/pull/9316), [#9321](https://github.com/loopx-project/loopx/pull/9321), [#9318](https://github.com/loopx-project/loopx/pull/9318), [#9307](https://github.com/loopx-project/loopx/pull/9307)

### 可选能力启用与使用

#### DSH

**启用：** DSH 是独立于 Core 安装的可选插件。请在受支持的 DSH 环境选择已授权的 profile。确认 GitHub 的 beta.8 发布页列出对应制品后，再用以下固定地址安装。在此之前保留已安装版本，不要把 npm 或 Hub 的搜索结果当成 beta.8 已发布的凭据。

```bash
dsh plugin --profile web add https://github.com/loopx-project/loopx/releases/download/dsh-loopx-plugin-v0.1.1-beta.8/dsh-loopx-plugin-0.1.1-beta.8.tgz
dsh plugin --profile web
```

**验证：** 确认该 profile 列出 `dsh-loopx-plugin@0.1.1-beta.8`。在已绑定 Goal 的会话中调用 `loopx` skill，确认 GoalBar 能显示成功的工具结果。暂停执行通道后重新加载 Driver，确认没有开启新步骤。[#9297](https://github.com/loopx-project/loopx/pull/9297)、[#9298](https://github.com/loopx-project/loopx/pull/9298)

**停用 / 回退：** 在同一 profile 执行 `dsh plugin --profile web remove dsh-loopx-plugin`。如需回退，在该 profile 装回[固定的 beta.7 制品](https://github.com/loopx-project/loopx/releases/download/dsh-loopx-plugin-v0.1.1-beta.7/dsh-loopx-plugin-0.1.1-beta.7.tgz)。beta.7 不包含 beta.8 的 Driver 暂停修复。

**权限边界：** 插件使用选定的 profile 和已绑定 Goal 的现有权限。公开报告请勿附上私人 Goal 捕获或会话回执。

**文档：** [版本化 DSH 安装和恢复手册](https://github.com/loopx-project/loopx/blob/dsh-loopx-plugin-v0.1.1-beta.8/packages/dsh-loopx-plugin/README.md)。
