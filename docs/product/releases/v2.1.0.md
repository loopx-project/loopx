# LoopX 2.1: recover the original work, keep the result visible

[中文指南](#中文指南) · [Release and verified assets](https://github.com/loopx-project/loopx/releases/tag/v2.1.0)

2.1 is a compatible feature and reliability update from 2.0.0. It connects safer
Bot recovery, source-bound delegation and clearer Goal context with a more usable
workspace and optional media production. An acknowledgement, resumed process or
completed Todo still does not establish that the original person received a result.

## Upgrade and verify

Use Python 3.11+ and Node.js 22.22.3+; Node 24 LTS is recommended. Preserve your
existing installation owner, Goal provider, ownership policy and explicit overrides.

```bash
python3 -m pip install --upgrade 'loopx==2.1.0'
loopx workflow-skills --install
loopx --version
loopx doctor --deep
```

Expect `loopx 2.1.0`. Existing archive/pipx/uv-tool users should inspect
`loopx update check` and `loopx update plan`, then use `loopx update apply` through
the same installation owner. Restart the Agent host after first installing skills.
CLI identity and the native desktop App's version are separate readbacks.

There is no additional persisted-state migration from 2.0.0. The 2.0 compatibility
cutoff remains: an unpromoted Markdown Goal or retired `legacy` ownership needs the
[reviewed migration](v2.0.0.md#choose-your-upgrade-path); an upgrade never silently
converts authority, releases leases or authorizes another writer.

## Recover conversations without replaying uncertain effects

Private Bot routing, quota failure recovery and original native-profile selection
now retain the original request and execution context. Safe continuation requires
independent evidence that the failed attempt performed no business effect.
Requests with tool effects, an uncertain result or a later correction/stop retain
their original recovery path. Authorization errors also require effect readback.

Queued handoffs recover their saved source before launching a receiver. Source
revocation is checked again in workers, a busy native lane is visible before
handoff, and the steward's conversation work surface exposes unfinished incoming
and outgoing requests. Read, adoption and a linked Todo remain distinct from
execution, result return and requester adoption.

Known limitation: admission and worker source checks are not atomic with final
Task completion. If a grant is revoked after the last check, the Task can still
commit before the operation reports revocation. Preserve the Task, operation and
Host evidence; that error does not prove no effects or make replay safe. See the
[independent revocation race review](https://github.com/loopx-project/loopx/pull/7016#pullrequestreview-5609184153).

## Keep the Goal and its evidence in view

Default planning context retains the current Goal and bounded work. Exceptional
objective revisions preserve acceptance guidance and require each Agent's own
adoption; one Agent cannot silently adopt for the others. Supporting outcomes
retain requirements and evidence separately from task completion. Native
Todo-less planning/recovery can settle without inventing a delivery task.

Research history and deep analysis make episode evidence, source citations and
quantitative results easier to inspect. Explicitly selected work controls the
Explore evidence window. Source-read continuation binds the verified digest.
These are visibility and decision-support changes, not measured proof of better
long-horizon outcomes or lower total cost.

## Use the workspace and desktop

Open `loopx dashboard`, select an existing Goal, and use **Quick navigation**
(`Cmd+K` on macOS or `Ctrl+K`) to find Goals, loaded tasks, saved previews and
results. Opening an item navigates; it does not apply a proposal or launch work.
Settings distinguish live device defaults from explicit Goal overrides.

The native desktop shell allows local startup while a manual update check runs,
distinguishes download transport failures from signature failures, and stops its
owned private services after the App exits or crashes. These are desktop-preview
improvements; a successful macOS build is not a Windows execution test.

See [#6996](https://github.com/loopx-project/loopx/pull/6996),

## Optional workflows and their boundaries

### Content media

In an existing Goal, **Results → Content artifacts** now owns composition, generated
footage/images, verified downloads and return to the conversation. Agent authoring
and edits stay in that conversation. The optional `loopx-media` package owns local
rendering, optional Blender scenes and explicitly submitted Ark generation.

From a checkout of this release, register the separate package explicitly:

```bash
uv tool install ./packages/loopx-media
loopx extension install --manifest packages/loopx-media/extension.toml --execute
loopx extension doctor loopx-media --execute
# Stop new provider work; inspect existing operations through their original IDs.
loopx extension disable loopx-media --execute
```

Existing providers need an explicit package upgrade and `loopx extension upgrade`
with the new manifest. Full-frame image/video/Blender shots preserve the picture
and retain a separate source strip; remove `framing` in a new composition revision
to restore editorial framing. Cloud video/image intents disclose upload, price
and usage consequences before explicit submission. Use separate scoped credentials;
never repeat an ambiguous paid submission. Stopping observation is not remote
cancellation. An image/video file, renderer check or Goal result is not acceptance
or publication permission.

[Provider setup, cost and recovery](../../../packages/loopx-media/README.md) ·
[#6876](https://github.com/loopx-project/loopx/pull/6876) ·
[#6979](https://github.com/loopx-project/loopx/pull/6979).

### MemT Nano Turn host

The experimental `loopx-memt-turn` package is a separately selected `generic-cli`
provider. It restores scoped native Nano memory between Turns; it does not add
memory to Codex or Claude, replace LoopX state or change default hosts/models.
It needs a separately operated Nano service, client/tokenizer assets, reviewed
upstream licensing and an operator-owned configuration outside the task workspace.

```bash
python3 -m venv .venv-memt
. .venv-memt/bin/activate
python -m pip install -e . -e packages/loopx-memt-turn
loopx-memt-turn --config /srv/operator/memt.json --doctor
```

Doctor is a local preflight, not a network/inference or memory-quality test.
Enable only that profile and select its explicit host command for an admitted
Turn with an independent artifact validator. Disable with `enabled: false` in
that operator profile and remove the explicit host selection for subsequent
Turns. Retain snapshots and uncertain operation results for recovery. The MCP
server enforces effect scope; remembered text grants no authority. Real GPU,
App/Lark integration and outcome/cost benefit remain unqualified.

[Installation, licensing and recovery](../../../packages/loopx-memt-turn/README.md) ·
[#7028](https://github.com/loopx-project/loopx/pull/7028).

### Ego browser continuation and optional source reader

Normal skill delivery refreshes the scoped policy for an already installed Ego
skill. Within the same authorized task, successful inventory evidence that a
known Agent-created TaskSpace disappeared permits one recorded replacement;
normal-closure proof and a repeated permission question are unnecessary.
Human control, explicit pause/reservation, refused claim, login verification,
uncertain creation and unknown business effects remain protected.

```bash
loopx workflow-skills --install --format json
loopx workflow-skills --format json
```

This neither installs Ego nor adds an MCP server or browser permission. The
separate source reader remains optional: configure its reserved Page and origin
scope on the actual host, inspect returned source/digest, and remove that MCP
entry to disable it. Scope rollback uses the documented explicit HTTPS origins
and an idle-host reload. Skill uninstall does not remove the user's Ego browser.

[Configuration and lifecycle](../../integrations/ego-source-reader.md) ·
[#7034](https://github.com/loopx-project/loopx/pull/7034).

### Native Codex account handoff

In **Workspace settings → Native Codex accounts**, inspect the registered
accounts and observed quotas. Automatic switching, client restart and force quit
are explicit options. Force quit targets only the verified dedicated GPT client
instance after normal quit fails; another CLI/file owner still holds switching.
A failed/unknown quota read is not exhaustion. Existing manual account selection
and model settings remain authoritative.

Use **Check quota** and inspect the resulting account/status readback. Turn off
**Switch automatically when quota runs out** to disable automatic handoff;
turn off client restart/force quit independently when those effects are unwanted.
The running LoopX service observes this policy. It does not buy credits, consume
reset coupons or replay submitted business work.

```bash
loopx --version
loopx doctor --deep
loopx dashboard
```

[Workspace guide](../../guides/personal-workspace-user-guide.md) ·
[#7008](https://github.com/loopx-project/loopx/pull/7008).

### Research trajectory analysis

Prepare and inspect an authorized source pack in the existing Goal. Analysis
uses the selected supported host/account; loading history and reading status
remain model-free. The workbench displays episodes, citations and original result
coverage independently of model judgments. Provider failure does not erase the
original attempt or justify switching identity silently.

```bash
loopx benchmark trajectory-assess --input-json evidence-pack.json --output-dir .local/trajectory-analysis --format json
# Add --execute only after reviewing the source/account/cost consequences.
loopx benchmark trajectory-assessment-status --directory .local/trajectory-analysis/KEY --format json
loopx benchmark trajectory-assessment-cancel --directory .local/trajectory-analysis/KEY --format json
```

Not executing keeps the preview read-only. Cancel an active analysis by its
original directory; an uncertain operation needs original-result readback before
any explicit retry. Private traces stay within their source grant.

### 先升级，再看原业务是否继续

按上方命令安装固定 2.1.0，刷新 skills，核对版本与 doctor。已有安装沿原 owner 的
update 路径升级；CLI 与 App 分别读回。2.0.0 到本版没有新增状态迁移；旧 Markdown
或 legacy ownership 的 2.0 迁移边界继续有效，不启动第二个 writer。

本版修复原生 profile、路由和额度失败的安全恢复；只有已证明没有业务效果的失败
可以自动接续。已有工具效果、结果未知或后来纠正/停止时保留原恢复门；权限错误也需读回实际效果。
原接收 Agent 仍需执行、沿原受众回传；已读、adopt、Todo done 都不替代最终答复。
委派入场复核原 source，忙碌 lane 先可见，管家对话显示未回传交办。
已知限制：入场与 worker 的 source 复核未与最终 Task 完成组成原子事务。最后一次复核后
若 grant 被撤销，Task 仍可能先提交完成，随后操作才报告撤权。应保留 Task、操作和 Host
证据；撤权错误不证明没有效果，也不证明可安全重放。见
[独立撤权竞态审查](https://github.com/loopx-project/loopx/pull/7016#pullrequestreview-5609184153)。

### 目标、证据和界面入口

默认计划保留 Goal 与当前工作上下文；目标修订保留验收指导，各 Agent 独立采用。
Supporting outcomes 的要求和证据独立于 Todo 完成；没有 Todo 的原生重规划可正常结算。
研究历程、逐段分析、引用和定量结果更易查看，所选任务限制 Explore 证据窗口。
这些属于可见性与决策支持，不声明已测得长程收益或成本下降。

工作台的「快速导航」支持 Cmd+K / Ctrl+K，查找 Goal、已载入任务、原预览与结果；
打开只导航，不应用预览。设置区分机器默认与 Goal 覆盖。桌面允许手动查更新时继续
本地启动，区分传输/签名错误，并在 App 退出或崩溃后清理自己启动的私有服务。

### 按需启用，也能明确停用

- **内容制作与云生成**：进入已有 Goal 的「成果 → 内容作品」。从此 tag 显式安装
  可选 loopx-media、注册 manifest、运行 doctor；Blender 单独装 extra。云视频/图像
  在提交前查看上传、价格和用量后果，使用独立凭据；结果不明不重复付费提交。
  `loopx extension disable loopx-media --execute` 阻止新工作，旧操作沿原身份恢复。
  大画面构图保留完整素材；新修订移除 framing 可恢复原构图。产物不授予发布许可。
- **MemT Nano**：另装可选 host、客户端及独立服务，先审阅上游许可。operator 配置
  默认关闭，doctor 不证明网络/推理。只为已准入且有独立产物校验的 Turn 显式选择；
  配置设 enabled=false 并移除后续 host 选择即可停用。不是 Codex/Claude 原生记忆，
  不改变默认模型或状态；真实 GPU、App/飞书入口及收益未资格化。
- **Ego**：正常 workflow-skills 更新已有技能。同一授权任务中，成功 inventory
  确认已知自有工作区不存在后可记录一次替代，无需反复确认；真人接管、暂停、拒绝
  claim、登录与未知效果门保留。可选 source reader 仍须原宿主 MCP 配置，移除该项
  即停用；技能刷新不安装浏览器、不扩来源或权限。
- **账号切换**：工作区设置中检查账号/额度，按需开启自动切换、重启及强制退出。
  强制退出仅针对已核验的专用 GPT 实例；其他 CLI/文件占用仍会阻止切换。额度读取
  失败不是耗尽，不重放已提交业务。关闭自动切换可停用；重启/强退选项可分别关闭。
- **轨迹分析**：先核验 source pack、宿主账号与成本，再从原目录执行或取消。预览、
  状态与历史读取不调用模型；失败与未知结果保留原尝试，显式重试前先读回。
