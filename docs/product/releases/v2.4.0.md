# LoopX v2.4.0

Keep original work, evidence, and conversations connected after interruption across Core 2.4.0, Desktop App 2.4.0, and `dsh-loopx-plugin 0.1.1-beta.7`. Core 2.4.0 adds one-confirmation Goal creation, searchable loaded conversations, isolated Steward memory, probe-gated Steward monitors and protected PR merge confirmations, bidirectional Codex/Antigravity Steward failover, and runtime-composed `quota_settlement_plan_v2` Turn envelopes while retaining `quota_packet` as the ordinary public default in the tagged release. Installation, data compatibility, and optional host integrations retain their own checks.

## At a Glance

Create a Goal from Chat with one confirmation. Search loaded conversations back to the original message. Recover interrupted Tasks through their original Turn, lease, and receipt. Coordinate Steward monitors, protected PR merge confirmations, peer result reads, bidirectional Codex/Antigravity routing, Lark group/private channels, Desktop App 2.4.0, and `dsh-loopx-plugin 0.1.1-beta.7` against LoopX 2.4.0.

### Upgrade

The C1 source checkout and newly qualified runtime artifacts default to Complete Turn.
The published `v2.4.0` tag keeps its original default. Once a compatible signed
preview is available, use the [manual macOS upgrade path](../release-readiness.md#macos-preview-upgrade-across-the-c1-cutover)
from an earlier preview.

After `v2.4.0` appears on your current distribution channel, check and apply the upgrade through that installation's owner. Review the migration below first if your registry still uses the legacy paused or stopped status.

```bash
loopx update check
loopx update plan
loopx update apply
loopx --version
loopx doctor
```

## Release Decision

**Who should upgrade:** Personal Workspace, Desktop App, Steward, and Lark users wanting one-confirmation Goal creation, searchable conversations, probe-gated Steward monitors, protected PR merge previews, bidirectional Codex/Antigravity failover, or hardened Lark delivery, plus `dsh-loopx-plugin 0.1.1-beta.7` operators who require LoopX 2.4.0+. Teams with scripts mutating legacy registry `status` pause fields must update them first.

**What this release solves:** It reduces Goal creation to one confirmation, connects loaded chat search and saved Research answers to original Turns, enables probe-gated Steward monitoring and exact-head PR merge confirmation, adds isolated owner-private Steward memory and bidirectional Codex/Antigravity failover, and hardens Task/lease recovery, Desktop preview qualification, Lark delivery, and DSH 0.2.2 compatibility.

**Breaking changes:** Yes. Legacy registry `status` values `paused` and `stopped` are retired in favor of `activation.state` and Goal lifecycle commands with a backed-up migration ([#8431](https://github.com/loopx-project/loopx/pull/8431)); the unqualified compaction working memory experiment is retired with saved settings kept inert ([#8928](https://github.com/loopx-project/loopx/pull/8928)); and `dsh-loopx-plugin 0.1.1-beta.7` requires LoopX 2.4.0 or newer for the `quota receipt` reader ([#8899](https://github.com/loopx-project/loopx/pull/8899)). The `v2.4.0` tag keeps `quota_packet` as the ordinary unhosted JSON `quota should-run` default ([#9084](https://github.com/loopx-project/loopx/pull/9084)).

**How to verify:** Verify `2.4.0` and the owning Python environment in `loopx doctor`, confirm an existing Goal and original Task or new Chat draft, and confirm the read-only archive check passes after any registry migration.

**Contributors:** Release maintainer @huangruiteng and the 22 community contributors credited below (9 first merged contributions). [Community Contributors](#community-contributors)

## Optional Capability Activation & Use

### Remote task gateway

**Activation:** From a source checkout with a qualified Node runtime and `npm ci --ignore-scripts`, provision an isolated PostgreSQL authority schema, a restricted runtime role, a service policy, and TLS credentials (or start the self-hosted PostgreSQL/TLS Compose bundle in `examples/coordination/remote-authority-compose`). Start the service as shown below. Optional scheduler observation requires an explicit `remote_authority.enabled: true` for one registered Goal plus its HTTPS origin, verified tenant and store identity, scoped actor, stable existing probe Todo, and private CA path when applicable. [#8508](https://github.com/loopx-project/loopx/pull/8508), [#8765](https://github.com/loopx-project/loopx/pull/8765), [#8887](https://github.com/loopx-project/loopx/pull/8887)

**Validation:** Recover a known operation receipt with the example client and a prepared `command.json`. For the configured Goal, use `quota should-run` to read the bounded remote observation through the normal scheduler.

**Disable / rollback:** Set `remote_authority.enabled: false` on the affected Goal. Stop the listener and remove its access grants to retire the service. PostgreSQL retains its receipts.

**Authority boundary:** The scoped principal and restricted PostgreSQL role define task mutation rights. Host observation is read-only. For a resource-scoped read-only listener, select `loopx_remote_authority_scoped_read_policy_v1` and authorize each exact Goal lifetime, Todo, and audience. Supply its original creation or first-adoption receipt; absent proof stays unavailable. That listener rejects writes and withholds free-form notes, lease keys, and global provider revisions. Remove the matching grant or ACL entry to revoke subsequent admissions. Local admission, owner Stop, and quota remain authoritative. [#8861](https://github.com/loopx-project/loopx/pull/8861)

**Docs:** [Remote authority task service](https://github.com/loopx-project/loopx/blob/v2.4.0/docs/reference/remote-authority-task-service-v0.md)

```bash
node --experimental-strip-types examples/coordination/remote-authority-service.ts \
  --policy "$SERVICE_POLICY" --cert "$TLS_CERT" --key "$TLS_KEY" --host 127.0.0.1 --port 8443
# In the scoped client environment, with the service credential loaded privately:
node --experimental-strip-types examples/coordination/remote-authority-client.ts \
  --endpoint "$SERVICE_HTTPS_ORIGIN" --ca "$TLS_CA" --recover < command.json
loopx --format json quota should-run --goal-id "$LOOPX_GOAL_ID" --agent-id "$LOOPX_AGENT_ID"
```

### Complete Turn context for external hosts

**C1 source checkout** JSON `quota should-run` delivers `loopx_turn_envelope_v1` by default, including with context and delta delivery off. Remove `--complete-turn` and `--turn-envelope`. An ordinary CLI consumer reads `cli_channel.next_cli_actions` in the full decision. A host that declares `--runtime-profile generic_cli` and binds Agent, Todo and Turn reads the returned `quota_settlement_plan_v2` when admitted. Its `--settle-turn --settlement-receipt` step uses the original identity. For a private progressive capture, supply a fresh Turn ID, an unused capture directory and `--context-delivery on --delta-delivery off`.

**Validation:** Confirm `loopx_turn_envelope_v1` on the returned or saved decision. A progressive response can return `context_capture_navigation_v1`; follow its pinned reader and verify the original digest and Turn identity. Finish the required reads, then follow the actions or plan returned for that Turn.

**Disable / rollback:** Use `--context-delivery off --delta-delivery off` for inline v1. To run the earlier live contract, follow the compatible installation rollback procedure and verify that the target can read the current authority state. Preserve digest-bound commands for existing captures.

**Authority boundary:** The current Goal, Agent, admission, permissions, required reads, hard-lease fence, and Stop conditions govern the Turn.

**Docs:** [Current Turn envelope reference](../../reference/protocols/turn-envelope-v0.md)

```bash
loopx --format json quota should-run --goal-id "$LOOPX_GOAL_ID" \
  --agent-id "$LOOPX_AGENT_ID" --turn-instance-id "$LOOPX_TURN_ID" \
  --context-delivery on --delta-delivery off --decision-output-dir ./complete-001
```

The reader's JSON Pointer selects a field inside the captured JSON; it is not a filesystem path. Copy the returned current reader reference into `CAPTURE_READER`. Listing and selecting the current capture does not require reading an older delta baseline or creating another admission.

```bash
loopx --format json quota context-read --reference-file "$CAPTURE_READER" --list --list-depth 2
loopx --format json quota context-read --reference-file "$CAPTURE_READER" --select /selected_todo
```

A selected Todo is only part of the contract. Read its applicable Goal requirements, constraints, and required sources before work. Keep the original Turn, capture, and settlement identity after compaction or recovery. A diagnostic-only recovery response grants no execution.

### 升级决策

**谁需要升级：** 在 Chat 创建 Goal 或检索原消息、使用桌面端或已安装工作台恢复任务、依赖管家监控/PR 合并确认/双向切换/飞书收发的用户可优先升级；`dsh-loopx-plugin 0.1.1-beta.7` 用户必须同时使用 LoopX 2.4.0 及以上版本。仍有脚本编辑旧 registry 暂停状态的团队需先迁移调用。

**如何验证：** 确认版本为 `2.4.0` 与 `loopx doctor` 所属环境正常，打开既有 Goal 与原任务或在 Chat 确认新草稿，并确保迁移后的只读检查命令通过。

### 可选能力启用与使用

#### Remote task gateway

**启用：** 从源码检出准备合格的 Node、`npm ci --ignore-scripts`、隔离 PostgreSQL authority schema、受限角色、服务策略与 TLS 证书，运行服务示例（或使用 `examples/coordination/remote-authority-compose` 自托管 Compose 部署包）。调度器观测另需在某个已注册 Goal 显式设置 `remote_authority.enabled: true`，绑定 HTTPS origin、已核验的 tenant 和 store identity、授权 Agent、既有 probe Todo 和所需私有 CA。 [#8508](https://github.com/loopx-project/loopx/pull/8508), [#8765](https://github.com/loopx-project/loopx/pull/8765), [#8887](https://github.com/loopx-project/loopx/pull/8887)

**验证：** 用示例客户端和已准备的 `command.json` 读取既有操作回执。通过 `quota should-run` 查看当前 Goal 的远程只读观测。

**停用 / 回退：** 在该 Goal 设置 `remote_authority.enabled: false`。停止监听器并撤销访问授权可停用服务。PostgreSQL 保留已写回执。

**权限边界：** 远程写入由受限 principal、数据库角色和策略控制。Host 观测提供只读输入。逐资源只读 listener 选择 `loopx_remote_authority_scoped_read_policy_v1`，精确授权 Goal lifetime、Todo 与接收者，并提供原创建或首次采用回执；缺少来源证明时保持不可用。该 listener 拒绝写命令，不返回自由文本、租约密钥或全局 provider revision。移除对应 grant 或 ACL 项可撤销后续准入，继续遵循本地准入、Stop 和额度约束。 [#8861](https://github.com/loopx-project/loopx/pull/8861)

**文档：** [远程任务网关](https://github.com/loopx-project/loopx/blob/v2.4.0/docs/reference/remote-authority-task-service-v0.md)

```bash
node --experimental-strip-types examples/coordination/remote-authority-service.ts \
  --policy "$SERVICE_POLICY" --cert "$TLS_CERT" --key "$TLS_KEY" --host 127.0.0.1 --port 8443
# 另在受授权的客户端环境私下加载服务凭据后执行：
node --experimental-strip-types examples/coordination/remote-authority-client.ts \
  --endpoint "$SERVICE_HTTPS_ORIGIN" --ca "$TLS_CA" --recover < command.json
loopx --format json quota should-run --goal-id "$LOOPX_GOAL_ID" --agent-id "$LOOPX_AGENT_ID"
```

#### Complete Turn context for external hosts

**C1 源码检出**的 JSON `quota should-run` 默认交付 `loopx_turn_envelope_v1`，关闭上下文和差分交付时也使用同一契约。移除 `--complete-turn` 和 `--turn-envelope`。普通 CLI 从完整决策读取 `cli_channel.next_cli_actions`。声明 `--runtime-profile generic_cli` 并绑定 Agent、Todo 与 Turn 的 Host 在准入后读取返回的 `quota_settlement_plan_v2`，其 `--settle-turn --settlement-receipt` 步骤沿用原身份。需要私有渐进捕获时，提供新的 Turn ID、尚不存在的捕获目录和 `--context-delivery on --delta-delivery off`。

**验证：** 在返回或保存的决策中确认 `loopx_turn_envelope_v1`。若返回 `context_capture_navigation_v1`，用固定 reader 核对原摘要与 Turn 身份。完成必读内容，再执行本轮返回的动作或计划。

**停用 / 回退：** 用 `--context-delivery off --delta-delivery off` 返回内联 v1。需恢复旧实时契约时，使用兼容的安装回退流程，并先核验目标能读取当前权威状态。保留既有捕获的摘要绑定命令。

**权限边界：** 继续遵循本次 Goal、Agent、准入、权限、硬租约护栏、必读内容和 Stop 条件。

**文档：** [当前 Turn envelope](../../reference/protocols/turn-envelope-v0.md)

```bash
loopx --format json quota should-run --goal-id "$LOOPX_GOAL_ID" \
  --agent-id "$LOOPX_AGENT_ID" --turn-instance-id "$LOOPX_TURN_ID" \
  --context-delivery on --delta-delivery off --decision-output-dir ./complete-001
```

reader 的 JSON Pointer 指向捕获 JSON 内的字段，不是文件路径。将返回的当前 reader 引用赋给 `CAPTURE_READER` 后可目录查看或选读；读取当前捕获不要求先读旧差分基线，也不需要重新准入。

```bash
loopx --format json quota context-read --reference-file "$CAPTURE_READER" --list --list-depth 2
loopx --format json quota context-read --reference-file "$CAPTURE_READER" --select /selected_todo
```

选中的 Todo 只占契约的一部分。工作前仍需读取适用的 Goal 要求、限制与必读来源；压缩或恢复后保留原 Turn、capture 和结算身份。仅用于诊断的恢复结果不授予执行权。

**启用：** 在已获授权的本地安装中按需安装并启用内置 `loopx-lark`，然后在 Core 工作台的 Lark 设置中用已获授权的账号绑定私聊。支持国内飞书和国际版 Lark 配置链接。 [#8871](https://github.com/loopx-project/loopx/pull/8871)

**验证：** 读取 provider doctor。用自己已配置的私聊发出获授权的测试请求，确认回复、管家快捷卡片或 Turn 作用域原生图片回到同一会话。重连后核对排队消息只出现一次并回到原会话。恢复旧版已完成回复中的图片时，worker 用原摘要核验操作者暂存的快照。保留的原文字送达回执用于确认是哪条回复。请在原私聊核对补发的图片。获授权的操作者也可读取同一 Turn 的历史补图状态和独立媒体送达回执。通过记录核验时，要同时确认状态为 `delivered` 且媒体回执与原私聊匹配。未确认的送达继续待核。 [#8999](https://github.com/loopx-project/loopx/pull/8999)

**停用 / 回退：** 断开已配置的会话。退役本地 provider 时执行 disable，并停止还在运行的采集进程。

**权限边界：** 沿用既有会话绑定、provider 身份和授权范围。Steward 快捷卡片只读，群聊保持受限。Provider 确认来源消息已撤回时，取消排队中的私聊管家卡片。来源暂时查不到时，卡片继续等待。历史图片恢复沿原已完成 Turn 和 provider 身份执行。 [#8847](https://github.com/loopx-project/loopx/pull/8847)

**文档：** [Lark 扩展生命周期](https://github.com/loopx-project/loopx/blob/v2.4.0/docs/reference/extensions.md#runtime-lifecycle)

loopx extension install --bundled loopx-lark --execute --format json
loopx extension enable loopx-lark --execute --format json
loopx extension doctor loopx-lark --execute --format json
# 退役本地 provider 时执行：
loopx extension disable loopx-lark --execute --format json

#### Private backup inspection

**启用：** 在 Settings → Capability Center → device defaults → Configuration backup and recovery 选择 Full archive inspection，提供原归档及匹配的外部 manifest。不支持的服务或平台保持不可用。下方 CLI 按次调用。先预览项目及所选配置范围的私有完整备份，再在现有授权内创建；保留匹配的 archive、外部 manifest 和兼容版本。 [#8864](https://github.com/loopx-project/loopx/pull/8864)

**验证：** 先验证文件对，再提取。只有 `--execute` 创建新的隔离检查目录，不激活 authority 或启动 Host；核对 included 和 missing 范围。

**停用 / 回退：** 停止调用或省略 `--execute`，已有备份继续私有保留。重装旧运行时不会撤销新版数据写入；目标读取器无法核验时保持当前运行时，后续数据操作沿原恢复 owner。

**权限边界：** 归档和历史租约是证据，不是新的执行授权。现代再激活另需身份、未决 effect 与准入检查；不能把旧归档直接覆盖到现用状态。

**文档：** [配置备份与恢复](https://github.com/loopx-project/loopx/blob/v2.4.0/docs/reference/configuration-backup.md#full-state-recovery-after-cold-import)、[Agent 原地升级](https://github.com/loopx-project/loopx/blob/v2.4.0/docs/guides/agent-upgrade.md)

```bash
loopx backup-state --project "$PROJECT_ROOT" --current-project-only \
  --configuration-goal-id "$LOOPX_GOAL_ID" --no-automations --no-skills \
  --output-dir "$PRIVATE_BACKUP_DIR"
# 核对预览后，在现有授权内重复命令并加 --execute。
loopx backup-state verify --archive "$BACKUP_ARCHIVE" --manifest "$BACKUP_MANIFEST" \
  --destination "$NEW_INSPECTION_DIR"
```

#### Scoped GitHub PR signal monitors

**启用：** 在已绑定的私聊 App 或飞书 `chat_root` 管家会话中创建或更新 `continuous_monitor` 待办时，显式传入稳定 `target_key` 与 `signal_scope`（`schema_version: "steward_signal_monitor_scope_v0"`、`include_portfolio`、`include_inbox` 及可选 `pr_filter` 条件，如 `exclude_drafts`、`exclude_conflicting`、`effective_verdicts`、`required_approver_declarations`、`author_mode`/`authors`、`min_stalled_hours`）。 [#9074](https://github.com/loopx-project/loopx/pull/9074), [#9182](https://github.com/loopx-project/loopx/pull/9182)

**验证：** 确认作用域已写入 `steward-monitors/<goal_id>/scopes/<target_key>.json`，`StewardMonitor` 对每个监控独立聚合并按精确 `session_id` / `chat_root` 投递单篇可读汇总（`steward_monitor_report_delivery_v0`），互不串扰唤醒。需注意在更新既有监控待办的 `signal_scope` 时必须附带非空的待办字段修改（如摘要、周期或 `stop_condition`），仅改作用域而不改待办本体会按现行基线返回 `Todo update requires a non-empty patch`。

**停用 / 回退：** 在管家对话中暂停或停止对应监控待办（`pause` / `stop`），或在 CLI 将该待办状态切离 `open`（`loopx todo update --goal-id "$LOOPX_GOAL_ID" --todo-id "$MONITOR_TODO_ID" --status blocked` 或 `deferred` / `done`），随后通过 `loopx todo list --goal-id "$LOOPX_GOAL_ID"` 读回确认状态不再为 `open` 且停止到期轮询。切勿通过删除 `steward-monitors/<goal_id>/scopes/<target_key>.json` 替代停用——对仍处于 `open` 的监控删除作用域文件会使其回退为无过滤默认观察范围；按上述方式暂停/完成后，作用域与快照文件会保留以供后续恢复。

**权限边界：** `steward_managed_mode.ts` 对未知 `signal_scope` / `pr_filter` 字段 fail-closed 拒绝；GitHub 外部探针仅只读采样且异常时不覆盖最近已核验哈希；报告严格投递到精确绑定的 `session_id` / `chat_root`，不授予仓库写或 PR 合并权限。

**文档：** [管家监控控制器](https://github.com/loopx-project/loopx/blob/v2.4.0/loopx/capabilities/native_chat/steward_monitor.py)、[管家受控模式](https://github.com/loopx-project/loopx/blob/v2.4.0/loopx/control_plane/collaboration/steward_managed_mode.ts)

```bash
loopx todo list --goal-id "$LOOPX_GOAL_ID"
cat "$LOOPX_RUNTIME_ROOT/steward-monitors/$LOOPX_GOAL_ID/scopes/$MONITOR_TARGET_KEY.json"
loopx todo update --goal-id "$LOOPX_GOAL_ID" --todo-id "$MONITOR_TODO_ID" --status blocked
loopx todo list --goal-id "$LOOPX_GOAL_ID"
```
