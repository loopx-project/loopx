# LoopX v2.4.0

Keep the original work and its evidence connected after interruption. Core 2.4.0 adds one-confirmation Goal creation, searchable loaded conversations and more precise task recovery. Installation, data compatibility and optional host integrations retain their own checks.

## At a Glance

Create a Goal from a conversation with one confirmation. Find the original message in a loaded chat. Recover existing work through its original task and receipt after an interrupted run.

### Upgrade

After `v2.4.0` appears on your current distribution channel, check and apply the upgrade through that installation's owner. Review the migration below first if your registry still uses the legacy paused or stopped status.

```bash
loopx update check
loopx update plan
loopx update apply
loopx --version
loopx doctor
```

### Highlights

- **Create a Goal from Chat.** Review the draft and confirm it once. The workspace creates the Goal and opens the corresponding conversation when the required runtime and permissions are ready. [#8780](https://github.com/loopx-project/loopx/pull/8780)
- **Return to the original message.** Search a loaded conversation and open the matching message in context. [#8676](https://github.com/loopx-project/loopx/pull/8676)
- **Recover existing work in an installed workspace.** Discover the Manager through the installed CLI and resume the original authorized Task through its existing record. [#8615](https://github.com/loopx-project/loopx/pull/8615), [#8802](https://github.com/loopx-project/loopx/pull/8802), [#8830](https://github.com/loopx-project/loopx/pull/8830)
- **Keep private Lark replies tied to their conversation.** The existing private connector preserves queued messages on reconnect, exposes read-only Steward shortcuts and can return verified native images. [#8668](https://github.com/loopx-project/loopx/pull/8668), [#8695](https://github.com/loopx-project/loopx/pull/8695), [#8741](https://github.com/loopx-project/loopx/pull/8741)
- **Evaluate a remote task gateway in an isolated environment.** The source-checkout example serves scoped task commands over authenticated TLS, with per-Goal opt-in for a read-only scheduler observation. [#8508](https://github.com/loopx-project/loopx/pull/8508), [#8765](https://github.com/loopx-project/loopx/pull/8765)
- **Read a saved result after reopening.** Research results stay in place across desktop reopening. Opening a selected saved answer reads its original Turn, and quoted messages retain readable Markdown. [#8868](https://github.com/loopx-project/loopx/pull/8868), [#8863](https://github.com/loopx-project/loopx/pull/8863), [#8880](https://github.com/loopx-project/loopx/pull/8880), [#8892](https://github.com/loopx-project/loopx/pull/8892)

## Release Decision

**Who should upgrade:** Chat users who create Goals or revisit source messages, operators resuming installed work, and users relying on the private Lark connector benefit directly. Teams with legacy registry tooling should first update it to the current activation contract.

**What this release solves:** It opens the conversation and Goal after one user confirmation, makes already-loaded messages searchable and improves recovery of the original work when a host or connector is interrupted.

**Breaking changes:** Yes. Legacy registry `status` values `paused` and `stopped` are retired. Use `activation.state` and the Goal lifecycle commands for pause and resume. The backed-up migration preserves pause intent and returns the original registry backup path. For direct pip/source installs and restored backups, review the read-only check before running the owner-authorized migration. [#8431](https://github.com/loopx-project/loopx/pull/8431)

**How to verify:** Verify `2.4.0` and the owning environment, then open an existing Goal and its original task or confirm a new draft in Chat. For a registry with legacy metadata, the following check must pass after migration.

**Contributors:** Release maintainer @huangruiteng and the 19 contributors credited below. [Community Contributors](#community-contributors)

## State Kernel & Control Plane

- Recovery retains the original Turn and debit identity while rechecking a fresh selection's gates. A validated Todo-less original Turn can recover its own receipt without a second spend. [#8894](https://github.com/loopx-project/loopx/pull/8894), [#8860](https://github.com/loopx-project/loopx/pull/8860), [#8900](https://github.com/loopx-project/loopx/pull/8900)
- Ordinary Todo edits preserve a compatible stored declaration. Once actual new fields require a newer reader, archive rollback checks the target's Todo read before switching; a failed check leaves the current runtime and data in place. [#8902](https://github.com/loopx-project/loopx/pull/8902), [#8906](https://github.com/loopx-project/loopx/pull/8906)
- Goal storage import follows the registered source and serializes the final source check with registry writers. Global discovery does not substitute another runtime for that source. An already canonical Goal needs no cold import. [#8864](https://github.com/loopx-project/loopx/pull/8864)
- Installed task recovery uses the original execution lease and receipt through the shared task lifecycle. Current host dispatch reads the complete authorized work contract, and standalone heartbeat settlement uses the installed route. [#8615](https://github.com/loopx-project/loopx/pull/8615), [#8707](https://github.com/loopx-project/loopx/pull/8707), [#8827](https://github.com/loopx-project/loopx/pull/8827)
- PostgreSQL authority archives preserve checkpoint history beyond 20,000 commits for backup and restore. Use the existing provider administration path for recovery. [#8759](https://github.com/loopx-project/loopx/pull/8759)

## Optional Capability Activation & Use

### Remote task gateway

**Activation:** From a source checkout with a qualified Node runtime and `npm ci --ignore-scripts`, provision an isolated PostgreSQL authority schema, a restricted runtime role, a service policy and TLS credentials. Start the service as shown below. Optional scheduler observation requires an explicit `remote_authority.enabled: true` for one registered Goal plus its HTTPS origin, verified tenant and store identity, scoped actor, stable existing probe Todo and private CA path when applicable.

**Validation:** Recover a known operation receipt with the example client and a prepared `command.json`. For the configured Goal, use `quota should-run` to read the bounded remote observation through the normal scheduler.

**Disable / rollback:** Set `remote_authority.enabled: false` on the affected Goal. Stop the listener and remove its access grants to retire the service. PostgreSQL retains its receipts.

**Authority boundary:** The scoped principal and restricted PostgreSQL role define task mutation rights. Host observation is read-only. For a resource-scoped read-only listener, select `loopx_remote_authority_scoped_read_policy_v1` and authorize each exact Goal lifetime, Todo and audience. Supply its original creation or first-adoption receipt; absent proof stays unavailable. That listener rejects writes and withholds free-form notes, lease keys and global provider revisions. Remove the matching grant or ACL entry to revoke subsequent admissions. Local admission, owner Stop and quota remain authoritative. [#8861](https://github.com/loopx-project/loopx/pull/8861)

**Docs:** [Remote authority task service](https://github.com/loopx-project/loopx/blob/v2.4.0/docs/reference/remote-authority-task-service-v0.md)

```bash
node --experimental-strip-types examples/coordination/remote-authority-service.ts \
  --policy "$SERVICE_POLICY" --cert "$TLS_CERT" --key "$TLS_KEY" --host 127.0.0.1 --port 8443
# In the scoped client environment, with the service credential loaded privately:
node --experimental-strip-types examples/coordination/remote-authority-client.ts \
  --endpoint "$SERVICE_HTTPS_ORIGIN" --ca "$TLS_CA" --recover < command.json
loopx --format json quota should-run --goal-id "$LOOPX_GOAL_ID" --agent-id "$LOOPX_AGENT_ID"
```

### Complete Turn context for external hosts

**Activation:** Add `--complete-turn` to JSON `quota should-run` in an external host that can consume the complete v1 contract. Give it an explicit fresh Turn ID and a writable capture directory.

**Validation:** Confirm `loopx_turn_envelope_v1` on the returned or saved decision. Finish its required Goal/context reads and follow the same Turn's execution and settlement contract. Follow the pinned reader supplied with a progressive response and verify the original digest and Turn identity.

**Disable / rollback:** Omit `--complete-turn` from subsequent requests to return to the prior context path. Keep the original digest-bound commands for existing captures.

**Authority boundary:** The current Goal, Agent, admission, permissions, required reads and Stop conditions govern the Turn.

**Docs:** [Turn envelope reference](https://github.com/loopx-project/loopx/blob/v2.4.0/docs/reference/protocols/turn-envelope-v0.md)

```bash
loopx --format json quota should-run --goal-id "$LOOPX_GOAL_ID" \
  --agent-id "$LOOPX_AGENT_ID" --turn-instance-id "$LOOPX_TURN_ID" \
  --complete-turn --decision-output-dir ./complete-001
```

The reader's JSON Pointer selects a field inside the captured JSON; it is not a filesystem path. Copy the returned current reader reference into `CAPTURE_READER`. Listing and selecting the current capture does not require reading an older delta baseline or creating another admission.

```bash
loopx --format json quota context-read --reference-file "$CAPTURE_READER" --list --list-depth 2
loopx --format json quota context-read --reference-file "$CAPTURE_READER" --select /selected_todo
```

A selected Todo is only part of the contract. Read its applicable Goal requirements, constraints and required sources before work. Keep the original Turn, capture and settlement identity after compaction or recovery. A diagnostic-only recovery response grants no execution.

### Material wave rerank preview

**Activation:** Supply a request with ordered material references and exact-read annotations to `plan-wave-rerank`.

**Validation:** Review proposed ordering, protected items and coverage of the exact input. The preview uses the material lifecycle contract.

**Disable / rollback:** Stop invoking the preview or discard its output. If an operator separately applies a plan, recover through the original material lifecycle rollback receipt.

**Authority boundary:** The command is stateless. Applying or rolling back a ranking uses the material owner's authorized operation and current revision.

**Docs:** [Material lifecycle capability](https://github.com/loopx-project/loopx/blob/v2.4.0/loopx/capabilities/material_lifecycle/README.md)

```bash
loopx material-lifecycle architecture --format json
loopx material-lifecycle plan-wave-rerank --input request.json --format json
```

### Private Lark conversations

**Activation:** In an authorized local installation, install the bundled `loopx-lark` provider if needed, then enable that provider and connect the private conversation in the workspace's Lark settings using its existing authorized account.

**Validation:** Read the provider doctor result. From your own configured private conversation, send an authorized test request and verify that the reply, shortcut or returned image appears in that same conversation. After a reconnect, check that a queued request appears once and reaches its original destination.

**Disable / rollback:** Disconnect the configured conversation. To retire this local provider, disable it and stop its host-managed collector if one is running.

**Authority boundary:** The connector uses the established conversation binding, provider identity and granted permissions. The Steward shortcuts are read-only. Image delivery follows the original private reply scope.

**Docs:** [The Lark extension lifecycle](https://github.com/loopx-project/loopx/blob/v2.4.0/docs/reference/extensions.md#runtime-lifecycle)

```bash
loopx extension install --bundled loopx-lark --execute --format json
loopx extension enable loopx-lark --execute --format json
loopx extension doctor loopx-lark --execute --format json
# To retire the local provider:
loopx extension disable loopx-lark --execute --format json
```

### Staged benchmark CLI activation

**Activation:** An existing authorized Docker benchmark controller stages a qualified source revision into its versioned release directory and previews its existing owned launcher with `activate_cli_source(..., execute=False)`. Provide the exact run identity, archive digest and required source, native receipt and current Stop callbacks. Revalidate those inputs before any explicitly authorized execution.

**Validation:** Run the source-checkout receipt-readback test below. For an authorized actual change, follow the source identity and launcher readback and observe the next real Host input separately.

**Disable / rollback:** Omit activation to keep the current launcher. For an interrupted switch, reconcile the original owned receipt with `reconcile=True`. An explicitly authorized `repair="old"` uses current control and reverified source identity.

**Authority boundary:** The existing controller owns the worker lock, Stop policy and finite allowance. The activation changes its future CLI subprocesses and requires separate execution authorization.

**Docs:** [Host CLI source activation](https://github.com/loopx-project/loopx/blob/v2.4.0/docs/reference/protocols/host-cli-source-activation-v0.md)

```bash
uv run --extra test python -m pytest -q tests/control_plane/test_cli_source_activation_readback.py
```

### Private backup inspection

**Activation:** In Settings → Capability Center → device defaults → Configuration backup and recovery, choose Full archive inspection for the original archive and matching external manifest. Unsupported services/platforms leave the operation unavailable. The CLI operations below are per-command. Preview a private full-state backup for the project and the selected configuration cohort before creating it. Retain the matching archive, external manifest and compatible package. [#8864](https://github.com/loopx-project/loopx/pull/8864)

**Validation:** Verify the pair before extraction. Only `--execute` creates the new inert inspection directory; it does not activate an authority or start a Host. Review included and missing sources.

**Disable / rollback:** Stop invoking the commands or omit `--execute`. Preserve retained backups privately. Reinstalling an older runtime does not reverse newer data writes; keep the current runtime when a target reader cannot verify them, and use the owning recovery process for further changes.

**Authority boundary:** An archive or restored historical lease is evidence, not a new execution grant. Full modern reactivation requires its own identity, pending-effect and admission checks. Never unpack an old archive over live state.

**Docs:** [Configuration backup and recovery](https://github.com/loopx-project/loopx/blob/v2.4.0/docs/reference/configuration-backup.md#full-state-recovery-after-cold-import), [Agent-assisted in-place upgrade](https://github.com/loopx-project/loopx/blob/v2.4.0/docs/guides/agent-upgrade.md)

```bash
loopx backup-state --project "$PROJECT_ROOT" --current-project-only \
  --configuration-goal-id "$LOOPX_GOAL_ID" --no-automations --no-skills \
  --output-dir "$PRIVATE_BACKUP_DIR"
# After reviewing the plan and within the existing authorization, repeat with --execute.
loopx backup-state verify --archive "$BACKUP_ARCHIVE" --manifest "$BACKUP_MANIFEST" \
  --destination "$NEW_INSPECTION_DIR"
```

## Install / Update

For a new PyPI install, run the following once `2.4.0` is available, then restart the agent host.

```bash
python3 -m pip install --upgrade 'loopx==2.4.0'
loopx workflow-skills --install
loopx slash-commands --install
loopx doctor
```

For an existing pip, pipx or archive install, use the explicit update commands above. To revalidate enabled extensions, use the existing operator path.

```bash
loopx extension doctor --all-enabled --execute
```

## Verification boundaries

- The package version and tag are `2.4.0` / `v2.4.0`. Confirm availability through the current installation owner, then verify the same Goal and original task after upgrading.
- Check ordinary File/SQLite write compatibility, original receipts and lease records, and rejection of a newer incompatible field set separately. Historical reads from an inert backup do not reactivate a modern Goal.
- Final clean commit/tree/version/tag, complete packaged pages, native Host, platform artifacts, real-model checks, the personal illustrated guide and public distribution remain separately evidenced under the [release contract](https://github.com/loopx-project/loopx/blob/v2.4.0/docs/product/release-readiness.md). This usage guide is not a qualification receipt.
- This release describes reliability and workflow changes. No net long-horizon outcome gain is asserted.

## 中文摘要

本页说明 Core 2.4.0 的升级与可选能力用法：在对话中确认 Goal、回到原消息，并按原任务及回执恢复工作。安装、数据兼容与可选 Host 集成分别核验。

在对话里确认一次即可创建 Goal。搜索已载入的会话并回到原消息。中断后可通过原任务和原回执继续。

### 升级

现有安装渠道提供 2.4.0 后，依次执行 `loopx update check`、`loopx update plan`、`loopx update apply`，再运行 `loopx --version` 和 `loopx doctor`。仍使用旧暂停字段的 registry 先核对下方迁移路径。

### 主要变化

- 在 Chat 检查并确认 Goal 草稿一次，运行环境和权限就绪后打开对应会话。搜索也可以从已载入会话直接定位原消息。 [#8780](https://github.com/loopx-project/loopx/pull/8780), [#8676](https://github.com/loopx-project/loopx/pull/8676)
- 已安装工作台可经 CLI 发现 Manager，按原任务记录继续已授权工作。 [#8615](https://github.com/loopx-project/loopx/pull/8615), [#8802](https://github.com/loopx-project/loopx/pull/8802), [#8830](https://github.com/loopx-project/loopx/pull/8830)
- 现有飞书私聊连接器在重连时保留排队消息，提供 Steward 只读快捷卡片，并支持带回读确认的原生图片回复。 [#8668](https://github.com/loopx-project/loopx/pull/8668), [#8695](https://github.com/loopx-project/loopx/pull/8695), [#8741](https://github.com/loopx-project/loopx/pull/8741)
- 源码检出可在隔离环境试用经过 TLS 认证的远程任务网关，并为指定 Goal 显式开启调度器只读观测。 [#8508](https://github.com/loopx-project/loopx/pull/8508), [#8765](https://github.com/loopx-project/loopx/pull/8765)
- 重开桌面时保留原研究结果，打开指定已保存回答时读回其原 Turn；引用消息继续使用清晰的 Markdown 正文。 [#8868](https://github.com/loopx-project/loopx/pull/8868), [#8863](https://github.com/loopx-project/loopx/pull/8863), [#8880](https://github.com/loopx-project/loopx/pull/8880), [#8892](https://github.com/loopx-project/loopx/pull/8892)

- 保留重规划历史中的主动监控事项。唯一范围内任务被依赖阻塞时等待，已被替换的 heartbeat 回执会在后续执行前拒绝。 [#8672](https://github.com/loopx-project/loopx/pull/8672), [#8511](https://github.com/loopx-project/loopx/pull/8511), [#8708](https://github.com/loopx-project/loopx/pull/8708)

### 升级决策

**谁需要升级：**在 Chat 创建 Goal 或回看原消息、使用已安装运行时恢复工作、通过飞书私聊收发的用户可优先升级。仍有脚本直接编辑旧 registry 状态的团队先迁移调用。

**解决了什么：**把创建 Goal 和打开对应会话压到一次确认，并改善已载入消息检索及 Host 或连接器中断后的原任务恢复。

**是否有破坏性变更：**有。Registry 停用旧 `status: paused/stopped`，暂停与恢复统一使用 `activation.state` 和 Goal lifecycle 命令。通过备份迁移保留原暂停意图。直接 pip 安装、源码运行或恢复旧备份后，可先只读检查，持有相应权限的 owner 再执行迁移。 [#8431](https://github.com/loopx-project/loopx/pull/8431)

**如何验证：**确认版本为 2.4.0 和 `loopx doctor` 状态，打开既有 Goal 与原任务，或在 Chat 确认新草稿。迁移旧 registry 后确认英文段的只读命令通过。

**贡献者：**发布维护者 @huangruiteng 与下文列出的 19 位社区贡献者。 [社区贡献者](#社区贡献者)

### 状态内核与控制面

- 恢复原 Turn 和扣额身份时仍核对新选择的门禁；已验证的无 Todo 原 Turn 可以读取自己的回执，避免再次扣额。 [#8894](https://github.com/loopx-project/loopx/pull/8894), [#8860](https://github.com/loopx-project/loopx/pull/8860), [#8900](https://github.com/loopx-project/loopx/pull/8900)
- 普通 Todo 修改保留兼容声明；实际新字段需要新版读取器时，归档回退先由目标版本读取 Todo，失败则保留当前运行时与数据。 [#8902](https://github.com/loopx-project/loopx/pull/8902), [#8906](https://github.com/loopx-project/loopx/pull/8906)
- 存储导入沿已注册的真实源执行，并与 registry 写方串行完成最后检查；全局发现不以其他 runtime 代替源。已采用 canonical authority 的 Goal 无需再次导入。 [#8864](https://github.com/loopx-project/loopx/pull/8864)

### 可选能力启用与使用

#### Remote task gateway

**启用：**从源码检出准备合格的 Node、`npm ci --ignore-scripts`、隔离 PostgreSQL authority schema、受限角色、服务策略与 TLS 证书，运行服务示例。调度器观测另需在某个已注册 Goal 显式设置 `remote_authority.enabled: true`，绑定 HTTPS origin、已核验的 tenant 和 store identity、授权 Agent、既有 probe Todo 和所需私有 CA。

**验证：**用示例客户端和已准备的 `command.json` 读取既有操作回执。通过 `quota should-run` 查看当前 Goal 的远程只读观测。

**停用 / 回退：**在该 Goal 设置 `remote_authority.enabled: false`。停止监听器并撤销访问授权可停用服务。PostgreSQL 保留已写回执。

**权限边界：**远程写入由受限 principal、数据库角色和策略控制。Host 观测提供只读输入。逐资源只读 listener 选择 `loopx_remote_authority_scoped_read_policy_v1`，精确授权 Goal lifetime、Todo 与接收者，并提供原创建或首次采用回执；缺少来源证明时保持不可用。该 listener 拒绝写命令，不返回自由文本、租约密钥或全局 provider revision。移除对应 grant 或 ACL 项可撤销后续准入，继续遵循本地准入、Stop 和额度约束。 [#8861](https://github.com/loopx-project/loopx/pull/8861)

**文档：**[远程任务网关](https://github.com/loopx-project/loopx/blob/v2.4.0/docs/reference/remote-authority-task-service-v0.md)

```bash
node --experimental-strip-types examples/coordination/remote-authority-service.ts \
  --policy "$SERVICE_POLICY" --cert "$TLS_CERT" --key "$TLS_KEY" --host 127.0.0.1 --port 8443
# 另在受授权的客户端环境私下加载服务凭据后执行：
node --experimental-strip-types examples/coordination/remote-authority-client.ts \
  --endpoint "$SERVICE_HTTPS_ORIGIN" --ca "$TLS_CA" --recover < command.json
loopx --format json quota should-run --goal-id "$LOOPX_GOAL_ID" --agent-id "$LOOPX_AGENT_ID"
```

#### Complete Turn context for external hosts

**启用：**可消费完整 v1 契约的外部 Host 在 JSON `quota should-run` 上显式传入 `--complete-turn`，提供新的 Turn ID 和可写捕获目录。

**验证：**在本次决策或保存的捕获中确认 `loopx_turn_envelope_v1`，完成其必读 Goal/上下文，并沿同一 Turn 的执行和结算契约推进。如返回分段导航，使用随决策返回的固定 reader，核对原摘要和 Turn 身份。

**停用 / 回退：**后续请求省略 `--complete-turn`，恢复原上下文路径。原捕获保留原摘要绑定的读取命令。

**权限边界：**继续遵循本次 Goal、Agent、准入、权限、必读内容和 Stop 条件。

**文档：**[Turn envelope](https://github.com/loopx-project/loopx/blob/v2.4.0/docs/reference/protocols/turn-envelope-v0.md)

```bash
loopx --format json quota should-run --goal-id "$LOOPX_GOAL_ID" \
  --agent-id "$LOOPX_AGENT_ID" --turn-instance-id "$LOOPX_TURN_ID" \
  --complete-turn --decision-output-dir ./complete-001
```

reader 的 JSON Pointer 指向捕获 JSON 内的字段，不是文件路径。将返回的当前 reader 引用赋给 `CAPTURE_READER` 后可目录查看或选读；读取当前捕获不要求先读旧差分基线，也不需要重新准入。

```bash
loopx --format json quota context-read --reference-file "$CAPTURE_READER" --list --list-depth 2
loopx --format json quota context-read --reference-file "$CAPTURE_READER" --select /selected_todo
```

选中的 Todo 只占契约的一部分。工作前仍需读取适用的 Goal 要求、限制与必读来源；压缩或恢复后保留原 Turn、capture 和结算身份。仅用于诊断的恢复结果不授予执行权。

**权限边界：**预览是无状态的。应用或回退需要材料 owner 授权并核对当前 revision。

#### Staged benchmark CLI activation

**启用：**由已有授权的 Docker benchmark controller 将通过资格检查的源码放入版本目录，用 `activate_cli_source(..., execute=False)` 预览所持有的 launcher。传入精确运行身份、归档摘要、源码/原生回执和当前 Stop 回调。实际切换需明确授权并重新核对输入。

**验证：**运行下方源码检出的回执读回用例。获授权的实际切换另需验证源码与 launcher，观察下一次真实 Host 输入。

**停用 / 回退：**省略调用可延用当前 launcher。切换中断后用 `reconcile=True` 收敛原回执。在当前控制规则与源码一致性均通过时，由授权 owner 用 `repair="old"` 恢复旧目标。

**权限边界：**worker lock、Stop 与有限预算沿用原 controller。此接口作用于后续 CLI 子进程，执行需要单独授权。

**文档：**[Host CLI 源切换](https://github.com/loopx-project/loopx/blob/v2.4.0/docs/reference/protocols/host-cli-source-activation-v0.md)

#### Private backup inspection

**启用：**在 Settings → Capability Center → device defaults → Configuration backup and recovery 选择 Full archive inspection，提供原归档及匹配的外部 manifest。不支持的服务或平台保持不可用。下方 CLI 按次调用。先预览项目及所选配置范围的私有完整备份，再在现有授权内创建；保留匹配的 archive、外部 manifest 和兼容版本。 [#8864](https://github.com/loopx-project/loopx/pull/8864)

**验证：**先验证文件对，再提取。只有 `--execute` 创建新的隔离检查目录，不激活 authority 或启动 Host；核对 included 和 missing 范围。

**停用 / 回退：**停止调用或省略 `--execute`，已有备份继续私有保留。重装旧运行时不会撤销新版数据写入；目标读取器无法核验时保持当前运行时，后续数据操作沿原恢复 owner。

**权限边界：**归档和历史租约是证据，不是新的执行授权。现代再激活另需身份、未决 effect 与准入检查；不能把旧归档直接覆盖到现用状态。

**文档：**[配置备份与恢复](https://github.com/loopx-project/loopx/blob/v2.4.0/docs/reference/configuration-backup.md#full-state-recovery-after-cold-import)、[Agent 原地升级](https://github.com/loopx-project/loopx/blob/v2.4.0/docs/guides/agent-upgrade.md)

```bash
loopx backup-state --project "$PROJECT_ROOT" --current-project-only \
  --configuration-goal-id "$LOOPX_GOAL_ID" --no-automations --no-skills \
  --output-dir "$PRIVATE_BACKUP_DIR"
# 核对预览后，在现有授权内重复命令并加 --execute。
loopx backup-state verify --archive "$BACKUP_ARCHIVE" --manifest "$BACKUP_MANIFEST" \
  --destination "$NEW_INSPECTION_DIR"
```
