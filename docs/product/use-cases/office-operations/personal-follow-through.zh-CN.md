## 用户结果与范围

用户承诺准备文档，随后收到改期要求，并请管家准备材料。管家保持同一个承诺事项，
完成已授权的准备，在原私有桌面对话返回有来源的简报。用户可检查、纠正、忽略和
暂停事项。草稿已准备或消息已发送，都不足以证明个人承诺已履行。

首个 profile 覆盖一位用户、私有本地工作区、选定且已授权的机器人可见飞书会话，
以及已有或明确创建的私有 Goal。核验本人平台身份，不从显示名称推断；展示机器人
可见覆盖范围。群访问权不包含全账号或私聊覆盖。邮件、钉钉、外部任务双向同步、
自动外发、云端全天运行和 connector 市场不在此范围。

## 飞书理解与证据

组合 `lark-event-inbox`、`manager-context`、`periodic-report` 和既有 Todo 操作。
`loopx-lark` 是随包提供的可选 provider，无需新增 connector capability。飞书
传输留在扩展，通用校验归类型化 work-item owner。Lead Agent 解释消息；来源
文本和模型输出都不能授权效果。

个人跟进的版本化 payload 放入既有 action/proposal 生命周期，包含来源绑定、
不透明事件/修订引用、已核验责任人、候选标题、提议操作、目标 Todo、修改所需
预期版本、证据引用，以及可选截止时间、时区和解释依据。字段省略保留原值，
显式清空与省略有区别。非法日历日期和身份不符不得产生变更。责任或日期模糊时
澄清；引用、问句和他人承诺不得自动提升为本人承诺。

解释结果可以为无需跟进、澄清、创建、修改、提议完成或忽略，映射到既有类型化
操作和提议转换，不新增状态枚举/数据库。保留来源 → 提议 → 规范 User Todo
→ 关联 Agent 准备任务 → 版本化产物/证据引用。User Todo 表示个人承诺，
Agent Todo 表示有界准备工作。完成 owner 要求本人明确决定或已授权且可核验
的标准；若承诺要求对方验收，还需对方验收证据。跨消息语义匹配必须明确关联
已有 Todo，传输去重不能独立识别同一承诺。

ACK/游标推进遵循既有采集/效果回执契约。来源编辑改变解释依据，重放先对账
原始回执；旧提议不能覆盖较新的用户纠正。来源删除/不可访问使受影响待审提议
失效，并在已有事实中展示证据不可用。这些属于 A5/A7/A15 的飞书用例，不形成
另一套恢复协议。每次交付通过实际 owner 区分已采集、已提议、已应用、已准备、
已返回和已核验证据。

## 启用、隐私与实现归属

默认关闭，直到既有设置展示选定来源/窗口、本人身份、私有返回位置、允许的本地
效果、频率、预算和保留期。初期审阅承诺变更；按管家 §5.3 复用已有授权范围，
不为已允许的读取或草稿准备重复要求确认。来源访问权不包含发消息、分派他人或
修改外部任务系统。

凭证由 provider 管理，原始正文保存在私有存储。本人私有简报使用独立限域的
报告 profile，公共安全 periodic-report 预设和共享投影不得接收私有来源正文。
关闭态保持原 Chat/Todo/采集/调度/报告行为，不调用模型或发通知。断开通过
既有撤权/dispatch 边界停止新增依赖工作，保留已创建 Todo 和去重回执。
删除与保留期是独立且用户可见的选择。不自动导入历史；有界补抓从显式游标/窗口
开始。复用既有 outbox、保留与调度恢复，不建立 profile 专属 daemon。

完整 profile 使用 TypeScript/TSX 和 Node.js，包括 provider 适配器、语义校验、
规范集成、报告组合与测试。不新增 Python 模块或子进程桥接。遵循
[TS 迁移 RFC](../../../architecture/rfcs/typescript-control-plane-migration-v0.zh-CN.md)：
刻画并迁移最小必要的 Python-only 完整 owner 及活跃消费者，保留规范权威与
回滚。无关语言重写不在范围内。验收包含 Python 不可用时的打包流程，孤立 Node
单元测试不能满足此要求。

## 场景评测与推广证据

冻结至少 100 条合成或经授权消息，其中至少 30 项可执行承诺，标签独立于模型
输出制作。覆盖本人/他人承诺、引用、否定、歧义、时区、编辑及删除。分别报告
提议准确率（正确提议 / 全部提议）和召回率（正确发现承诺 / 全部标注承诺）。
profile 提议目标为准确率至少 95%、召回率至少 90%、错误责任人自动变更为零、
越权效果为零。这些是尚未测量的发布目标，不代表已交付性能，也不替代管家验收。

通过安装版前端、飞书和 CLI 执行独立规定的序列：连接 → 承诺 → 审阅 → 规范
Todo → 改期 → 用户纠正 → 授权准备 → 重启 → 原对话产物返回 → 断开。
核对状态和回执，注入响应丢失/崩溃/并发，覆盖撤权、来源提示注入、错误接收方、
凭证过期、预算耗尽和断网/休眠。ACK、模拟轨迹、后端测试或草稿准备都不能通过
真实安装流程验收。

适用正确性门槛通过后，运行用户授权的七天试用。检查全部提议/采纳项，独立抽样
原消息查漏。记录来源窗口、分母、重复率、截止时间准确率、核验后的准备结果、
成本和每日审阅/纠正分钟数，对比同等工作量人工基线。正确性通过且总审阅成本
降低后，沿用管家 M4 推广决策；小样本保持探索性结论。仅公开脱敏汇总。
来源身份/平台、保留期、模型/标签和提议阈值必须在验收前确定；观察失败后改阈值
需要记录决策，并使用新的独立测试数据。
