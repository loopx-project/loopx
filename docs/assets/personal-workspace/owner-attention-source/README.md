# Owner-notification source recovery evidence

Packaged Chat UI over real HTTP, native File Todo authority, the typed
notification planner and the existing outbound worker. Provider/model transport
is synthetic. No live account or paid model is involved. The fixture also leaves
unrelated source-history gaps visible; notification delivery does not certify
complete inbound history or business-request completion.

- `before-desktop.png`: previous qualified UI bundle, 1200×888, reading the same
  partial-source backend state. Its generic notification error cannot distinguish
  a missing Goal from an entirely unavailable worker.
- `partial-desktop.png`: current bundle, 1200×888. One unavailable source is
  explicit while the other Goal continues automatic checking. The existing
  notification checkbox and native-monitor disclosure stay in place.
- `partial-phone.png`: current bundle, 390×844 emulated viewport, after bringing
  the notification control into view. The partial-source message wraps without
  horizontal overflow. This is not physical-phone acceptance.
- `recovered-phone.png`: the same 390×844 composition after restoring the
  disposable native source. The original worker discovers and independently
  verifies that Goal's notice; the status returns to active with zero pending notices.

Ego Lite captured these actual rendered views. Keyboard Space toggles were read
back through the real settings API; re-enable retained notice identities without
another send. Native recovery produced independently verified provider receipts
and zero model Turns. A separate old-adapter counterfactual blocks the healthy
native source when its neighbor lacks authority; the fixed File/SQLite regression
passes. These checks qualify this bounded notification change, not daily reports
or the entire steward portfolio.

Reproduce with the test extra and a built Chat bundle:

```sh
python apps/presentation/dashboard/smoke/owner-attention-source-fixture.py \
  --assets loopx/web/chat --output /tmp/loopx-owner-source-qa
```

Open the returned URL and select machine settings → Lark. An optional
`--baseline-assets` serves a previous UI over the same state. Creating
`recover-source` in the output directory initializes the unreadable fixture
Goal. The optional `source-unavailable` marker injects a later read outage for
that Goal; removing it resumes the existing worker. All state is disposable.
