# 面向原目标的 replan：晚期 checkpoint 消融提案

[English](README.md)

**Draft 研究提案。本次没有实现 treatment、配置开关或修改产品默认行为，也没有实验结论。**
下一步是已有 owner 下的 packet 原型与真实接收资格，再使用预先选定的晚期点实验。
现有 checkpoint、retained/fresh 研究保留各自协议。

## 问题与已有能力

明确要求审视全局目标，并更好地组织相关证据，能否改善长程研究的决策和结果？

对照组已经有原目标。现有 TypeScript
[`projectCoreGoal`](../../../../loopx/control_plane/work_items/replan_context.ts)
提供同源 objective 和 acceptance；可选
[`planning horizon`](../../../../docs/reference/protocols/quota-planning-horizon-v0.md)
可在选择前提供 Goal。现有 replan 指导也已包含原优先级、边际成本、负证据适用范围和合理继续。
本研究不是修复 Goal 丢失，也不能把再加一个字段当作效果。

待验证的假设是使用方式：即使原目标在上下文中，模型仍可能锚定当前 Todo、近期活动或继承计划。
一次全局审视可能让注意力回到最重要的未解决问题。这不是已验证的普遍收益，
也不说明所有没有换路的决定都有问题。

## 两项独立变化

**G：全局目标审视指令。** 保留普通 packet 及其原目标，仅在到期 replan 增加候选指导：

> 回到原始 Goal，纵观当前可用证据，规划下一段有价值的工作。
> 重新判断现在最重要的问题，并说明当前路径应当继续还是调整。

英文候选见配套文档；实跑时冻结一种语言和确切字节，不把翻译差异当作同一 treatment。
沿用现有 Vision/path-delta 和 Todo 写回，不添加必填回答模板、结算义务或强制换方法。
指令会影响模型行为，未来实现仍须披露行为变化，不能因机器准入不变就称为无行为影响。

**C：有来源的决策上下文组织。** 保留完整普通 packet 和相同可读来源，增加精简且带引用的阅读索引：

1. 原目标、优先级和尚未满足的验收，均来自既有 owner。
2. 实际当前候选、保留的 incumbent 及对应已公开结果。
3. 仍适用的正、负、未决证据，以及各自测试条件。
4. 前次决定、实际后续工作、未解决依赖或替代路径，同时说明缺失与省略覆盖。

先展示原目标事实，再展示继承计划。主要矛盾由模型读完证据后判断；renderer 不生成
“瓶颈已确诊”的事实，也不暗中给路线打分。优先复用原文片段与引用，不增设模型摘要调用。
如后续提出额外模型调用，另作干预并计入完整成本。

第一轮 C 比较研究组织和显著性，不增加特权或知识。索引只展开冻结普通 packet 已交付的事实，
缺项记为 unknown，不额外取记录或用 operator 笔记补齐；更丰富的检索需另作干预。
所有组保留同样的 Goal、完整 packet、源版本和授权读取路径，新增索引与读取都计费。
即使 C 有收益，也不能据此区分排序、重复强调和
额外 token 的作用；需要时另做等长或重排对照，不倒推第一轮已经证明。

## 归属与边界

本研究属于 `benchmark-toolkit`，使用 native EdgeBench provider，不新增 capability/provider。
未来原型复用已有 TypeScript replan/context、planning-horizon 和引用解析 owner；
Python 只负责传输或适配。不建第二份 Goal、历史、相关性分类器或决策权威。

目前部分结构化 followthrough/Explore basis 仅在 stride 开启时投影。
C 不能为获得这些上下文而暗开 stride；应独立资格化只读 owner 的复用，保持 stride-off 策略。
各源的可用性、版本、遗漏和错误必须如实保留，所有组保留原机器义务和基础指导。

G/C 仅是本研究标签，不是共享协议枚举或可运行 CLI 开关。本 Draft 不增加前端、飞书或 CLI 控件。
未来若形成产品配置，必须复用原配置 owner，补齐有效值读回、关闭以及所需前端和其他调用方入口；
不能把提案写成已发布的 opt-in 能力。

## 晚期点准入与固定条件

使用新捕获且合格的自然 **pre-replan** 点；此时模型尚未做本轮决策。
按源年龄与质量预选，不能看分数或哪段轨迹更有利再选。
例如原预算的 75% 可作为晚期规则，但题目级规则必须在选点前冻结。
旧点或早期点能恢复不等于本研究的晚期点合格。

核验原 Goal、代码/incumbent、科研文件和依赖、原生公开反馈/历史、剩余机会/冷却，
以及 Explore 节点、发现和关系。关系覆盖与研究质量分开：缺边不能造边，也不能记成没有研究。
模型进入前先验证真实普通 receiver 和动态依赖。

G/C 各组固定为 fresh 会话：根据原目标与捕获证据重新 replan，不能在原会话已经复盘后再切 fresh 执行。
本研究与 retained/fresh 正交，同时改变两者无法识别 G 或 C 的作用。

固定 receiver/product/runner/native 来源、模型/effort、完整科研文件、资源、replan 节奏和反馈。
Goal horizon 开、stride 关、TurnEnvelope 关，不注入宿主截止时间、倒计时或常驻 runtime guidance。
保留原权限、Task/Turn/obligation 身份、来源围栏与 incumbent 排名。
不能加入 checkpoint 之后的私有观察、另一臂后来的结果或隐藏评测细节。

## 建议消融与执行顺序

| 本研究标签 | 全局目标指令 | 决策上下文索引 |
|---|---|---|
| G0C0 | 现有指导 | 现有上下文 |
| G1C0 | 候选 G | 现有上下文 |
| G0C1 | 现有指导 | 候选 C |
| G1C1 | 候选 G | 候选 C |

四组分别识别指令、上下文差异及组合交互。每格一次只能作描述性案例，
稳定效果需要独立重复与更多题目；不能假定 provider 或模型 seed 可确定性重现。

1. 在可丢弃环境准备 packet 原型，验证来源/引用、关闭时一致、义务与普通输入完整。
   覆盖 Goal 缺失、过期/错误生命周期证据、不可读来源、矛盾结果、截断历史、无前次决策。
   代码或文本检查只验证传输，不证明模型使用或科研净益。
2. 在看到 treatment 输出前冻结一个合格晚期点、确切 packet/digest 和分析规则；
   容量允许时 pilot 四次 fresh replan，保留失败、保持原路和不确定决定。
   模型真实请求/返回留在私有实验空间，用于核验实际处理是否符合声明。
3. 继续到完整且有意义的实验，以及结果后的下一次决定，包含负结果。
   使用预声明共同窗口，不奖励只改措辞或没有执行的计划。复制四组，或在独立点预注册选择后的比较；
   看完 pilot 再选择的比较须标为探索性。

服从既有执行授权与容量。一题四格 pilot 不授权同时开十二格，也不替代主 retained/fresh 研究。
最多三题六个研究 worker；排队或分波不能重置预算和机会。
若累计上限获准为 36h，必须包含来源年龄、setup 和应计等待，不能恢复后再加 36h。
原生冷却从受理起算，不积攒机会，不补额外尾评；保留顺序和共享宿主影响。
复用先前对照须满足预注册协议、来源与窗口等价，不能只因标签相同或分数好。
本文不启动任何实验。

## 整体节奏与 outcome refinement 候选

先完成既有 retained/fresh 主对照，再做单一 opt-in stride，随后 G/C。
必要正确性修复和新版本 FROM-ZERO 晚期点生产优先于三者。
升级接收端通过不能把旧 donor 变成新冷启动；donor、receiver、runner、native evaluator
与实际安装来源分别固定。

| 阶段 | 启动条件与有用出口 | 容量与记账 |
|---|---|---|
| 有效性与新晚期点 | 验证普通实装接收端及接续；从准入的 FROM-ZERO 来源选择按时间首个合格、完整的自然 pre-replan 点。保留捕获失败和过早退出。 | 从私有 manifest 读回实际 worker、成对空槽、源年龄和绝对截止。合并或空槽不等于实验准入。 |
| 主 retained/fresh | 恢复同一个不可变研究状态、原 Goal、incumbent 和原生 cursor；只改变本轮 replan 的 retained/fresh 会话因素，继续到公开反馈后的实际决定。 | 替代源就绪再排空被替代 donor；保留原机会、受理起算冷却与累计上限。 |
| 原 stride | 验证所声明单策略 grow/switch/verify 的实际采用、完整实验和随后证据驱动的决定。 | 前序工作释放成对槽位；不与 G/C 同时改，不把声明当执行。 |
| G/C | 当前真实 client/receiver 资格后，冻结 packet、episode/rubric 和匹配窗口，再做既定四格或事先缩小的比较。 | 保留上文四格。分波仍须满足来源和窗口可比；较小配对不能事后算完整 factorial。 |
| Outcome refinement，低优先级 | 先厘清与 G/C 重叠，独立资格化可隔离的功能差异，再考虑匹配比较。 | 不自动多开臂、翻倍四格或续期；来源不兼容、无成对槽或原剩余预算不足时保留候选。 |

获授权累计 36h 时，剩余至多为 `36h－源年龄－后续 setup/等待/恢复 elapsed`，
按原绝对时钟执行。恰好 9h 或 13.5h 的点，在扣除后续成本前至多剩 27h 或 22.5h；
这是上界，不是新额度。模型输入仍不注入宿主截止时间或常驻 runtime guidance。

[PR #6784](https://github.com/loopx-project/loopx/pull/6784) 在
`a1e9cee8ae9959eeacfc2bb14053446d02cc4afe` 的方案作为低优先级候选：
保存原始意图/累计需求、逐项证据复盘，并将未覆盖缺口接回规划。
默认流程没有整体 enabled 开关；可选 executable checks 是证据路径，不能充当整体对照开关。
已读方案不能证明 live 模型资格或效果。

可考虑共同合格基底 Q 对 Q 加上隔离的 outcome-refinement 功能差异，两边包含全部共同必要修复。
预注册前验证普通安装与状态兼容；从尚未被新版写回的同一不可变点分别恢复，
不能把新需求状态倒灌不兼容旧 binary。不开造 disabled 配置、第二 Goal store 或可选策略版本。
若无法隔离差异，只保留工程表征。

G 测额外复盘指令，C 组织已交付事实，outcome refinement 还改变结构化需求维护与复盘。
实际等价的问题合并，不重复造臂；部分重叠时固定 G/C、stride 和 fresh，只声明新增机制包。
若 outcome refinement 先成为公共基底，后续 G/C 估计该基底上的增量，不能反推其自身效果。

## 指标与判断

复用既有[数值与 episode 口径](../../../../docs/architecture/rfcs/long-horizon-harness-benchmark-research-program-v0.md#6-measurement-model)
和已实现的[轨迹分析 owner](../../../../docs/reference/trajectory-assessment.md)。
沿 **送达 → 实际采用 → 研究证据/决定 → 采用候选 → 原生结果与成本** 解释差异。
这是待核验的证据链，不能自动补成因果图。

### 先固定 episode、适用性与覆盖

一个 research episode 跨越问题/竞争解释、干预、观察和随后决定，可以跨 Turn。
在看组标签与收益前冻结起点、结束规则、先前证据范围、适用性和窗口；
未完工作保留，适用时按右删失处理。工具调用、Turn、截图、节点和重复输入不是独立 episode，
重叠 episode 还可能共享依赖和成本。

模型执行前由 curator 声明 eligibility，报告抽样规则、已知或未知总体、穷尽标记、遗漏材料，
以及明确排除的无后续机会样本。目的性 debug 样本或 `exhaustive=false` 不能报全 run 比例。
不能让模型删除困难样本，也不能看完标签才修分母。

### 复用六项过程判读

六项均复用现有 TypeScript 词汇与 reducer，保持 `uncalibrated_model`；
不新造评分器或加权进度总分。各项展示 yes/no/unknown/eligible，
同一 pack 内不同指标的适用分母和观察终点仍可能不同。

| 指标与决策问题 | 适用分母与窗口 | 所需证据与解释 |
|---|---|---|
| `goal_alignment`：实际工作是否针对原目标的限制因素？ | 固定窗口内预声明适用的已执行 episode。 | 原目标/优先级、实际代码/输入及有依据的瓶颈关联；复述 Goal 不够，小改进也可以对齐。 |
| `benefit_test`：是否真正检验所声称的收益？ | 适用的已完成 episode。 | 原生评测或有独立代表性依据、位于原目标路径的 proxy。有效负检验可为 yes；只做正确性前置为 no，不等于无价值。proxy 代表性未知则 unknown。 |
| `discrimination`：是否区分了竞争解释？ | 预声明的已完成实验。 | 固定备选、干预/对照、有效性与观察；无效实验为 no，有效性缺失为 unknown。通过无关检查或一个正 proxy 不够。 |
| `information_gain`：是否解决决策相关、先前未解决的不确定性？ | 预声明适用的 episode，绑定可用先前证据范围。 | 先前证据、新观察和被解决的问题；有用负结果计入，噪声未决及先前覆盖缺失保留 unknown。 |
| `evidence_adoption`：适用反馈是否影响后续动作？ | 截止前确有后续动作机会的适用证据 episode；无机会样本明确排除。 | 公开反馈、实际可用时刻，以及绑定版本的后续代码/实验或有依据保留的产物；引用/Todo 不够，缺关联为 unknown。 |
| `redundancy`：是否无有用理由地重复同一问题/干预/输入？ | 固定先前证据范围内可判读的适用 episode。 | 方法/输入身份、旧结果、新执行及复现/噪声/恢复理由；yes 方向为问题。必要验证和合理复现不自动算重复。 |

每项 `eligible = yes + no + unknown`，`assessed_fraction = (yes + no) / eligible`，
unknown 留在分母。`[yes / eligible, (yes + unknown) / eligible]` 只是本样本缺失标签上下界，
不是置信区间、校准或总体估计；eligible 为零是 N/A。
redundancy 的负向含义不能展示成有用进展；数值归约不证明引用蕴含模型判断。

### 六项判读旁的事实指标

以下分别标明已有读回、可从绑定证据计算或待资格的研究诊断，不增加模型评分字段。

| 机制或结果 | 固定单元、分母/窗口与未知处理 | 来源、关联和当前可得性 |
|---|---|---|
| 处理送达与使用 | 尝试送入的到期 replan 输入，区分送达、未送达、unknown；实际使用另查后续动作。 | client 真正可见的输入/返回、packet digest、Goal/Turn/obligation 与后续动作。原型只资格 framing；文件存在不等于收到，收到不等于使用。当前真实 receiver/model 链仍待。 |
| 反馈响应延迟 | 有合格后续动作的适用公开反馈，按动作时刻减反馈可用时刻；截至终点未动作按删失，时间缺失为 unknown。 | 原生交付/solver 动作时间和版本关联；不从提交起算、不按相邻时间补采用。有两端与关联证据时可算，未宣称已有全 run 通用 reducer。 |
| Proxy→native 迁移与保留 | proxy 改进且确有已完成有效 native 后续的候选，按固定 anchor 计改善/不变/退步；无后续单列。 | 同候选源码/输入、proxy 代表性、native 条件/评分器及实际保留/拒绝读回。属于待资格研究归约；暂存候选、下一工作树、保存 incumbent 分开。 |
| Native initial/window-best/retained/latest-valid/final | 固定起始 incumbent 与共同 elapsed 窗口；保留提交顺序、指标方向及有效/无效/缺失。运行中 final 待定，未达阈值的时间/成本按删失。 | 既有 native projection 在覆盖允许时提供有界 first/best/retained/final-valid；submission-one initial 要求完整前缀，capture-final-valid 不等于研究终态。保留由 provider 指定，不自动取数学最优。匹配窗口与阈值成本仍待研究资格。 |
| 运行损失与点的可用性 | wake、replan、capture、restore 各自失败/尝试；再统计真正恢复且接续合格点/尝试点，保留全部失败准入臂。 | 原回执、源 manifest 和实际接续；文件存在不证明完整，exit zero 仍可能宿主过早退出。恢复成本与科学策略质量分开，跨阶段研究归约待资格。 |
| 完整成本 | 每臂接续成本及 study 层只计一次的来源成本；固定窗口，保留未知/未分配区间。 | solver、分析任务、native、setup/恢复/重试和人工各保留来源。完整会话 usage 投影已有；跨 donor/接续、共享宿主、价格和全研究总账并非自动可得。 |

累计 usage 只在合格的同会话历史内差分，继承 baseline 只减一次；reset/gap 明确不支持。
恢复后重新处理旧上下文仍是新成本。cached input 含在 input 中，reasoning 可能已含在 output 中；
并发 wall 用区间并集。分析器研发/维护与每次调用（含失败重试）分列，再归入对应完整研究成本。
未知价格、人工注意力或区间不能变成虚构美元、节省或浪费比例，整轮工作也不是纯 replan 开销。

### 分析器资格与对照示例设计

科学 G/C 比较前，使用已有授权的正例、负例、不改善、未采用、缺覆盖和运行失败样本打磨方法，
原始轨迹与确切 case 读回保留私有。以下是可复用的 **诊断设计**，不是 G/C 结果或固定模型标签：

| 样例设计 | 核验链 | 能区分什么 |

| 已捕获证据，却把有界索引当全部历史 | checkpoint/报告 digest → 可见投影与省略 → 重复方法 → 纠正审计 → 下一实际动作及成本。 | 区分文件丢失与检索/覆盖理解问题；后续纠正可能采用了有用负证据，不能把整轮纠正成本都算浪费。 |

## 尚未完成的作者工作

初步可丢弃的 **离线** packet 组合原型已使用真实隔离 File/SQLite CLI 输出。
它复用现有 TypeScript `checkpointArtifacts` 决策前选择和 `validateReplanContext`，
不复制准入规则。普通 UTF-8 packet 原文绑定 digest、Goal、Agent、Turn 与 obligation。
G0C0 逐字节保持原输入，其他三格只追加声明的 G 指令和/或 C 索引；
每个索引值都带同一 packet 内的 JSON pointer。组合过程不额外读源、不调用模型摘要、
不排序相关性，也不补齐缺失事实。

原型核查完整普通输入不变、两个 G 条件下的 C 追加内容相同、引用与原值一致，以及缺项明确可见。
每种存储各有十二个负输入，覆盖 digest/身份变化、上下文身份不一致、Goal 缺失、证据格式错误、
非 replan 与未提交边界；矛盾观察和截断覆盖均保留。
这些合成夹具中，G 增加 197 个 UTF-8 字节，C 约增加 4.3 KB；
这是 packet 大小观察，不是 token、延迟或效果测量。
可丢弃 composer 未安装到 runner，也不是新增运行时 API；夹具与输出不是 benchmark 结果。

由此明确一个传输限制：stride 关闭时，普通 context 不提供 stride 专属的结构化决策后续执行视图。
第一轮 C 索引须保留 unknown，不能为此开启 stride 或额外取历史；
也不能从自由文本摘要推断候选/incumbent 关联。
因此第一轮 C 仅组织实际交付事实，不冒充已经提供上文所列的全部理想上下文。

可丢弃 CLI 传输原型现已保留单个有效 JSON 响应：真实目标端 CLI 只执行一次，
保留全部原响应成员和原文 digest，再从同一响应组合独立的 study 局部提示。
G0C0 与关闭状态逐字节不变；G/C 不替换当前 Goal、命令、Turn 或 obligation。
C 索引保留原 kernel projection envelope 的新鲜度告警与省略覆盖；
adapter 不能把保留事实重新标成刚读到的源。上面的纯文本片段仍只作离线表征，不能作为生产 JSON serializer。

真实隔离 File/SQLite CLI 已检查这种 framing、原值不变、两个 G 条件下的 C 相同、
普通/错误响应原字节、错误目标端，以及丢失显示后按同一已提交 guard 重试且不新增扣账。
