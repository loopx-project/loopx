# Research display language

These viewports use the production packaged reader and actual disposable
SQLite/Explore history, verified pack, analysis-job and HTTP owners. The twenty-hour
fixture contains twenty questions and ten tentative/refuted findings. The provider
is an explicit synthetic process: this proves integration and interaction, not
model translation quality, native benefit, an installed App or scientific calibration.
The tested source revision is recorded in the PR description.

`first-*` shows the default reading hierarchy at 1440×1000 and 390×1000.
`reader-*` shows the selected translated question, original recorded refutation,
negative numeric observation and declared decision. `original-reader-*` switches
the same selected content back to English. This comparison uses two modes of the
same build, rather than claiming a separately built baseline. The switch is in
the reader, so narrow-screen users can reach the original without scrolling away.

The primary question and complete finding remain readable. One original-text
switch is shown in the current reading context. Coverage and translation provenance
are behind contextual help; partial or inapplicable coverage stays visible.
History/version details remain optional. Expanded historical prose uses the
reading text token rather than the caption token.

The durable `research-display-language` scenario checks both interface languages,
the original switch, complete structured findings and history, literal negative
values, keyboard return, reload, partial/invalid fields, another physical source,
unavailable browser hashing and a refused explicit retry. Browsing performs no
mutation; that deliberate refused action is counted once and keeps saved results.
The adjacent route-reading and finding-reader scenarios retain long-content,
mixed-state, keyboard/touch and return-path coverage.

No private Goal, original research transcript, local path, account or credential
is used in these images. Each PNG contains only IHDR, IDAT and IEND chunks.
