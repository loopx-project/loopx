# Research route focus return

The user opens a route endpoint, reads its complete original question, then
returns to that same control. Pointer or accessibility activation in WebKit
does not necessarily focus a button; the reader must retain its actual opener.

These public captures use the production packaged components and a disposable
SQLite/HTTP history owner. All questions and analysis readbacks are synthetic;
source mutations and analysis dispatch are refused. This is packaged browser
evidence, not an installed-App claim.

The route-reading regression covers both locales, 1440/768/390 widths, keyboard
and activation without browser focus, complete original reading, exact focus
return, reload/Back and zero source/model writes. The baseline fails the new
return assertion; the corrected handler passes. The existing finding reader
also retains its own parent navigation.
